# Design

## Context

动机见 [proposal.md](proposal.md)，行为约定见本变更下的四份规范。当前实现中有几处会直接影响设计：

- `AssistantService.chat()` 从全局上下文取得当前书籍，并自行构造通用助手工具集；`useRightPanel` 和普通聊天会话也依赖全局当前会话。导入不能直接以另一个面板实例复用这些全局状态。
- 月詠已经拆出消息列表、思考展示、输入状态、操作详情及绑定逻辑，可以复用这些展示组件和模型调用能力。
- `BaseScraper` 有现成的代理、站点请求头和网站解析能力，但现有小说抓取入口包含取页面与连续目录处理。导入需要让请求、结果和后续来源选择都可由 Agent 工具调用追溯。
- 现有 `fetch_webpage` 依赖 Tavily，返回的纯文本会折叠空白并限制长度，不适合作为小说原文的权威存储。
- 当前 IndexedDB 为 v11，小说结构存于 `books`，段落及翻译存于 `chapter-contents`。`BookService.saveBook()` 先逐章保存，再写小说元数据，不能直接作为整次导入或撤销的原子操作。
- 当前章节合并以 `webUrl` 为主要标识，无 URL 的章节直接追加。文件重导、段落译文保留和跨章重组需要单独的变更计划。
- `loadChapterContent` 对「没有正文记录」和「读取失败」都返回 `undefined`，并把失败缓存成 `null`；`BookService.getBookById(id, true)` 因此会静默留下没有 `content` 的章节。导入的预览、匹配和撤销前镜像不能直接用这条读取路径。
- 整章翻译按 chunk 从 composable 的内存章节对象落盘，写入不带任何版本校验。导入应用与正在运行的翻译任务同时作用于同一本书时，后到的翻译写入会覆盖已应用的导入结果。
- 仓库中目前没有任何 `navigator.locks`、`BroadcastChannel` 或 `new Worker` 的使用；这三者都是本次新引入的运行时能力。Electron 生产构建通过 `loadFile` 以 `file://` 载入，开发模式走 `http://localhost:9000`，因此能力差异只会在打包产物中暴露。

## Goals / Non-Goals

**Goals:**

- 在现有前端、模型提供商、代理和 IndexedDB 分层内实现工具驱动的导入，不引入新的执行服务。
- 把来源快照、提取内容、可变草稿、确认方案和书库数据分开，明确各自的修改权限。
- 通过显式任务上下文、草稿版本和书籍修改序号处理恢复、迟到结果、并发修改及撤销。
- 保持通用月詠聊天、现有网站导入和翻译任务的外部行为，所需共享调整在现有模块内完成。

**Non-Goals:**

- 不另建 Agent 框架、通用插件系统、后端、浏览器扩展或云浏览器适配层。
- 不让模型执行任意 JavaScript、直接写书库或通过生成全文代替内容提取。
- 不改变 Gist 同步协议，不同步导入任务、原始文件、工具日志和撤销快照；它们仅在当前本地工作区保存。
- 不新增电子书排版阅读器、正文图片段落或 OCR；EPUB 图片资源可用于封面，正文仍采用现有文本段落模型。

## Decisions

### 1. 页面沿用应用壳，月詠展示与导入执行上下文分离

新增 `/import/:taskId?` 路由，指向 `ImportPage.vue` dispatcher，由 `useDeviceVariant` 选择三个设备变体。页面业务状态由导入 composable 和 store 提供，任务列表、来源管理与草稿编辑使用共享组件；变体切换不重新启动任务。

桌面中间工作区承载来源和卷章，导入功能自己装配聊天外壳：复用 `AssistantAvatar`、`ChatMessageList`、输入组件、操作详情和 `useChatPanelBindings`，数据来自 `useImportChatPanel`。**不修改 `AppChatPanelDesktop` / `TabletChatPanel` / `MobileChatSheet`**，也不在它们内部切换会话数据源。现有布局始终挂载全局聊天，所以必须在其外层面板宿主增加路由范围选择：导入路由的聊天槽位挂导入外壳，其他路由挂原组件，每次只挂载一个聊天控制器；不能在 `RouterView` 内再放一套聊天而留下原全局聊天。导入以对话为核心，导入路由上的对话常驻、不可收起：桌面右面板宿主在导入路由强制展开，平板在布局中常驻停靠（侧滑浮层只保留给其他路由），手机不挂抽屉，而是作为工作台的「对话」分区，底部栏的「月詠」在导入路由切到该分区。翻译进度保留原入口与切换行为。路由范围选择与设备选择分开，设备变体仍只经 dispatcher；项目禁止的是手写设备分支，并非所有路由条件。

导航同时接入 `useMainNavActive` 与 `useMainNavDispatch` 的目标类型、路径匹配和派发映射，不能只加菜单按钮。第一版手机通过已有侧边菜单提供 AI 导入入口，保持底部五项功能；在导入路由上即使聊天已展开，也应显示导入的导航上下文，不能误亮首页或将导入会话识别为普通全局聊天。

新增 `useImportChatPanel` 实现共享组件所需的数据绑定，读取显式 `taskId`。它不调用普通 `useChatSession`，不改变普通聊天的 `currentSessionId`，也不把导入目标写进全局当前书籍。离开导入路由后，普通月詠会话照常展示。

**取舍：**复用展示与协议，单独提供状态适配器。直接挂载 `AppChatPanelDesktop` 会继承其全局会话与书籍绑定；复制聊天界面则会重复维护消息、输入和工具记录。

### 2. 用任务专属执行配置复用助手调用循环

给现有助手循环增加明确的执行配置入口，包含 system prompt 构造、工具定义集合、工具执行器、显式上下文、检查点与让出执行回调。普通聊天使用现有默认配置；导入由 `ImportAgentService` 提供专属配置，不重写一套流式请求、工具循环和摘要逻辑。

每次导入运行固定捕获 `taskId`、`runId`、`runEpoch` 和所用模型 ID，默认选用现有全局 assistant 模型。模型凭据仍从现有设置读取，不复制到导入任务或操作日志。导入 system prompt 复用月詠表达风格，附加工具职责、正文不可改写、来源用途和单本小说约束；来源文本始终作为待分析数据，不作为系统指令。

执行器同时校验“本轮暴露的工具名称”和“导入工具允许的操作”。不把通用工具全集交给 Agent，也不开放普通书籍修改、翻译修改、应用或撤销工具。候选书籍的读取包装器使用显式 `book_id`，不依赖当前页面。模型每次继续前取得任务摘要、当前草稿版本、待处理问题与未完成来源概览，正文按需读取。

现有工具循环次数和上下文限制继续生效。达到限制时保存检查点并暂停，不能报告为整理或导入成功。用户继续时重新取得当前任务数据，并从已保存结果开始。

**取舍：**执行配置是对现有助手入口的有限扩展，不改写翻译任务状态机。另起 Agent 框架会增加重复逻辑；直接使用通用助手工具集无法保证导入前只修改草稿。

### 3. 工具按来源、内容、草稿与书库对照划分

工具名称和关键参数按下表实现；通用上下文由宿主传入，不允许模型通过参数切换 `taskId` 或伪造用户确认。

| 工具                                                   | 关键输入                                       | 返回与副作用                                                          |
| ------------------------------------------------------ | ---------------------------------------------- | --------------------------------------------------------------------- |
| `list_sources`                                         | 父来源、状态筛选、分页游标                     | 来源描述、状态和发现路径；不读取正文                                  |
| `inspect_source`                                       | `source_id`，可选刷新请求                      | 文件类型、目录条目、HTML 结构、链接及元信息线索；必要读取产生来源快照 |
| `read_source`                                          | 来源快照或内容引用、视图、范围／游标           | 原始或已提取内容片段、位置、后续游标；不把片段当成完整正文            |
| `add_sources`                                          | 已发现资源的引用、父来源、用途                 | 登记资源并返回来源 ID；去重且不抓取                                   |
| `extract_novel_info`                                   | 已登记来源及快照                               | 小说元信息候选、当前资源的卷章目录及后续资源引用；不读取目录外章节    |
| `extract_content`                                      | 明确的来源列表、快照、解析规则或范围与排除规则 | 保存提取结果，返回内容引用、段落位置、预览、排除记录和异常            |
| `get_import_draft`                                     | 所需草稿范围                                   | 当前结构、正文引用、目标、匹配建议、待处理问题和版本                  |
| `edit_import_draft`                                    | 基础草稿版本、具名操作列表                     | 原子修改当前任务草稿并返回新版本；不接收任意小说数据库对象            |
| `search_books`                                         | 书名、作者、来源线索                           | 本地候选小说及匹配依据；不使用网络搜索                                |
| `get_book_info` / `list_chapters` / `get_chapter_info` | 候选 `book_id`、章节 ID、分页                  | 复用现有只读能力，默认不附带与匹配无关的记忆内容                      |
| `search_web`                                           | 元信息检索问题                                 | 使用现有搜索配置，返回仅用于元信息的结果引用                          |
| `ask_user` / `ask_user_batch`                          | 问题及候选，必要问题的宿主标识                 | 复用问答界面和结果格式，回答归属当前任务                              |
| 待办工具                                               | 当前任务的待办操作                             | 复用待办展示和操作约定，持久化归属导入任务                            |
| `preview_import`                                       | 当前草稿版本和目标                             | 生成实际差异与待确认方案；不应用                                      |

工具结果统一包含 `success`、关联来源／草稿版本、结果摘要、必要的内容引用或分页游标、警告及可恢复错误码。单个资源失败不吞掉批次中其他资源的结果。批量提取只处理参数中列出的资源，第一版沿用小批次和有限并发；一个 Agent 不等于每次只能读取一章。

`edit_import_draft` 的操作包括设置元信息候选、声明小说候选及来源归属、提出目标与匹配、增改卷章、关联内容范围、重排和调整导入选择。其正文输入只接受已提取内容引用，或绑定当前目标书籍快照的既有段落引用；后者用于保留和重组旧内容，不能引用另一候选小说的段落。模型不能通过标题、简介或自由文本字段绕过正文来源规则。应用服务另外检查字段用途与来源，不信任 Agent 自报的处理数量和确认状态。

**取舍：**两层提取共用解析与存储实现。高层工具降低常见站点和 EPUB 的交互成本，通用读取与范围规则处理未知页面；不按每种格式创建一套重复的工具，也不提供一个会自动跑完整本导入的黑盒工具。

### 4. 来源具有稳定快照与不可由 Agent 提升的用途

来源描述记录 `sourceId`、`taskId`、种类、用户提供／Agent 发现、父来源、发现证据、处理状态和用途。正文根来源只由用户的输入动作授予；正文派生来源必须来自该根下已观察到的相关资源。搜索结果及其后续读取默认是 `metadata-only`，Agent 不能把它改成正文来源。用户后来主动提供同一网址时，记录新的用户授予关系。

工具检查得到的链接和文件条目生成宿主资源引用，`add_sources` 使用这些引用解析实际 URL 或文件，不依赖模型拼造的本地路径。URL 只接受 HTTP(S)，相对链接根据实际来源解析；请求 URL 与章节锚点分别保存，保留可能有语义的查询参数。去重使用规范化资源定位和所属任务，不以书名或文件名去重。

文件选择后保存 `File`／`Blob` 与必要元信息属于输入登记，不进行正文解码。文件夹使用浏览器目录选择返回的文件清单与相对路径建立可访问范围，Agent 调用工具后才能枚举或读取其中条目；目录选择不支持时仍可使用批量文件选择。依据见 [目录选择与相对路径](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/webkitdirectory)。

实际读取产生不可变 `snapshotId`：保存原始字节或响应正文、请求与实际响应定位信息、编码信息及内容摘要。重新读取生成新快照，不覆盖草稿正在引用的旧快照。文件重新提供时核对原始字节摘要；同名但不同内容作为新版本，不能默默接续旧的范围引用。

**取舍：**保存原始输入允许恢复和检查清理结果，代价是占用本地存储。仅保存文件路径或只保留清理后的文本无法满足恢复与追溯要求。

### 5. 解析器只执行当前工具指定的范围

从 `BaseScraper` 提取共享页面传输模块，保留现有代理选择、站点请求头和错误处理，增加取消信号与响应快照输出。普通网站导入继续使用原入口；导入工具调用共享传输及可复用的单页面解析能力。把可复用的目录和正文选择规则从连续抓取编排中分离，避免在导入工具内直接调用会隐式继续翻页的入口。

- **HTML／网页：**复用现有 Cheerio 解析能力，在不执行来源脚本的环境中建立结构和文本块。站点预设与 Agent 指定的 CSS 范围、排除规则共用同一个快照；下一页只作为发现结果返回。
- **TXT：**用浏览器 `TextDecoder`，优先 BOM 与明确编码，再采用可解释的候选编码检查；不能可靠解码时返回编码问题，不靠模型修复乱码。保留原始字节和解码后的换行信息。
- **Markdown：**复用现有 `marked` 依赖的 lexer 取得标题和块结构，补充原文位置映射。现有帮助页已用 lexer 构造目录，但没有原始位置映射。lexer 会将 CRLF／CR 规范化为 LF，因此不能把 token 的 `raw.length` 累积值直接当作原文件偏移；解析前保存原始解码文本与规范化文本的偏移映射，token 范围先定位于规范化文本，再映射回原文切片。只累加同层 token，不能把父子 token 的重叠 `raw` 重复计算；覆盖与顺序核对失败时返回定位失败。以 CRLF、空白、引用定义及嵌套块的原文切片往返用例锁定，不执行嵌入脚本或自动请求外部资源。
- **EPUB：**新增按需加载的 `fflate` 处理 ZIP，读取容器、OPF、spine 和 EPUB 导航／NCX，正文条目交给共享 XHTML 提取器。选择它是因为提供浏览器可用的 ZIP 和流式接口，不需要引入整套阅读器。[fflate 官方说明](https://github.com/101arrowz/fflate)

解包校验条目路径、条目数、单条及总解压量；正文解析有输入规模和执行时间上限。大文件解码、解包和匹配计算放到按需 Worker，避免阻塞预览编辑。遇到加密或不支持的压缩内容返回具体失败，不新增解密或 OCR 流程。

提取结果包含正文块、元信息、前言／后记／注释、被排除范围、规则和异常。块标识绑定快照及位置，不能只由文本哈希生成，否则重复句子会混淆。范围精确到块及必要的块内偏移，覆盖单行长 TXT 的分章需求；空白块保留用于还原，不单独作为段落匹配的唯一锚点。

`extract_content` 调整规则时生成新的提取结果。当前草稿继续引用旧结果，只有明确的草稿编辑才采用新结果并使旧预览失效。选中的原文不做语义改写、标点归一化或摘要。元信息与导航分离，附属文字默认保留；不确定的删除依据保留为问题。

元信息搜索复用现有 Tavily 配置与请求实现，不新建搜索服务。网页信息页通过同一来源机制读取；正文资格检查贯穿提取与草稿引用，不能只在提示词中要求“不要搜正文”。封面候选保留实际图片地址或 EPUB 图片资源引用及出处；本地封面在应用时转换成现有封面字段可持久保存的值，不能持久化临时 object URL。

**取舍：**现有爬虫的选择规则和传输继续复用，提取的 I/O 范围由 Agent 控制。把 Tavily 返回的折叠文本或模型生成文本直接当作原文会丢失格式、来源位置和完整性。

### 6. 导入数据保存在现有数据库的独立 stores

将数据库版本从当前 v11 提升到下一个版本，新增以下 stores，不重写现有小说记录。若实施期间数据库版本已有其他变更，则顺延迁移版本，不能复用已占用的版本号。

| Store               | 保存内容                                                                                   |
| ------------------- | ------------------------------------------------------------------------------------------ |
| `import-tasks`      | 任务状态、小说候选和选择证据、草稿树及版本、目标建议、进度、运行代次、会话摘要与待回答问题 |
| `import-sources`    | 来源描述、用途、父子关系、发现条目、当前快照引用与错误；按任务索引                         |
| `import-resources`  | 原始 Blob、来源快照、文本块与提取结果；列表查询只读取描述，不加载大正文                    |
| `import-events`     | 用户／助手消息、模型工具调用与结果、操作记录及检查点；按任务和序号读取                     |
| `import-operations` | 导入方案、应用记录、目标 ID 映射、受影响记录的前镜像、应用后修改序号及撤销状态             |
| `book-revisions`    | 本地书籍语义修改的单调序号及最近操作标识；不进入同步载荷                                   |

草稿树仅保存标题、顺序、归属、内容范围引用、匹配建议和选择状态，不内嵌整本正文。工具结果完成后将资源、来源状态和事件检查点一起提交；流式文字可以节流保存，但未完成工具参数不作为可重放调用。

手动与 Agent 编辑都通过同一个草稿服务提交具名操作，携带 `baseDraftRevision`。在事务内比较并递增版本；不相等则返回 `DRAFT_CHANGED` 和当前版本，要求重读。手动修改的元信息记录为用户来源，Agent 不能凭旧推断覆盖。

消息与 API 工具历史复用现有类型和摘要策略，持久化归属由导入仓库承担，不受普通聊天 localStorage 的会话淘汰影响。摘要只压缩模型上下文；原始来源、提取结果、必要确认和可供用户检查的操作记录保留。

不自动清理仍被草稿或可撤销操作引用的资源。用户删除任务时清理其专属来源、事件、资源和快照，并明确撤销能力随之移除；不删除已导入的小说。存储失败要保留未保存标识并暂停推进，不能显示已可靠保存。

**取舍：**使用现有 IndexedDB，便于跨 `books`、`chapter-contents` 与导入操作建立事务。另建数据库会让应用和快照无法在一个本地事务中提交；把大文件放进普通聊天 localStorage 也不合适。

### 7. 执行锁、等待问题与恢复

导入任务使用独立状态：`draft`、`running`、`pausing`、`paused`、`waiting_user`、`failed`、`ready`、`applying`、`applied`、`reverting`、`reverted`。这些状态不替换翻译任务已有状态。`ready` 由有效预览产生，`applied` 由已提交的应用记录产生，Agent 文字不能设置最终状态。

通过同源 Web Locks 独占锁 `tsukuyomi:import-agent` 协调各标签页，使用 `ifAvailable` 立即报告忙碌，不排入会自动启动的队列，也不使用 `steal`。锁覆盖本次模型循环和仍在执行的工具；任务记录保存宿主生成的运行代次，每次工具写入前检查代次和可执行状态。Web Locks 的锁会在回调完成时释放，支持该范围的跨页面协调。[API 行为](https://developer.mozilla.org/en-US/docs/Web/API/LockManager/request)

**Electron 单实例。**Electron 生产构建以 `file://` 载入，`navigator.locks`、`BroadcastChannel` 和模块 Worker 的可用性必须在打包产物中实测（任务 1.3），不能用开发模式结果推断。实测可用时与 Web 端一致。实测结论：同一进程内多个窗口之间 Web Locks 互斥正常，但同一 `userData` 的第二个进程仍能取得同名锁，且打开同一 IndexedDB 返回 `UnknownError`，即多开在现有版本中本就无法使用书库。因此本变更在主进程启动时调用 `app.requestSingleInstanceLock()`（`src-electron/single-instance.ts`）：同一 `userData` 工作区只允许一个进程，第二次启动直接退出并由已有实例还原、聚焦或重建工作台窗口。锁由 Electron 按 `userData` 目录区分，使用不同 `--user-data-dir` 的实例互不影响。单实例成立后，Electron 的导入运行锁、书籍执行占用与应用／撤销独占直接使用 Web Locks，与 Web 端一致；受保护执行前的 IndexedDB 可访问性预检保留为兜底，单实例锁意外失效时仍拒绝第二个进程写书库。不另建无锁的进程内互斥；Web Locks 不可用时拒绝执行。Web 端缺少 Web Locks 时仍拒绝执行。Worker 不可用时，解包、解码与匹配统一使用受上限约束、分段让出且可取消的主线程路径；`BroadcastChannel` 不可用时以数据库复核代替通知，两种降级都需在产物中验证。

暂停先进入 `pausing`、中止模型流和支持取消的请求、停止派发后续工具，再等待当前步骤停止后保存检查点并释放锁。不能因界面卸载释放后又让旧循环继续运行。恢复时若当前来源调用尚无已保存结果，按未完成处理；已有成功回执的提取或草稿操作不重放。

必要问题存为带 `questionId`、候选和来源范围版本的记录。问答界面继续复用月詠组件；导入执行器在问题待回答时保存待完成工具调用并让出执行，释放运行锁。现有工具循环按顺序等待每个调用，最后才返回整批结果，因此让出必须支持批内中断：已完成的工具结果照常落盘，未执行的调用连同问题一起保存，恢复时不重放已成功的部分。用户回答写入该问题的记录，继续执行时重新取得锁，再补入对应工具结果。

现有 `ask_user` / `ask_user_batch` 在调用 UI 桥之前就检查工具上下文中的 `bookId` 与书籍跳过设置。导入执行器必须在进入问答 handler 前提供不含 `bookId` 的导入问答上下文，仅传递任务及问题身份；候选书籍读取工具使用的临时书籍上下文不能泄漏到问答调用。只在 UI 桥入口去掉书籍 ID 已经太晚。普通聊天的问答行为和书籍跳过设置不变；取消或跳过也不能解除导入的必要选择，用户仍可从任务中完成选择。

小说候选由来源检查和 Agent 分析提出；检测到多本或追加来源归属冲突时设置 `novelScope` 待选择。只有用户界面或绑定问题的实际回答能写入 `user-confirmed` 证据，草稿编辑工具不能伪造该字段。一个文件包含多部作品时，来源归属可细化到内容范围；未选作品保留来源记录，不进入所选小说草稿。

刷新后只加载任务和检查点，不自动开始请求。取得锁后才把上一运行遗留的中断状态转换为可继续状态；锁仍被其他页面持有时，当前页面仅观察。Electron 在单实例锁下与 Web 端共用同一锁路径；缺少可靠互斥或所需持久化能力时明确显示不可执行原因，不退回仅能保护单标签页的假互斥。

**取舍：**采用浏览器提供的独占锁加持久运行代次，避免用易受后台节流影响的超时租约抢占仍在执行的任务。运行锁只控制导入 Agent，不锁住整本书直到任务结束；应用时另行校验目标状态。

### 8. 匹配生成显式变更计划，不直接拼接小说对象

新增纯函数为主的导入匹配与计划构建模块，输入为草稿、不可变提取结果、目标小说完整快照及已确认的对应关系，输出 `ImportPlan`。计划包含任务与草稿版本、目标与修改序号、内容引用版本、字段变更、卷章操作、段落对应、译文清空计数、缺失列表、冲突和新实体 ID。所有 ID 在计划生成时分配，应用重试不能再随机创建。

目标小说候选使用本地书名、作者及来源线索搜索。章节优先采用已应用记录中的来源对应、明确的一对一 URL 对应和用户选择；标题、顺序和相似内容只能提供候选。多个匹配或合并后设置冲突必须留作待处理问题，Agent 提出的对应不能伪装成用户已确认。

段落匹配遵循以下顺序：

1. 在已确认的章节或重组范围内建立旧段落序列，优先核对已有段落引用及来源映射。
2. 使用精确文本及唯一的前后文锚点对齐未变段落，再在限定大小的间隙内进行顺序匹配；重复句子的多种等价映射标记为冲突。避免对整本小说执行无界的二维比较。
3. 文本与对应关系均确定未变时复用原段落 ID、全部翻译及当前选用。段落移到其他章节也遵循此规则。
4. 明确的一对一原文修订保留逻辑段落身份，但令 `translations=[]`、`selectedTranslationId=''`；新插入段落分配新 ID 且没有译文。
5. 多对多改写或段落边界发生变化时，要求明确的替换范围，列出旧段落与新范围及译文损失后供用户确认，不任意继承旧译文。正文中的删除也是实际差异的一部分，不能伪装成未修改。

精确文本比较不做标点、全半角或语义近似归一化；来源解码与换行处理须固定并可追溯。仅移动章节边界不改变段落文本，因此可保留译文；拆分或合并段落本身则必须按真实对应与文本变化计算。

章节重组显式列出被替代的旧章节、保留／移动的段落及新结构。未匹配、未选择和抓取失败的旧章节加入最终保留集合，不能通过新旧数组差集删除。章节专属翻译指令或其他设置在合章时存在冲突的，列入预览待解决项。更新从旧小说派生，只修改确认字段，保留术语、角色、备注、设置等无关数据。

一对一网页章节沿用 `webUrl`；聚合多个资源或拆分一个来源时，以操作记录中的多来源映射为准，不把某个 URL 伪装为唯一身份。应用记录保存草稿到书库 ID 的映射，支持同一任务部分导入后的补齐；记录不可用时回到候选匹配，不能猜测已导入关系。

`preview_import` 从持久化书库读取完整的所需内容，不把懒加载未读取或读取失败当成空正文。现有 `loadChapterContent` 对「无记录」和「读取失败」都返回 `undefined` 并把失败缓存成 `null`，`getBookById(id, true)` 只是跳过赋值，二者无法区分，因此不能直接用于导入。新增区分错误的读取入口：在当前只读事务中直接读取正文记录，返回 `{ kind: 'loaded' | 'absent' | 'failed' }`，不复用旧 loader 的否定或可能过时的正缓存。仅记录不存在算 `absent`；合法空数组是 `loaded`，存储错误、反序列化失败和损坏的数据形状算 `failed`，失败不写否定缓存。候选正文读取工具、匹配、预览、前镜像和撤销检查都使用该入口，书籍元数据与正文取自同一快照边界；原调用方继续保持既有 loader 行为。出现 `failed` 时不能生成空快照或覆盖该章节。未解决覆盖冲突的部分不可应用，用户可解决或排除后生成新方案。

**取舍：**现有 `mergeNovelData` 的 URL 合并适合原网站导入流程，但不满足段落保留、无 URL 文件和跨章重组。新模块生成显式计划，不改变原有合并方法的默认语义；避免按段落索引配对或让模型输出最终数据库对象。

### 9. 书籍修改序号在持久化边界维护

新增 `book-revisions` 的本地单调序号。新旧小说在没有记录时从 0 开始；小说语义数据发生写入或删除时，在同一事务内递增。删除小说后保留其序号记录，避免相同 ID 恢复后误认为未变；完整工作区重置同时清理导入记录和序号。

接入点包括 `BookService` 的单本／批量保存和删除、`ChapterContentService` 的单章／批量保存和删除，以及同步、备份恢复经过的这些公共入口。独立 Memory 的创建、内容修改和删除也记录所属书籍修改，防止导入后新建的书籍关联数据被撤销创建所遗弃；访问时间、派生嵌入和索引更新不递增语义序号。仅查看页面或写 `book-details-ui` 不计作小说修改。

将书籍和章节的序列化及事务内写入辅助逻辑收敛到不依赖 Pinia 的持久化模块，供现有 Service 与导入应用共同使用。保留现有 Service 公共调用形式；单本保存需要一起保存正文时，将正文和结构放进同一事务，避免导入预览读取到半次保存。实际值未变的写入继续跳过；不能只依据 loader 的内存缓存判断是否更新序号。

导入计划记录 `baseBookRevision` 和语义快照摘要，撤销记录 `postApplyBookRevision`。摘要由现有规范化序列化和哈希能力计算，但不能代替单调序号：数据先改后恢复相同值，也已发生后续修改，不应重新获得旧快照撤销资格。

**取舍：**这是现有持久化层的局部一致性补充，不把 revision 加进同步协议，也不重建所有业务服务。仅检查 `lastEdited` 或当前内容哈希会漏掉章节独立写入、恢复旧时间戳和改后改回的情况。

### 10. 应用采用短事务，确认只绑定一个方案

用户点击确认时，由 UI 调用 `ImportApplyService`；该方法不注册为 Agent 工具。确认仅授权 `planId` 对应的任务、目标和草稿状态，不能从聊天文字或持久化的 `confirmed=true` 推导授权，也不在重新打开应用时自动续写。

**目标小说的在途写入与导入提交互斥。**`book-revisions` 只反映已提交修改，不能预见旧任务的迟到保存。`ai-processing` 的本页列表与 `thinking` / `processing` 状态只能用于提示：停止会立即标记 `cancelled`，但 `useChapterTranslation` 的 `finally` 仍会执行最终保存；另一标签页也有独立的内存列表。因此两次查询状态不能作为提交保障，`end` / `cancelled` 不代表写入已完全结束。

增加按 `bookId` 作用的执行占用守卫，供会写回正文／译文的 AI 执行入口及导入应用、撤销共同参加。Web 端采用同源书籍锁：AI 写任务在读取其操作快照前取得共享占用，并持有至全部回调与最终保存结束后的最外层 `finally`；导入应用和撤销只在实际提交阶段尝试取得短时独占占用，失败返回 `TARGET_BUSY` 及可查询的占用者信息。取得独占后再复核草稿、目标修改序号和快照，提交或失败完成后释放。新 AI 任务不能在检查与提交之间插入并读取旧快照；其后启动时必须重新读取提交后的数据。同一本书原有多个章节翻译可共享占用，其他书和只读 AI 操作不被阻止。Electron 由决策 7 的单实例锁保证只有一个进程，直接使用同一套 Web Locks 守卫。

此守卫包含整章、批量、单段翻译／润色／校对及其他会延迟写回正文的入口，任务状态仅提供 UI 说明，不是占用的权威。暂停或取消后，要等执行和最终保存真正结束才释放；不要只在模型服务内部持锁而漏掉 composable 的最终保存。操作持有的是一次执行占用，导入收集、整理和等待确认期间不独占整本书。本次不增加逐段版本校验协议，但任务级占用接入是应用／撤销前置工作，不能留到后续变更。已保存方案和已完成回执重复请求先按幂等规则识别，不把已经完成的提交再执行一次。

应用步骤：

1. 在事务外读取一致的目标快照及修改序号，完成正文装配、匹配、计数、哈希、序列化和封面值准备。不能在写事务中进行网络请求、模型调用、异步哈希或解包。
2. 用户看到的是已保存的确定方案。进入最终写事务后，重新读取任务与方案、草稿版本、目标存在性和 `book-revisions`；任何不符返回 `PLAN_STALE`，要求重新预览。生成预览时未应用的手动修改也必须先保存或明确提示未保存。
3. 在一个覆盖 `books`、`chapter-contents`、`book-revisions`、`import-tasks`、`import-operations` 的读写事务中，先登记恢复所需的前镜像，再写确定的新记录、删除显式重组淘汰的记录，最后保存应用结果与新修改序号。快照或任一写入失败则整个事务回滚。
4. 提交后才更新 Pinia 和正文缓存，发布提交通知，触发索引与嵌入维护。事务失败不提前替换 UI 中的书库对象。

前镜像包含旧小说元数据及受影响章节记录，新增记录使用“不存在”的前镜像标记。未受影响的章节不必重复存一份正文。计划中的 `operationId` 唯一标识一次导入；事务发现该操作已应用时返回既有回执，不重复新增或清空译文。

崩溃恢复读取操作记录：已提交就显示已应用并补做派生维护；未提交则书库保持原状，草稿仍待用户确认。没有“完成一半又从头追加”的默认路径。IDB 事务中只等待自身数据库请求，遵循 [idb 事务生命周期约束](https://github.com/jakearchibald/idb#transaction-lifetime)。

部分导入只装配选中且已成功提取的范围，缺失章节仍记录在任务中。之后向同一任务补源可产生新草稿版本和新方案；根据已应用映射跳过未变部分，新增补齐内容。每次应用独立记录快照，后一次应用会使前一次整次撤销失效。

**取舍：**用同一 IndexedDB 内的短事务实现核心数据原子性，不为每个章节另开一次应用事务。复用现有高层 `booksStore.updateBook` 会在持久化前修改 UI，并分阶段保存和清理，无法承担这个提交边界。

### 11. 撤销恢复内容，但作为新的本地修改提交

撤销先取得决策 10 的目标小说独占提交占用，再在事务内检查操作状态及目标 `postApplyBookRevision`。有尚未完成的正文写入时返回 `TARGET_BUSY`；当前序号不同、小说已删除或操作已撤销时拒绝旧快照覆盖。只检查已发生的修改仍可能漏掉已开始但尚未落盘的翻译，不能依据页面上曾经显示“可撤销”放行。

- 更新撤销恢复快照中的元信息、卷章、原文和全部译文，删除该次新增的记录，恢复被显式重组替代的记录。
- 新建撤销仅删除本次创建的小说及关联导入正文，并按现有 Gist 删除规则登记小说墓碑。保留全局封面历史等不专属于该小说的共享数据。
- 撤销完成后递增书籍修改序号，操作标记为 `reverted`。恢复业务内容与原创建信息，但为恢复写入使用新的本地编辑时间，使既有同步流程能够观察到此次修改。

需要登记删除墓碑时，把受影响的 `sync-configs` 记录纳入同一事务，读取最新配置并只合并目标小说的删除记录。抽取现有设置／删除路径中的定向合并能力，避免用旧的整个同步配置数组覆盖新墓碑；不回退整个同步设置或凭据。同步写回小说会递增本地书籍序号，因此导入后的同步变更同样阻止撤销。

导入任务、来源快照和事件不进入 Gist；应用与撤销产生的最终小说状态继续走现有同步流程。本设计保证当前本地工作区的提交与撤销，不承诺跨设备原子回滚，也不改变已有同步冲突规则。

**取舍：**采用“无后续修改才可整次撤销”的已确认规则，不引入差异撤销或三方合并。直接恢复旧 `lastEdited` 或仅删除本地新书而不登记墓碑，会使同步语义与用户撤销意图不一致。

### 12. 提交后的缓存与派生数据维护可重试

从现有章节保存／删除路径提取共享的提交后维护能力，用于正文 loader 缓存失效、书库与当前章节刷新、全文索引失效、被删除章节的嵌入取消与清理，以及保留章节的重新计算。导入不复制另一套索引维护逻辑。

操作记录持久化尚未完成的维护事项，事务提交后执行；失败只影响对应派生状态，不能把已成功提交的书库导入再报告成“没有导入”并重新执行。恢复时按目标小说的当前状态重试，已过时的维护任务不重新写回旧正文。

当前标签页通过只更新缓存的 store 入口加载已提交记录，不再调用会二次保存的 `updateBook`。其他标签页通过 `BroadcastChannel` 得到小说 ID、修改序号和受影响章节 ID 后失效本地缓存；消息丢失时在重新聚焦、预览或撤销前从数据库检查。数据库始终是应用判断的依据。

**取舍：**索引与嵌入是可重建数据，放在书库事务外能缩短事务并复用既有异步服务；提交记录保存维护状态，避免页面关闭后永久遗留旧缓存或索引。

## Risks / Trade-offs

- **站点无法取得正文或返回验证页面** → 工具返回结构化失败，保留来源与已成功内容，支持同任务补文件；不扩展为远程浏览器方案。
- **来源和撤销快照占用较多存储** → 原始资源与正文按需读取、引用复用、解包及任务容量有上限；保存失败明确提示，无法保存快照时不应用。
- **重复文本和不同版本难以可靠匹配** → 精确锚点与限定范围对照，歧义留给用户，不把模型置信度当作保留或清空译文的依据。
- **较大文本阻塞页面** → 解包与匹配放到 Worker；模型只读分页，算法按章节／明确重组范围处理，避免整书无界比较。
- **解析规则错误删除正文** → 原始快照、规则、排除记录和新旧提取结果均可检查；空正文不算成功，未确定的附属内容先保留。
- **工具结果或旧页面串写任务** → 运行上下文由宿主绑定，保存时检查任务 ID、运行代次和草稿版本；来源文本不具备工具授权能力。
- **持久化入口遗漏修改序号** → 审计所有生产代码中的书籍／正文／书籍关联语义写入与清空入口，包含同步和备份恢复；用跨入口用例验证预览失效和撤销阻止，不能只测导入自己的写入。
- **模型调用结束不等于计划完整** → 宿主检查待回答问题、缺失状态和匹配冲突；达到循环上限暂停，不宣称完整导入。
- **旧标签页和新数据库版本混用** → 升级按现有 blocked 机制提示关闭或刷新旧页面；不会在升级受阻时开始导入执行。
- **Web Locks、目录选择或存储能力不足** → 运行前检测；目录选择可用批量文件替代。Electron 的 `file://` 能力已在产物中验证；多实例由主进程单实例锁排除，锁失效时由 IndexedDB 预检拒绝第二个进程执行。
- **在途或取消后收尾的翻译覆盖导入／撤销** → 任务级书籍占用保持至最终保存完成，应用与撤销短时独占同一目标；验证跨标签页、终态后的收尾及启动竞争，不能只查 UI 状态。
- **懒加载读取失败被当成空章节** → 匹配、预览、前镜像与撤销统一走区分错误的读取入口，失败不写否定缓存、不落入空正文分支；跨入口用例覆盖「读取失败的章节既不被清空也不被快照成空」。
- **重组后的章节不再一对一对应旧网站章节** → 导入操作保留多来源映射供后续 AI 导入使用；旧网站导入的 URL 合并语义保持原状，不将其作为重组匹配依据。

## Migration Plan

1. 以现有助手默认行为、网站抓取结果、书籍正文保存和同步恢复用例建立回归基线，在打包的 Electron 产物中验证 `file://` 能力和同工作区多实例／窗口重建边界，确定决策 7 中各条件路径是否可用，再按测试先行方式引入共享接口。
2. 增量创建导入 stores 和本地修改序号 store，更新数据库完整清理及测试重置路径；既有小说按需使用初始序号，不进行全文重写或迁移进导入任务。
3. 接入公共持久化写入的修改序号、严格快照读取、事务内辅助方法、AI 写任务的完整执行占用与共享提交后维护；验证独立保存、终态收尾、批量同步和恢复等入口都不会绕过导入与撤销守卫。
4. 完成来源快照、两层工具、解析与元信息搜索用途约束，以及独立草稿和持久执行检查点。
5. 接入助手执行配置、月詠展示适配器和各设备页面，验证来源登记本身无提取副作用，多标签执行互斥且页面切换不改变运行归属。
6. 接入计划、应用和撤销，验证重复请求、事务失败、提交后页面关闭、部分导入后补齐、目标并发变更和撤销前再次修改。
7. 运行针对性测试及项目要求的 lint、类型与质量检查，再验证实际 Web 与 Electron 构建中的 EPUB 解析、代理请求、设备入口以及步骤 1 实测过的互斥与 Worker 行为。具体任务拆分放入下一产物。

回退采用前向兼容版本关闭导入入口和执行，保留新增 stores 与原有书库数据，不降低 IndexedDB 版本。不能直接回滚到只认识旧数据库版本的构建。已应用的小说使用现有模型可继续读取；需要撤销时遵循同一后续修改守卫，不做批量快照回滚或清库。

## Open Questions

- 文本分页大小、单次提取批量、解压规模和任务存储上限的具体默认值，在桌面与手机真实样本中确定；分页、限额及超限失败机制已确定，不影响工具职责与任务拆分。
- 同一技术方案下，任务列表在窄屏使用列表页还是选择抽屉，可在页面实现时根据空间验证确定；不改变任务、会话和草稿的绑定方式。
