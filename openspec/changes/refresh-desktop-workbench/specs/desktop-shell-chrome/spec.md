## ADDED Requirements

### Requirement: 桌面端保持多区工作台骨架

系统 MUST 在桌面断点下将应用壳层呈现为顶部系统条、左侧主导航、中央页面画布和右侧上下文面板组成的工作台骨架，并继续沿用现有 `ui.sideMenuOpen`、`ui.rightPanelOpen` 与 `ui.rightPanelWidth` 的状态语义。

#### Scenario: 桌面主路由加载时保持多区骨架
- **WHEN** 用户在桌面断点进入任意主路由
- **THEN** 系统 MUST 同时渲染顶部系统条、左侧主导航、中央内容画布和右侧上下文面板容器，且中央内容区 MUST 保持独立滚动

#### Scenario: 面板开合保留桌面工作流语义
- **WHEN** 用户切换左侧导航或右侧上下文面板的开合状态
- **THEN** 系统 MUST 复用现有开合行为与宽度状态，并 MUST NOT 退化为 mobile 或 tablet 的覆盖式导航流程

### Requirement: 桌面页面共享工作台语法

系统 MUST 为桌面主页面提供一致的页面语法，包括 eyebrow、主标题、摘要、统计条或状态条、section surface 与统一内容边距，使书库、书籍详情、设置、AI 与帮助页面在桌面下呈现同一套 workbench 视觉层次。

#### Scenario: 桌面内容页使用统一标题区
- **WHEN** 任一桌面主页面渲染主要内容
- **THEN** 页面 MUST 提供由 eyebrow、主标题、摘要和主要操作区组成的标题区，而不是沿用彼此割裂的历史标题样式

#### Scenario: 桌面内容页使用统一区块表面
- **WHEN** 桌面主页面渲染统计条、工具区、列表区块或上下文说明区
- **THEN** 这些区块 MUST 共享一致的表面材质、边框、圆角和垂直节奏，以形成连续的桌面工作台体验

### Requirement: 桌面导航与上下文保持一跳可达

系统 MUST 保持桌面端主导航与上下文工具的一跳可达性，并 MUST NOT 以手机底部导航、平板 rail-only 导航或 drawer-only 入口替代桌面直接操作。

#### Scenario: 左侧主导航保持稳定直达
- **WHEN** 用户在桌面端切换首页、书库、AI、设置或帮助
- **THEN** 系统 MUST 通过左侧主导航直接提供入口，而无需先展开覆盖式抽屉

#### Scenario: 右侧上下文面板保持流程连续
- **WHEN** 用户在桌面端打开 AI 助手、翻译进度或其他右侧上下文工具
- **THEN** 系统 MUST 在当前页面上下文内打开右侧面板，并保持当前主内容页与用户定位不丢失
