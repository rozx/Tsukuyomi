# Proposal

## Why

书籍详情的「检查更新」只能用于四个内置抓取站点，且依赖 `book.webUrl`；AI 导入器导入的书（包括来自内置站点的书）没有记录任何来源，检查更新形同虚设。现有更新应用链路整章替换正文（一个错字也清空全章译文），没有与翻译任务的写入互斥，撤销也无法恢复懒加载的章节正文。每次检查都调用 Agent 又太贵且不确定，因此需要一份可确定性回放的「来源配方」和一个与界面解耦的同步服务。

## What Changes

- 书籍新增可选的「更新配方」：记录目录网址、回放引擎（内置站点引擎或通用 HTML 选择器引擎）、正文清理规则、标题剥离设置、已跳过章节与录入自测信息；随书籍数据保存和云同步。
- 没有配方但 `webUrl` 指向内置站点的书，在检查时由系统推导「虚拟配方」，不写回书籍，现有书籍无需迁移。
- 新增确定性回放：按配方抓取目录与正文、执行清理，不调用任何 Agent，也不创建导入任务；硬失败（抓取失败、验证页、目录无法识别已导入章节、正文为空、清理超时）一律判定为「配方失效」，不产出部分结果。
- 新增同步服务：
  - 快速检查（目录 + 内置引擎按日期筛出的候选章节）与可取消的深度检查（逐章比对已导入正文，最多 3 路并发）；
  - 生成绑定书籍修改序号的变更集：新章节（含按相邻章节推断的目标卷）、有更新（含段落级匹配结果与将清空的译文版本数）、已跳过、失败；
  - 正文在一次会话内只抓取一次，预览、比对与应用共用；
  - 应用时与翻译等正文写入互斥，书籍修改序号变化则拒绝并要求重算；部分成功仅写入成功项；
  - 会话内撤销：书籍在应用后未再修改时可恢复应用前的书籍记录与受影响章节正文。
- 跳过/取消跳过章节：写入配方的已跳过列表（首次跳过时把虚拟配方落为真实配方）。
- 本变更不修改任何界面；现有 `NovelScraperDialog` 与更新面板保持不变，由后续变更 `redesign-book-sync-ui` 接入。

## Capabilities

### New Capabilities

- `book-sync-recipe`: 书籍更新配方的内容、虚拟配方推导、确定性回放、清理执行安全与配方失效判定。
- `book-sync-service`: 基于配方的检查（快速/深度）、变更集生成、目标卷推断、段落级合并、版本绑定的受保护应用、部分成功与会话内撤销，以及跳过章节管理。

### Modified Capabilities

（无：现有界面行为在本变更中不变。）

## Impact

- 模型：`src/models/novel.ts`（`Novel.updateRecipe`），新增同步相关类型。
- 服务：新增 `src/services/book-sync/`（配方解析、引擎、检查、变更集、应用）；复用 `NovelScraperFactory` 内置抓取器、`fetchScraperPage`、`parseImportHtml`、导入器正则 worker 作业、`matchImportParagraphs`、`BookExecutionGuard`、书籍修改序号与 `bookCommitBus`。
- 数据：书籍记录新增可选字段，经 `serializeBookRecord` 与 Gist 同步透传；无数据库版本升级。
- 质量检查：本变更单独落地时同步服务尚无界面消费者，Fallow 可能报告未使用导出；与 `redesign-book-sync-ui` 同分支交付后消除，不做行内抑制。
