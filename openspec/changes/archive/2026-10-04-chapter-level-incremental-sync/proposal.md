# Proposal

## Why

新增一章会改变整本书的哈希，导致整本压缩流的所有分块重新上传。实测只新增一小章也会上传 13 个文件。需要缩小同步粒度，同时避免每章一个 Gist 文件触发 300 文件列表截断。

## What Changes

- 分离书籍元数据/目录与章节正文，用章节稳定 ID 将每本书分为 16 个固定小组，组内按 ID 排序；只上传变化的小组与目录。
- 下载变化的小组并与目录重组，保留未下载章节的本地内容及未上传编辑，继续使用既有合并和删除规则。
- **BREAKING**：manifest 协议升级到 v6，兼容读取旧版整书文件并迁移；同步、强制覆盖和历史恢复均支持新布局。
- 在写入前检查最终及中间文件数量，超过 Gist API 可完整列出的 300 文件时中止，避免写入后无法读取。
- 保留哈希校验、失败不推进同步状态、逐批并发检查与章节结构基准。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `sync-manifest`：章节小组布局、局部传输、v6 迁移与完整恢复。

## Impact

涉及 manifest 构建、Gist 编解码和上传/下载、历史恢复、同步执行器结构基准、局部书籍合并及三语言同步文档。不新增依赖，不变更本地书籍模型和数据库布局。
