## MODIFIED Requirements

### Requirement: 桌面端保持多区工作台骨架

系统 MUST 在桌面断点下将应用壳层呈现为顶部系统条、左侧主导航和中央页面画布组成的工作台骨架；右侧上下文面板只在 AI 助手打开时（或导入页上）出现，关闭时右侧 MUST NOT 保留任何图标栏或占位宽度。系统继续沿用现有 `ui.sideMenuOpen`、`ui.rightPanelOpen` 与 `ui.rightPanelWidth` 的状态语义。

#### Scenario: 桌面主路由加载时保持多区骨架
- **WHEN** 用户在桌面断点进入任意主路由
- **THEN** 系统 MUST 同时渲染顶部系统条、左侧主导航和中央内容画布，且中央内容区 MUST 保持独立滚动；助手面板打开时 MUST 另外渲染右侧面板

#### Scenario: 面板开合保留桌面工作流语义
- **WHEN** 用户切换左侧导航或右侧助手面板的开合状态
- **THEN** 系统 MUST 复用现有开合行为与宽度状态，并 MUST NOT 退化为 mobile 或 tablet 的覆盖式导航流程

#### Scenario: 助手关闭时右侧不占宽度
- **WHEN** 桌面端非导入页上助手面板处于关闭状态
- **THEN** 中央内容画布 MUST 延伸到窗口右边缘，右侧 MUST NOT 显示图标栏

#### Scenario: 助手打开时停靠在右侧
- **WHEN** 用户在桌面端打开助手面板
- **THEN** 面板 MUST 停靠在右侧并挤窄中央画布（而非覆盖在其上），且 MUST 可以拖动调整宽度

#### Scenario: 导入页助手面板常驻
- **WHEN** 用户在桌面端处于导入页
- **THEN** 助手面板 MUST 保持打开且不可关闭

### Requirement: 桌面导航与上下文保持一跳可达

系统 MUST 保持桌面端主导航与上下文工具的一跳可达性，并 MUST NOT 以手机底部导航、平板 rail-only 导航或 drawer-only 入口替代桌面直接操作。

#### Scenario: 左侧主导航保持稳定直达

- **WHEN** 用户在桌面端切换首页、书库、AI、设置或帮助
- **THEN** 系统 MUST 通过左侧主导航直接提供入口，而无需先展开覆盖式抽屉

#### Scenario: 右侧上下文面板保持流程连续

- **WHEN** 用户在桌面端打开 AI 助手或其他右侧上下文工具
- **THEN** 系统 MUST 在当前页面上下文内打开右侧面板，并保持当前主内容页与用户定位不丢失

#### Scenario: 任务进度从顶部系统条一跳可达

- **WHEN** 用户在桌面端任意页面想查看翻译、润色或校对任务进度
- **THEN** 系统 MUST 通过顶部系统条的任务中心 chip 一次点击打开任务中心，MUST NOT 要求先打开右侧面板或切换页签

#### Scenario: 助手从顶部系统条一跳可达

- **WHEN** 用户在桌面端任意页面点击顶部系统条的助手按钮
- **THEN** 系统 MUST 打开助手面板；面板已打开时再次点击 MUST 关闭它（导入页除外），按钮 MUST 在面板打开时显示激活态

#### Scenario: 窄窗口下顶部系统条不溢出

- **WHEN** 桌面端（含 Electron）窗口宽度缩小到顶部系统条放不下全部文字
- **THEN** 系统条 MUST 按固定顺序收起文字（品牌副标题、同步倒计时、各按钮文字），只保留图标与任务中心的数字，MUST NOT 出现横向溢出或按钮被挤出视口

#### Scenario: 面板关闭时从正文发送到助手

- **WHEN** 助手面板关闭时用户对段落执行「复制到助手」或「解释选中」
- **THEN** 系统 MUST 打开助手面板并把内容填入输入框
