# agent-mcp-desktop-server Specification

## Purpose
在 Electron 桌面应用中提供面向本地 Coding Agents（如 Claude Code、Pi、Antigravity）的本地 Streamable HTTP MCP 服务端、安全鉴权机制、进程间工具桥接以及与跨设备同步隔离的本机配置持久化。

## Requirements

### Requirement: 仅限本机回环的 Streamable HTTP MCP 服务端
桌面端应用 SHALL 在启用本地 MCP 服务后，在 `127.0.0.1` 的可配置端口上提供符合 MCP Streamable HTTP 规范的 JSON-RPC 2.0 端点，并 MUST 在同一端点上同时服务使用初始化握手的旧版协议客户端与使用无状态逐请求协议版本的新版协议客户端，支持服务端能力发现、工具发现与调用以及工作流 Prompt 发现与读取。

#### Scenario: 旧版协议客户端完成握手并发现工具与工作流
- **WHEN** 外部 MCP 客户端携带有效凭据向本机 `/mcp` 端点发送 `initialize`、`tools/list` 与 `prompts/list` 请求
- **THEN** 服务端返回兼容的协议版本、服务端能力声明、当前权限下可用的工具清单以及内置翻译工作流 Prompt 清单

#### Scenario: 新版协议客户端无需握手直接发现并调用工具
- **WHEN** 外部 MCP 客户端携带有效凭据，不发送 `initialize`，直接发送带逐请求协议版本的服务端发现、`tools/list` 或 `tools/call` 请求
- **THEN** 服务端按无状态语义独立处理每个请求，返回受支持的协议版本、服务端能力、工具清单或工具执行结果

#### Scenario: 新版协议请求头缺失或与请求体不一致
- **WHEN** 新版协议请求缺少必需的协议请求头，或请求头中的协议版本、方法名、工具名与请求体不一致
- **THEN** 服务端返回 HTTP 400 与明确的 JSON-RPC 错误，且不向渲染进程转发调用

#### Scenario: 请求的协议版本不受支持
- **WHEN** 客户端请求了服务端不支持的协议版本
- **THEN** 服务端返回包含受支持版本列表的 JSON-RPC 错误，使客户端可以选择共同支持的版本重试

#### Scenario: 不提供流式与会话端点
- **WHEN** 客户端向 `/mcp` 发送 `GET` 或 `DELETE` 请求
- **THEN** 服务端返回 HTTP 405，且任何响应中都不签发会话标识

#### Scenario: 默认不自动监听本地端口
- **WHEN** 用户首次启动桌面应用且未显式开启本地 MCP 服务
- **THEN** 桌面端 MUST NOT 监听任何本地 MCP HTTP 端口

### Requirement: Bearer Token 鉴权与防跨站重绑定校验
本地 MCP 服务端 MUST 要求每个请求携带与本机有效令牌匹配的 `Authorization: Bearer <token>` 请求头，且 MUST 校验请求 `Host` 仅属于本机回环地址并拒绝携带非本机来源的浏览器 `Origin` 请求。

#### Scenario: 缺少或错误的令牌被拒绝
- **WHEN** 客户端未提供 `Authorization` 请求头或提供已失效令牌访问 `/mcp`
- **THEN** 服务端返回 HTTP 401 状态码且不向渲染进程转发调用

#### Scenario: 跨站网页尝试访问本地端口被拦截
- **WHEN** 带有外部网站 `Origin` 请求头或非本机 `Host` 请求头的请求到达本地 MCP 端口
- **THEN** 服务端返回 HTTP 403 状态码并拒绝处理

#### Scenario: 重置令牌后旧令牌立即失效
- **WHEN** 用户在界面触发重新生成令牌
- **THEN** 新生成的随机令牌立即生效，使用旧令牌发起的后续请求返回 HTTP 401

### Requirement: 主进程与渲染进程的双向工具桥接
桌面端主进程收到合法的 `tools/list`、`tools/call`、`prompts/list` 或 `prompts/get` 请求时 SHALL 通过安全进程间通信转发至应用渲染进程中的共享工具内核执行，并将结构化结果或错误回传给 MCP 客户端。

#### Scenario: 通过本地 MCP 端点执行工具并实时更新书库界面
- **WHEN** 外部 Coding Agent 调用本地 MCP 端点的译文提交工具
- **THEN** 主进程将调用路由至渲染进程工具内核落盘，向客户端返回工具执行结果，且桌面应用界面实时刷新显示新译文

#### Scenario: 渲染进程未就绪或调用超时返回结构化错误
- **WHEN** 工具请求到达时主窗口尚未就绪或执行超过超时阈值
- **THEN** 服务端向客户端返回明确的 JSON-RPC 错误响应而不会造成主进程挂起

#### Scenario: 启动时同步失败
- **WHEN** 渲染进程挂上桥接监听后，首次与主进程同步服务状态失败
- **THEN** 已挂上的监听被卸下，之后重新启动桥接时不会出现重复监听

#### Scenario: 主窗口关闭后重新打开
- **WHEN** 本地 MCP 服务运行期间主窗口被关闭，随后重新打开
- **THEN** 窗口关闭时仍在等待的请求立即收到错误响应，窗口重新就绪后的新请求正常执行

#### Scenario: 非主窗口来源的桥接消息被忽略
- **WHEN** 主进程收到并非来自应用主窗口顶层页面的 MCP 桥接消息
- **THEN** 主进程忽略该消息，不启动、停止或重新配置服务，也不将其作为工具执行结果返回给客户端

### Requirement: 端口冲突与生命周期管理
桌面端 MCP 服务端 SHALL 支持运行期启动、停止、修改端口后重启以及应用退出时自动清理监听；当目标端口已被占用时 MUST 返回明确错误信息并保持停止状态，不得导致应用崩溃。

#### Scenario: 配置端口被占用时优雅报错
- **WHEN** 用户尝试启动本地 MCP 服务但所选端口已被本机其他进程占用
- **THEN** 启动失败并向界面报告端口占用错误状态，应用其余功能不受影响

#### Scenario: 启动尚未完成时收到停止
- **WHEN** 本地 MCP 服务还在启动或更换端口，主进程又收到停止请求
- **THEN** 启动与停止按收到的先后依次执行，最终服务处于停止状态，端口不再被监听

### Requirement: 本机配置持久化与 Gist 同步隔离
桌面端 MCP 服务开关、监听端口、Bearer Token、WebMCP 开关、权限模式、默认写回策略与写操作通知开关 SHALL 持久化保存在本机设备设置中；在执行 GitHub Gist 数据同步或导出备份文件时 MUST 剥离上述本机敏感与设备专属字段，且下载、恢复远端设置或导入备份文件时 MUST 保留当前设备既有值。

#### Scenario: 上传配置到 Gist 不泄露本机令牌与端口
- **WHEN** 用户开启本地 MCP 服务并执行 Gist 同步上传
- **THEN** 上传到远端 Gist 的设置载荷中不包含本机 MCP 令牌、监听端口与开关状态

#### Scenario: 从 Gist 下载或恢复设置保留本机 MCP 配置
- **WHEN** 用户从 Gist 同步下载设置或恢复历史修订版本
- **THEN** 当前设备已保存的 MCP 令牌、端口与运行开关保持原值不变

#### Scenario: 仅修改本机 MCP 配置不产生待同步的设置变更
- **WHEN** 用户只修改了 MCP 开关、端口、令牌或权限模式
- **THEN** 参与同步比对的设置内容保持不变

#### Scenario: 导出与导入备份文件不携带 MCP 配置
- **WHEN** 用户导出设置备份文件，或导入来自其他设备的备份文件
- **THEN** 导出的文件不包含本机 MCP 令牌、端口与开关状态，导入后当前设备的 MCP 配置保持原值不变
