## 📌 打開與關閉 {#settings-guide-section-2}

- 設定頁會記住你上次打開的分頁。

## 🌐 一般設定 {#settings-guide-general}

**介面語言**可選擇簡體中文、繁體中文或 English。無已儲存偏好時匹配系統首選語言：繁體腳本及台港澳用繁中，簡體腳本、中國大陸和新加坡用簡中，英語地區用英文，其他語言回退簡中。

手動選擇會保留到下次啟動，並參與應用設定同步；收到同步偏好後介面即時更新。介面切換不會翻譯歷史訊息、使用者指令、角色描述、記憶或歷史更新紀錄，也不會自動翻譯小說。

新書在真正建立時以當時的介面語言初始化目標。已有書籍請在 **書籍詳情 → 設定 → 翻譯設定** 修改目標，介面切換不會改變它。正在運行的 AI 任務使用啟動時的語言；新執行才採用新設定。

## 2) 🌐 代理設定（僅瀏覽器版） {#settings-guide-section-7}

用於配置瀏覽器版訪問網頁與 AI 服務時使用的 CORS 代理。

### 基礎開關 {#settings-guide-section-8}

- **啟用代理**：開啟後，爬蟲和網路工具會優先走代理。

> 舊版的「自動切換代理服務」已移除：請求失敗時不再依次嘗試列表中的其他代理，而是由 Firecrawl 備援兜底（見「API Keys」與「網站對應」）。

### 預設代理與代理 URL {#settings-guide-section-9}

- 可從“選擇代理服務”下拉中選擇（預設 CORS Tsukuyomi）。
- 代理 URL 支持模板：`...{url}`。
- 當選擇了列表中的代理服務時，URL 輸入框會被鎖定為對應項。

### 代理列表管理 {#settings-guide-section-10}

- 添加代理（名稱、URL、可選描述）
- 編輯代理
- 刪除代理
- 測試代理（測試目標為 `https://www.duckduckgo.com`）
- 拖曳排序

列表中的其他代理只會在你把它設為預設代理，或寫入某個網站的對應時使用。

### 重要說明 {#settings-guide-section-11}

- 該分頁只在非 Electron 環境顯示。
- 即使關閉代理，瀏覽器版對部分內置站點仍會走應用內 `/api/...` 路徑。
- 瀏覽器版 AI 模型請求使用獨立的預設 CORS 代理邏輯，不受此處“代理 URL”直接控制。

## 3) 🗺️ 網站對應 {#settings-guide-section-12}

為特定網站指定抓取方式，按順序優先使用。瀏覽器版與桌面版都會顯示。

### 抓取順序 {#settings-guide-section-13}

1. 網站對應的第一項是 **Firecrawl**（且已啟用 Firecrawl 備援）時，直接經 Firecrawl 抓取。
2. 否則先按對應中的 CORS 代理依次嘗試（沒有對應時使用預設代理）；關閉代理時走 `/api/...` 或直接訪問；桌面版始終直接訪問。網路錯誤、超時、429、5xx 會稍後重試一次。
3. 仍被攔截（403、429、5xx、網路錯誤，或返回了 Cloudflare 等反爬驗證頁）且已啟用 Firecrawl 備援時，改由 Firecrawl 抓取。404 等“頁面不存在”不會回退。

### 自動新增對應 {#settings-guide-section-14}

- **僅 Firecrawl 可用時自動新增對應**：網站只能經 Firecrawl 抓取成功時，自動把 Firecrawl 置頂寫入該網站的對應，之後直接使用 Firecrawl，不再先嘗試代理。
- 該開關依賴「API Keys」中的 Firecrawl 備援總開關。
- 自動寫入不會彈出提示；如果網站恢復了代理訪問，可在對應中移除 Firecrawl 或調整順序。

### 對應管理 {#settings-guide-section-15}

- 輸入網站域名或網址，選擇 CORS 代理或 **Firecrawl** 後添加。
- 每個網站最多 **3** 項，可在編輯對話框中調整順序、啟用/禁用。
- 桌面版直接訪問網站，對應中的 CORS 代理條目顯示為不生效，只有 Firecrawl 條目生效。

## 4) 🔑 API Keys {#settings-guide-section-16}

### Tavily 搜索 API Key {#settings-guide-section-17}

- 用於 AI 網路搜索與網頁讀取（助手聊天、匯入元資訊，以及翻譯 / 潤色 / 校對任務）。
- 點選“儲存”後寫入本地設定；清空後儲存可移除該 Key。

### Firecrawl {#settings-guide-section-18}

- **啟用 Firecrawl 備援**（預設開啟）：網頁抓取被攔截時改由 Firecrawl 抓取；同時在未配置 Tavily（或 Tavily 出錯）時，為助手聊天與匯入提供網路搜索 / 網頁讀取。開啟後，被訪問頁面的網址與搜索內容會發送給 Firecrawl。
- **API Key（選填）**：未配置時使用 keyless 免費模式，按 IP 有每日請求數與額度上限（具體數值未公開）。
- 儲存 Key 時會先查詢額度驗證，Key 無效時不會儲存。
- **檢查額度**：顯示剩餘額度 / 套餐額度與帳期結束日（需要已儲存 Key）。
- 額度用盡時，正在進行的批量匯入 / 更新檢查會停止，已獲取的章節會保留；稍後或補充額度後可繼續。

## 5) 🔄 同步設定（GitHub Gist） {#settings-guide-section-19}

用於配置並執行 Gist 同步。

### 基礎配置 {#settings-guide-section-20}

- 啟用 Gist 同步
- GitHub 使用者名
- GitHub Personal Access Token
- Gist ID（可選，留空可在上傳時建立）

> ⚠️ **同步內容包含 API Key**：AI 模型的 API Key、Tavily API Key 與 Firecrawl API Key 會以明文隨配置上傳到 Gist。應用建立的 Gist 為 secret（不公開列出），但任何拿到鏈接的人都能查看，請勿分享 Gist 鏈接。GitHub Token 本身不會上傳。如不希望密鑰離開本設備，請不要開啟 Gist 同步。

### 操作按鈕 {#settings-guide-section-21}

- **驗證 Token**
- **上傳到 Gist**
- **從 Gist 下載**（未填 Gist ID 時不可用）

### 自動同步 {#settings-guide-section-22}

- 可啟用“自動同步”。
- 同步間隔範圍：**1~1440 分鐘**。
- 自動同步會先用條件請求檢查遠端是否有變化。遠端無變化時不消耗 GitHub API 配額，可以放心設定較短的同步間隔。

### 增量同步與並行衝突處理 {#settings-guide-section-23}

從 v0.10.1 起，同步採用基於 **manifest（清單）** 的增量策略：

- **只上傳變化的內容**：編輯一本書後觸發同步，僅該書與清單檔案會被上傳；其他書籍、AI 模型、封面、記憶庫都不會被重復推送。
- **選擇性下載**：遠端有更新時，只反序列化並合並行生變化的條目，未變更的資料不會被重新處理。
- **多設備並行保護**：上傳前會再次檢查遠端是否被其他設備修改。如發現並行寫入，自動重新拉取合併後重試（最多 3 次）。超過後會提示“其他裝置正在頻繁寫入，請稍後再試”。
- **跨設備智能配對**：同一在線章節即使在不同設備生成了不同本地 ID，也會優先按來源 `webUrl` 配對；卷在 ID 不一致時會按原文標題回退匹配並保留已有譯名，減少重復卷與重復章節。
- **同步快照邊界**：同步以本地資料打包前的快照時刻為邊界。上傳期間繼續產生的編輯會保留到下一輪同步，不會被誤判為已經上傳或被遠端刪除。
- **失敗條目重試**：單條下載、解析或應用失敗時，不會把該條目標記為已同步；下輪會重新拉取，避免陳舊本地副本覆蓋遠端新資料。
- **刪除跨端傳播**：manifest 中保留墓碑（tombstones）記錄，在 A 設備上刪除的條目不會被 B 設備重新推回。
- **頭部待同步提示**：Header 會顯示當前待同步變更的數量，點選同步按鈕旁的小 Popover 可以查看每一項的具體修改。徽標覆蓋書籍、AI 模型、封面、應用設定、**記憶庫條目**以及跨端刪除墓碑（自 v0.11.1 起補齊記憶變更）。

> 超過 300 個檔案時，GitHub API 可能只回傳部分檔案清單。應用會讀取同一修訂版本的同步清單，補齊未列出的同步檔案，並繼續增量同步；清單或升級時儲存的暫存目錄無法使用時會安全中止。

### 章節原文與譯文合併 {#settings-guide-section-24}

從 v0.16.0 起，每台設備會在成功同步後記錄章節的段落結構基準，區分原文修改和新增譯文：

- **只有一端改了結構**：已有同步基準時，採用該端的段落順序與原文。另一端即使剛完成翻譯，也不會因此把已刪除的段落帶回。
- **譯文合併**：只有原文完全一致的段落才合併雙方譯文；段落 ID 相同但原文不同，不會把舊原文的譯文套到新原文上。
- **語言隔離**：原文相同時，段落版本及各語言選用分別合併，標題與術語、角色、別名譯名的語言槽也分別儲存；清空一個語言槽不刪除其他語言。舊資料沒有語言標記時歸為簡中。
- **兩端都改了結構**：以較新的章節為主，追加另一端獨有的段落，並在同步結束後列出有衝突的書籍和章節，請檢查合併結果。
- **尚無基準**：沿用原有規則，以較新章節為主並追加另一端獨有的段落。升級後完成成功同步，才會逐步建立基準；基準只存在當前設備，不上傳到 Gist。

### 🔐 同步憑據安全 {#settings-guide-section-25}

- GitHub Personal Access Token 只保留在當前設備。
- 首次上傳、增量上傳與強制推送都會從同步包中剝離 Token，不會把憑據寫入 Gist。
- 即使首次上傳在建立 Gist 後的驗證階段失敗，應用也會儲存已建立的 Gist ID，重試時不會繼續建立孤兒 Gist。

### 🧹 強制推送模式（Force Push） {#settings-guide-section-26}

用於"遠端資料損壞"或"設備遷移"場景，把遠端清空後用本地資料**完全覆蓋**：

- 位置：同步設定 → 強制推送開關（預設關閉）。
- 啟用後下一次上傳以本地可見內容為準整體重寫 Gist；仍須讀取並驗證遠端協議及實體刪除元資料，讀取失敗或發現未來協議時不上傳。
- 操作具有破壞性，請務必先在接收設備備份，並確保其他設備暫不觸發自動同步。

> 💡 **多設備使用者注意**：Manifest 架構涉及 Gist 檔案結構調整。建議在所有已登錄同一賬戶的設備上同步升級客戶端後再觸發同步。首次從舊佈局同步時會自動執行一次性遷移（讀取舊佈局 → 合併本地資料 → 以新佈局重寫 Gist），遷移失敗時本地資料保持不變，下次同步會自動重試。

### 多語言協議與實體刪除 {#settings-guide-language-sync}

- 書籍目錄與正文分開儲存，正文按章節 ID 固定分為最多 16 個小組，空組不占檔案。新增一章通常上傳所在小組、目錄與清單；只修改正文時，未變更的目錄也會跳過。小組過大時仍會分塊，插入或重排章節不會讓其他組重新分配。
- 首次升級到 v6 會完整遷移舊書籍，此次上傳量仍可能較大。遷移中斷後保留舊版正文，下一次同步可重試。歷史還原會重組全部正文組，任一所需組缺失或損壞都會中止還原。
- 300 是 GitHub API 檔案清單的回傳上限，不是書庫容量上限。超過該數量仍可同步；客戶端下載同一修訂的清單與對應檔案，並保留雜湊校驗及失敗中止。舊布局分批升級會先儲存暫存檔案目錄，中斷後可繼續讀取原有書籍；正式清單發布後刪除暫存目錄。清單與暫存目錄都無法使用時會停止操作以保護資料。

- 新同步清單使用 **manifest v6**，書籍儲存對應實體協議版本。先在所有參與設備匯出備份，再升級所有客戶端，最後逐台完成同步，避免舊設備同時寫入。
- 舊協議 1–5 會在成功遷移時升級；遇到高於當前支持的協議會停止寫入。舊客戶端的普通同步無法處理 v6。已經發佈的舊版強制推送無法被新客戶端遠程修補，請關閉其同步或先升級，勿對共享 Gist 強制推送。
- 記憶存取時間僅用於本機排序、LRU 和檢索，不參與上傳；修改內容或摘要才產生同步變更。舊記憶首次升級時保留原時間作為內容修改時間。
- 下載、套用或本機資料讀取失敗時，不會將本輪標記為已同步。上傳的每個批次前都會重新檢查遠端 ETag；Gist API 不提供原子條件寫入，同時寫入仍可能發生競爭。

- 術語、角色、別名使用穩定身份及字段邏輯版本；別名改名保留身份。各語言並行修改分別合併，同一字段按確定性邏輯版本裁決，不依賴設備牆上時鐘。
- 刪除整個實體優先於遲到的離線編輯。書內刪除記錄長期保留，即使離線超過 90 天，舊身份也不會復活；刪除角色也阻止其舊別名回流。清空某語言譯名只清空該槽，不刪除實體。
- 刪除段落的某個譯文版本會留下刪除記錄，其他設備上的舊副本同步時不會把它帶回；在原處修改譯文也會推進版本，合併時保留較新的修改。譯文版本的刪除記錄在該段落最後一次變動 90 天後清理，離線更久的設備仍可能帶回舊版本。
- 明確撤銷刪除、備份/修訂覆蓋恢復和強制推送所需的恢復會生成新身份，保留已知刪除記錄，並重建範圍內引用。使用者看到的是恢復快照的內容，後續同步不會讓已刪除的舊身份覆蓋恢復項。
- 完整備份保留書籍目標、所有語言成果與刪除記錄。設備自身的同步身份不會複製到另一設備；把備份遷入新設備不會讓兩台設備共享同一身份。

### 修訂歷史 {#settings-guide-section-27}

啟用且有 Gist ID 時可查看修訂歷史：

- 刷新曆史
- 展開單個修訂查看檔案變更
- 恢復到指定修訂

> 自 v0.11.1 起，從修訂歷史恢復**完整支持** manifest 新佈局：AI 模型、封面歷史、記憶庫都會隨修訂快照一並還原，不再只恢復書籍主體。若修訂來自舊版本聚合佈局，會自動回退到舊解析路徑。

恢復前會建立包含章節正文與譯文的本地備份。若修訂快照的任一必要條目讀取失敗，恢復會整體中止並保留當前資料；若應用階段失敗，回滾也會還原獨立存儲的章節內容，而不只是書籍元資料。

### 刪除 Gist {#settings-guide-section-28}

- 可執行“刪除目前的 Gist”（需確認）。

### 資料恢復與同步覆蓋行為（當前實現） {#settings-guide-section-29}

- **版本修訂級別恢復**：從單次網路修訂版恢復時，會先清空本地書籍、AI 模型、封面歷史，再全量應用遠端備份的資料。
- **本地誤刪軟恢復**：在開啟同步功能且存在雲端備份記錄時，如果本地無意間刪除了資料並在同步前找回，系統通常會彈出“已刪除項同步處理”對話框供選擇。
- **恢復項防止再次刪除**：恢復成功的條目會刷新同步時間並清理對應墓碑，避免下一輪同步把剛恢復的資料再次刪除。
- 此時恢復對話框提供了針對（書籍、模型配置、封面和記憶庫 Memory）的高級恢復交互，不僅能恢複資料，還能覆蓋當前的刪除行為記錄防止從雲端錯誤清除。

## 6) 🧬 本地嵌入 {#settings-guide-section-30}

用於配置**本地向量檢索**，為記憶庫的語義檢索和章節 `query_chapter` 工具提供支持。完整介紹、運行原理與故障排查見獨立文檔：[本地嵌入](/help/local-embedding)。

### 總開關 {#settings-guide-section-31}

- **啟用本地嵌入**（預設關閉）：開啟後會按需下載嵌入模型並在背景生成向量索引。
- 關閉時：嵌入隊列自動停止、相關 UI 隱藏，AI 不再暴露 `query_chapter` 工具，翻譯提示詞也會移除對應引導。
- **移動端強制禁用**：Quasar 檢測到移動平台時會鎖定此開關為關閉，避免瀏覽器 WASM 記憶體限制導致崩潰。

### 嵌入模型與運行後端 {#settings-guide-section-32}

- 預設模型：`hotchpotch/bekko-embedding-v1-a25m`，約 123M 總參數 / 25M 活躍參數，使用 384 維向量、mean pooling 和 L2 歸一化。模型檔案約 190 MiB，詞表 int8 壓縮、Transformer 計算 fp32；首次下載後由瀏覽器 Cache Storage 持久化。
- 執行後端自動選擇：
  - **WebGPU** — 能取得 GPU 介面卡時優先使用。
  - **WASM** — 介面卡不可用時直接使用；兩個後端共用同一預設檔案。
- 模型版本號：`bekko-embedding-v1-a25m@384@mean@raw`。模型 / 維度 / pooling / 輸入方案變化時更新版本號，舊向量作為 stale 在背景重算。
- 僅在啟用後且曾經快取過模型時才會自動預熱，首次開啟需下載模型，請耐心等待。

### 記憶注入 {#settings-guide-section-33}

- 最低相關度閾值：低於此分數的記憶不會被注入翻譯上下文（預設 0.30）。
- 字符預算：單次注入的最大字符數（預設 2000）。
- 可在對應面板查看分數分布和實時測試檢索結果。

### 本地向量索引對話框 {#settings-guide-section-34}

- 展示每本書的章節 / 記憶向量記錄數（已嵌入 / 總數 / stale 三檔）。
- 支持**批量重算**、單書重建、測試查詢對話框（可直接輸入文本查看相似度最高的章節）。
- 嵌入隊列進行中時會顯示進度橫幅，可暫停或繼續；同步進行中時由 sync gate 臨時掛起，結束後自動恢復，不影響使用者主動 pause 的狀態。

## 8) 💾 匯入/匯出 {#settings-guide-section-36}

### 匯出資料 {#settings-guide-section-37}

匯出為本地 JSON 檔案，檔案名格式：

- `tsukuyomi-settings-YYYY-MM-DD.json`

匯出資料包含（當前實現）：

- AI 模型
- 書籍（含章節內容）
- 封面歷史
- Memory
- 同步配置
- 應用設定

### 匯入資料 {#settings-guide-section-38}

- 支持檔案類型：`.json`、`.txt`（內容需為可解析 JSON）。

匯入行為（按當前實現）：

- AI 模型：有資料時先清空再匯入。
- 書籍：有資料時先清空再匯入。
- 封面歷史：有資料時先清空再匯入。
- Memory：按書籍逐條建立（不會先全量清空）。
- 應用設定：執行設定匯入邏輯。
- 同步配置：有資料時覆蓋當前同步配置。

> 匯入不是“按字段精細選擇”的流程；操作前建議先匯出備份。

## 9) ℹ️ 關於（v0.13.0 起） {#settings-guide-section-39}

展示應用基本資訊：

- 應用 Logo 與副標題「月之神官，伴君譯筆」
- 當前版本號（含 build 號）
- 作者鏈接（Rozx）
- GitHub 倉庫鏈接

> 主要用於版本核對與對外引用——不包含可編輯的設定項。

### 桌面版自動更新（v0.16.1 起） {#settings-guide-section-40}

僅在正式桌麵包中顯示；Web 版與開發模式不顯示或顯示「自動更新無法使用」。

- **自動檢查**：啟動 30 秒後檢查一次，之後每六小時檢查一次；發現新的正式版本會自動在背景下載，關於頁顯示目標版本與下載進度。
- **檢查更新**：空閒時可手動檢查（檢查、下載或準備重啟期間按鈕不可用，下載完成後改為「重新啟動並更新」）；檢查失敗會顯示原因，可重試。
- **重新啟動並更新**：下載完成後按鈕變為「重新啟動並更新」，確認後應用退出、安裝新版本並重新啟動。書庫與設定沿用原資料位置。
- **查看發布版本**：跳轉到 GitHub 發佈頁，可手動下載。
- 離開關於頁再回來，會顯示當前的檢查 / 下載狀態，不會重新開始。

安裝只會由使用者確認觸發，普通關閉或下次啟動不會自動安裝。以下情況會拒絕重啟並提示原因，更新包仍保留，稍後可重試：

- 正在翻譯、匯入、同步，或書籍正在執行操作；
- 仍有未完成的儲存；
- 重啟前的儲存檢查期間有新的工作開始（該工作會照常完成並儲存，本次重啟準備失敗）。

> v0.16.0 及更早的桌面版沒有更新模組，需要手動下載一次 v0.16.1。Windows 版改為便攜 ZIP，請保留整個解壓目錄。macOS 版未經 Apple 公證，首次打開被攔截時可在「系統設定 → 隱私與安全」中選擇「仍要打開」。

## ❓ 常見問題 {#settings-guide-section-41}

### Q1：為什麼桌面版看不到“代理設定”？ {#settings-guide-section-42}

A：代理設定分頁只在瀏覽器版顯示。桌面版直接訪問網站，被攔截時由 Firecrawl 備援兜底；網站對應在桌面版同樣可用。

### Q1.1：某個網站總是匯入失敗（例如 403）怎麼辦？ {#settings-guide-section-43}

A：確認「API Keys」中已啟用 Firecrawl 備援。keyless 模式有每日上限，大量匯入時建議配置 Firecrawl API Key，並在「檢查額度」中查看剩餘額度。

### Q2：API Keys 里為什麼沒有 OpenAI / Gemini Key？ {#settings-guide-section-44}

A：模型 API Key 在“AI 列表”中的模型編輯對話框內配置，不在這裡。

### Q3：匯入後資料不符合預期怎麼辦？ {#settings-guide-section-45}

A：先確認匯入檔案結構與內容；建議始終先匯出一份當前本地備份，再執行匯入。

### Q4：同步按鈕可用但下載按鈕灰色？ {#settings-guide-section-46}

A：通常是未填寫 Gist ID，或當前處於同步中。
