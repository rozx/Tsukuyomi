# 外部 Agent 與 MCP 接入指南 {#agent-mcp-guide-section-1}

透過 **外部 Agent 工作台**（`/mcp`），你可以讓 Claude Code、Pi、Antigravity 等本機 Agent 直接操控 Tsukuyomi，使用現有 Agent 訂閱額度完成建立書籍、新增章節、維護設定與分塊翻譯。

## 執行模式 {#agent-mcp-guide-section-2}

### 桌面版：本機 Streamable HTTP MCP 服務端 {#agent-mcp-guide-section-3}

- 僅監聽本機迴路位址 `127.0.0.1`（預設連接埠 `48321`），預設關閉，需要在 `/mcp` 頁面手動開啟。
- 強制驗證 `Authorization: Bearer <token>`、`Host` 與 `Origin`，防止跨站網頁誤存取。
- 同一 `POST /mcp` 端點同時相容 `2026-07-28` 無狀態協定（`server/discover`）與 `2025-03-26` 握手協定（`initialize`）。
- 本機連接埠、Bearer Token、服務開關與權限模式僅儲存在目前裝置，不會同步到 GitHub Gist，也不會包含在匯出備份檔案中。

### 瀏覽器版：WebMCP 本機中繼 {#agent-mcp-guide-section-4}

- 瀏覽器版透過 **WebMCP 本機中繼**（`@mcp-b/webmcp-local-relay`）讓 Claude Code、Cursor 等本機 Agent 使用本頁的工具，不需要開啟瀏覽器的實驗開關。
- 在頁面第一步開啟 WebMCP 後，應用會在本頁註冊目前權限允許的工具（含唯讀的工作流指南 `get_workflow_guide`），並連線到你電腦上執行的中繼。
- 在 Agent 用戶端裡加入中繼：Claude Code 執行 `claude mcp add webmcp-local-relay -- npx -y @mcp-b/webmcp-local-relay@latest --widget-origin <本頁位址>`，其他用戶端把頁面給出的 JSON 合併到 MCP 設定裡。需要 Node.js 22 或更高版本。頁面給出的設定已經填好本頁位址，中繼只接受來自它的連線。
- 開啟後，頁面第一步會顯示是否真的接上了本機中繼：已接上、本機有中繼但本頁沒有接上（多半是中繼的 `--widget-origin` 與本頁位址不一致），或還沒有找到中繼（Agent 用戶端還沒有啟動它）。
- 讓 Agent 呼叫 `webmcp_list_sources`，能看到本頁就表示已連線。工具列表裡看不到本頁工具時，可用 `webmcp_list_tools` 列出、`webmcp_call_tool` 按名稱呼叫。
- 使用期間請保持 Tsukuyomi 的分頁開啟（不必停留在「外部 Agent」頁面，在書籍、設定等任何頁面都一樣）：工具來自這個分頁，關閉或重新整理後 Agent 會暫時看不到它們。
- 中繼比頁面晚啟動，或者 Agent 用戶端重新啟動過時，頁面會在二十秒左右自動重新接上，不需要切回分頁或重新整理。有些用戶端不直接列出 MCP 工具，而是按需載入：Agent 說看不到工具時，先讓它依用戶端的方式尋找，再判斷是不是沒連上。
- 只開一個 Tsukuyomi 分頁：同時開著多個時，Agent 看到的工具名會帶上分頁後綴。
- 頁面給出的設定裡的位址取自你開啟頁面時的位址；換一個位址存取（例如 `localhost` 換成 `127.0.0.1`，或換了網域）後需要重新複製設定。
- 瀏覽器開著舊版的 WebMCP 實驗開關時，應用會在本頁自動改用內建實作；個別情況下無法替換，頁面會提示去 `chrome://flags/#enable-webmcp-testing` 關閉該開關。
- 本頁必須透過 HTTPS 或 localhost 開啟，否則無法開啟。
- 瀏覽器環境因跨網域限制無法抓取部分站點時，可讓 Agent 自行取得正文後呼叫 `create_book` 與 `add_chapters` 直接匯入。

## 權限分級與多版本寫回 {#agent-mcp-guide-section-5}

- **僅唯讀（`read_only`）**：僅開放書庫、章節、術語、角色、記憶查詢，全書搜尋與詞頻統計，分塊上下文拉取，以及讀取你目前的頁面位置和內建使用文件。
- **翻譯與編輯（`translate_and_edit`，預設）**：允許建書、修改書籍資訊、匯入、批次加章、檢查並匯入書籍更新、提交與批次取代譯文，新增、修改和刪除術語/角色/記憶，但禁止刪除書籍。
- **完全控制（`full`）**：額外開放 `delete_book`；切換到該模式時頁面會要求再確認一次。
- **譯文版本策略**：預設以 `append` 追加新譯文版本並設為選中；每種語言每段最多保留 5 個歷史版本，超過上限時會逐出最早版本，因此請避免對同一段落反覆提交不同譯文。Agent 翻譯一章時複核並修正自己剛提交的譯文屬於例外：指南讓它用 `overwrite` 就地改寫那份草稿，不多佔一個版本；潤飾、校對已有譯文仍依預設方式追加新版本。

## 推薦翻譯工作流 {#agent-mcp-guide-section-6}

1. 在 `/mcp` 頁面只需要兩步：開啟服務，然後複製「快速上手指南」並貼給 Agent。
2. 指南開頭的「首次設定」會讓 Agent 替你完成準備：詢問並建立專案資料夾、在其中設定好這個 MCP、把指南的其餘部分保存為該資料夾裡的 AGENTS.md（Claude Code 另建一個引用它的 CLAUDE.md）。之後在這個資料夾裡啟動 Agent 就能直接工作，不用再貼上。指南後面是資料模型、全部工具、分步工作流程、規則與出錯處理；保存下來的部分控制在 23.5 KB 以內，不會被對規則檔有大小上限的用戶端（如 Antigravity 的 24,000 位元組）截斷。桌面版的 MCP 設定裡包含存取權杖，不要把這個資料夾提交到公開儲存庫。想自己在用戶端裡加入 MCP 時，展開頁面上的「手動加入 MCP」。
3. 長篇網頁小說透過 `import_book_from_url` 預設按批抓取最多 20 章，可依回傳的 `pending_chapter_count` 重複呼叫續傳，並透過 `max_chapters` 調整單批章數。
4. 連載中的書籍可用 `check_book_updates` 檢查來源站點的新章節，再用 `apply_book_updates` 匯入。預設只匯入新章節；套用已匯入章節的正文改動（`include_updated`）會清除被改段落的譯文。檢查結果同時附帶本機的翻譯進度（`local_progress`：各狀態的章節數、第一個沒譯完的章節、最新兩章各譯了多少段），你剛手動匯入過新章節時，站點上沒有新章節，Agent 也不會誤報「沒有可譯的章節」。
5. 譯文寫入後會立即更新書庫與閱讀頁面，頁面上的「呼叫活動」會即時顯示每次工具呼叫的參數與回傳結果摘要（重新整理頁面後仍保留，關閉分頁後清空），譯文歷史會顯示對應的外部來源標籤（例如 `MCP · claude-opus-4`）。
6. Agent 能知道你正在看什麼：`get_app_context` 會回傳你所在的頁面、開啟的書和章節、選取的段落及其原文與譯文，以及你在頁面上反白選取的文字。所以可以直接說「潤飾我選取的這一段」。
7. 統一修改譯名時，Agent 會先用 `count_occurrences` 統計舊譯名的出現次數，再用 `replace_in_translations` 預覽並批次取代。依預設的寫回方式，每個改動的段落會追加一個新版本，舊版本仍然保留。全書範圍的搜尋用 `search_paragraphs`（支援正規表示式），翻譯時查前文的譯法可以限定只搜目前章節之前的章節、只看已有譯文的段落，不會被後面還沒翻譯的章節佔滿結果；啟用了本機嵌入時還可以用 `search_chapters` 依內容描述找章節。
8. 可以直接問 Agent「Tsukuyomi 怎麼匯入小說」這類使用問題：它會用 `search_help_docs` 和 `get_help_doc` 查閱本說明文件後回答。
9. `delete_terms`、`delete_characters`、`delete_memories` 用於清理過時或重複的項目。指南要求 Agent 在刪除前先徵得你的同意。
10. 翻譯新章節的第一塊時，Agent 會同時拿到上一章末尾的原文與譯文，以及最近幾章的標題譯名，用來延續語氣、標點習慣和標題格式。
11. 原文把術語或角色名寫錯字（例如同音字）時，這些項目會作為「可能相關」單獨列出並標明原文裡的寫法，由 Agent 確認後使用。站內的翻譯、潤飾、校對也有同樣的提示。
12. Agent 遵守的翻譯規則（標點與引號、保持格式、日語敬語、術語與角色怎麼建、記憶該記什麼）與內建翻譯是同一份，寫在快速上手指南和工作流範本裡。記憶只用來存可重複使用的翻譯決定（稱呼、術語譯法、文風），取翻譯塊時依相關度自動帶出，不用來記劇情；你希望每次都帶上的長期要求請寫進書籍或章節的特殊指令。每章都要遵守的全書規範（標題格式、標點約定、敘事文風）也應寫進書籍層級特殊指令：記憶依與正文的相關度帶出，與劇情無關的格式規則常常取不到，而特殊指令每次取翻譯塊都會帶上。指南會讓 Agent 發現這類規範時用 `update_special_instructions` 的 `mode: "append"` 追加，不覆蓋既有的指令（不傳 `mode` 時整體替換）。有多種常見譯法、需要全書統一的詞（職業、魔物類別、設定高頻詞）則建成術語，依塊帶出，不往特殊指令裡堆詞表；無歧義的日常詞不建術語。
13. 長篇書籍不需要讀整本目錄：`get_book` 只要卷的概覽時也會給出每卷已譯完、譯了一部分、還沒開始的章節數和第一個沒譯完的章節，也可以只取最近幾章或某一卷；要接著翻譯時可以用 `from_first_untranslated` 搭配 `limit`，只取從第一個沒譯完的章節起的幾章（例如「翻譯第 28～33 話」時不必拉整卷）。`list_terms` / `list_characters` 支援分頁和精簡輸出。
14. 搜尋類工具（全書搜尋、詞頻統計、章節段落、術語與角色列表、使用文件）預設精確比對，另有可選的模糊比對：Agent 記不清確切寫法或原文有錯字時可以開啟。批次取代譯文不支援模糊比對，避免改到不該改的文字。
15. 本機的 txt 等文字檔也可以讓 Agent 匯入：它自己讀取檔案，用 `create_book` 建書，再用 `add_chapters` 逐章寫入。分段規則與內建匯入一致——每一行是一個段落，空行和行首縮排原樣保留。
16. `move_chapters` 可以調整章節在卷內的順序，或把章節移到另一卷（也可以新建一卷）；內建的聊天助手也有同名工具。它只改變位置，不改動內文與譯文。
17. `get_translation_chunk` 的一塊有三道上限，誰先到就在哪裡收口：最多 60 段（不計標點不超過 8 個字的短行、純符號行算半段，彈幕式的短行一塊能放下一百多行；Agent 可用 `max_paragraphs` 調整，上限 200）；字元預算預設取書籍的分塊大小，但最多 4000 字原文（`chunk_size` 可另行指定）；整個回應的 JSON 不超過約 9000 位元組（UTF-8，中日文每字 3 位元組；`max_response_bytes` 可調整）。最後這道上限針對 Antigravity 這類把超過 10 KiB 的工具結果存成檔案、要多一輪讀取的用戶端：先放角色、術語、記憶、上一章末尾等上下文，剩下的空間再裝段落，所以命中角色多的第一塊會少幾段，`compact` 的續塊能多裝。取一塊正好對應一次提交和一次複核。一塊之後只剩很少幾段（依配額折算不超過段數上限的四分之一，併入後字數不超過字元預算的 1.25 倍、回應不超過位元組預算 5%）時併入這一塊，章末不會多出一個只有十來段的小尾塊。
18. 回憶、首尾呼應、前後篇裡原樣重複的句子：取翻譯塊時，如果某段原文與本章前文或之前 30 章裡已經譯過的段落完全相同（忽略空白，不計標點至少 10 個字），會把當時的譯法一併帶出，Agent 可以直接沿用。「ええ、もちろんですわ」這類客套話、短應答譯法隨語境變化：不計標點不到 24 個字的短句，前文最近兩處的譯法不同時不會帶出。更早的章節或只是相近的句子需要 Agent 自己用 `search_paragraphs` 查。
19. Agent 的翻譯步驟與內建翻譯相同：先準備（確認術語、角色、記憶與翻譯策略，新術語和新角色這時就建好），再翻譯並提交，最後複核；潤色與校對沒有複核。快速上手指南和工作流程範本裡的步驟是同一份，Agent 不需要兩邊各讀一遍。
20. 快速上手指南開頭寫著對應的應用程式版本。應用程式更新後，Agent 會發現自己儲存的指南版本不一致，並用 `get_quick_start_guide` 取得目前版本、替換儲存的副本，不需要你重新複製。
21. 翻譯塊裡術語與角色的說明合計約 600 字：命中的條目不多時每條最多帶 150 字，條目多時（如群像場面）依條目數收緊，每條至少 40 字；被截短的標明 `description_truncated`，全文可用 `list_terms` / `list_characters` 讀取。譯名、性別、說話風格與別名不截短。不需要說明時可以傳 `include_descriptions: false`。續取後續塊用的 `compact` 省略說明、最近章節標題和第一塊已給過的章節標題、目標語言等資訊，為空的清單（如沒有命中的記憶、近似命中）也不再列出；角色的性別與說話風格仍然帶上，後面才出場的角色也有口吻可依。上一章末尾與最近章節標題只用來對齊語氣和格式，不帶段落和章節的 ID。
22. 「可能相關」的術語與角色（原文寫法略有出入的近似命中）不會從一個更長的片假名詞中間切出一段來比對，名稱的前半後面接著助詞的也不算；不超過 4 個字的純片假名名稱，首字不同時視為另一個詞。
23. 新章節的第一塊帶有 `style_hints`：統計本章與之前 5 章已有譯文（最多 200 段）裡引號（「」 或 “”）、破折號、刪節號、對白句末是否帶句號、數字全半形、空格的寫法。書籍沒寫標點約定時，Agent 照多數的寫法翻譯，不必先逐個搜尋前文確認；特殊指令裡寫明的規範優先。已有譯文不到 10 段時不給出。
24. `upsert_terms` / `upsert_characters` 按補丁更新：只傳 ID（或原名）和要改的欄位，沒傳的欄位保留原值，例如只補說話風格不會抹掉說明；空字串表示清空說明或說話風格。新建條目時原名和譯名都要給。`aliases` 整體替換別名清單；只想補一個別名時用 `append_aliases`，同名的別名改寫譯名，其餘別名保留。
