# 🧬 本地嵌入（Local Embedding） {#local-embedding-section-1}

本地嵌入是 Tsukuyomi 的**離線語意檢索引擎**：完全在瀏覽器內執行嵌入模型，把記憶與章節內容映射成向量，讓 AI 能依語意而不是關鍵詞找到相關上下文。向量計算在本機完成，不消耗 AI API 額度。向量屬於**裝置本機狀態**：Gist 同步只上傳記憶內容，不上傳向量，每台裝置各自產生；實際傳送給 AI 的上下文仍依模型請求傳送，詳見本文隱私說明。

> 本指南面向想瞭解或排查本地嵌入功能的使用者。設定入口請見[設定說明](/help/settings-guide#settings-guide-section-30)，記憶相關用法見[記憶管理](/help/book-details-memory)。

---

## 1. 它能做什麼 {#local-embedding-section-2}

啟用本地嵌入後，系統會在背景為以下資料建立向量索引：

- **記憶庫**：每條記憶的「摘要 + 內容」依段落和句末標點切成 ≤1200 字的短段分別嵌入，再做多分段穩健聚合，避免長記憶被截斷後語意漂移。翻譯時三訊號評分中的「語意相似度」分量（嵌入可用時權重 0.85）由此提供；AI 也能呼叫 `search_memories` 工具以自然語言搜尋記憶。
- **章節內容**：每章依段落（目標 100 字/chunk）和「標題 + 首段」拆成多個 chunk 分別嵌入，AI 透過 `query_chapter` 工具以自然語言找到相關段落，無需依賴預先產生的章節摘要。

章節語意向量統一編碼原文，避免已譯與未譯章節的語言差異影響排名；原文缺失時使用目標譯文。關鍵字、預覽和全文索引保留原文與目前目標的選用譯文。快取依目標語言及實際輸入簽章校驗，譯文變化也會更新關鍵字與預覽。切換目標後，失效快取會在背景重建；舊目標的遲到計算不會覆蓋新快取，未完成時可能顯示重建狀態。術語、角色和別名檢索只擴展原名與本次目標譯名，缺譯名不借用其他語言。記憶內容與記憶向量跨目標共用，不因目標切換清空。

模糊情節查詢會對少量候選的原文段落進行本機重排，避免關鍵情節被前後文稀釋。已有明確符合的查詢保留整塊上下文，重複查詢重用向量快取；重排計算失敗時保留原排名。整個過程在瀏覽器內完成，不增加 AI API 請求。

未啟用時：

- 三訊號評分自動退化為關鍵詞 + 時間衰減（權重 0.75 / 0.25，仍然有效，但語意層面的「意義相近但措辭不同」會漏召）。
- AI 不再提供 `query_chapter` 工具，翻譯提示詞也會移除對應引導。
- 「向量索引」入口隱藏，已開啟的面板關閉。

## 2. 模型與執行方式 {#local-embedding-section-3}

### 預設嵌入模型 {#local-embedding-section-4}

- **模型**：`hotchpotch/bekko-embedding-v1-a25m`（Bekko a25m 多語言編碼器）。
- **架構**：約 123M 總參數、25M 活躍參數，支援中 / 日 / 英等 100+ 語言。
- **維度**：使用完整的 **384 維**向量，並做 L2 正規化。
- **Pooling**：mean pooling — 對有效 token 的表徵求平均。query 與 document 共用同一編碼路徑，不加任務前綴。
- **預設檔案**：官方 `onnx/model.onnx`，約 **190 MiB**；靜態詞表已做 int8 壓縮，Transformer 計算保持 fp32。`dtype: fp32` 選擇這個已壓縮檔案，不表示下載完整 fp32 詞表。
- **模型版本號**：`bekko-embedding-v1-a25m@384@mean@raw`。模型 ID、維度、pooling 或輸入方案變化都會更新版本號，舊記憶與章節向量會被判定為 stale，需要重新計算（見第 5 節）。

> **從 GTE 升級**：先前使用 GTE 模型的使用者需要重新下載 Bekko 模型，既有向量全部需要重建。模型下載完成前，記憶評分使用關鍵詞 + 時間衰減；模型就緒後，尚未重建向量的舊記憶在關鍵詞強命中（原始置信度 ≥ 0.8）時逐條改用關鍵詞 + 時間衰減評分，仍可被自動注入或被 `search_memories` 找到；只部分命中的不會被召回。章節語意搜尋在重建前暫時無法使用。開啟書籍詳情頁會自動重建該書向量，建議升級後盡快完成重建。

### 執行後端 {#local-embedding-section-5}

模型載入、分詞與推理都在獨立瀏覽器 Web Worker 中執行，不佔用頁面主執行緒，下載或推理期間介面不會卡頓；整個過程仍完全在本機完成，不需要伺服器。WASM 在 Worker 內使用單執行緒，無需跨來源隔離。Worker 內優先檢查是否能取得 WebGPU 介面卡並建立裝置；不可用時直接使用 WASM；WebGPU 初始化失敗時也會自動回落到 WASM。兩個後端共用同一份預設模型檔案。

| 後端       | 檔案與計算                              | 大小     | 適用情境                          |
| :--------- | :-------------------------------------- | :------- | :-------------------------------- |
| **WebGPU** | 預設 ONNX，詞表 int8 / Transformer fp32 | ~190 MiB | 支援 WebGPU 的桌面瀏覽器          |
| **WASM**   | 同一預設 ONNX 檔案                      | ~190 MiB | WebGPU 介面卡或裝置不可用的瀏覽器 |

> 介面卡不可用時，本次工作階段使用 WASM；在設定中點選「重新載入」會重新檢查 WebGPU。實際推理速度取決於裝置、輸入長度和執行後端。

### 行動裝置強制停用 {#local-embedding-section-6}

Quasar 偵測到實體行動裝置時會**鎖定**「啟用本地嵌入」開關為關閉：「本機嵌入」設定頁仍然可見，但開關呈灰色無法操作，並顯示不支援的原因。原因是瀏覽器 WASM 的記憶體上限（一般 ~2GB）在模型載入與多 chunk 推理時極易觸發當機。行動裝置依然能正常使用關鍵詞比對 + 時間衰減訊號。由於向量不隨同步上傳，桌面端產生的向量也不會出現在手機上。

此判斷只看裝置類型，不看視窗寬度：桌面瀏覽器縮窄視窗不會被當成行動裝置。

## 3. 啟用步驟 {#local-embedding-section-7}

1. 進入 **設定 → 本機嵌入**。
2. 開啟「啟用本地嵌入」總開關。若瀏覽器尚未快取模型，會**直接開始下載**（約 190 MiB，WebGPU 與 WASM 相同），不會跳出確認視窗；之後若狀態為「未載入」，也可點選「下載模型」手動開始。**下載需要穩定網路，請保持視窗在前景。**
3. 下載期間設定卡片內顯示「模型載入進度」及百分比，下方提示目前階段：「正在準備模型檔案…」→「正在下載模型檔案…」→「正在初始化模型…」。
4. 下載完成後模型會被瀏覽器 Cache Storage 持久保存，**之後啟動會自動預熱，無需再次下載**。
5. 狀態變為「已就緒」後，便可進入下一步。
6. 開啟任意書籍，點選「向量索引」入口（見第 4 節），查看或依需要補建本書的章節 / 記憶向量。

關於進度顯示：

- 百分比只統計 `.onnx` 權重檔案的下載位元組，設定檔、分詞器等小檔案完成不會讓進度虛高。
- 權重總大小未知時進度條顯示為不確定狀態（來回捲動），取得大小後切換為百分比。
- 下載階段最多顯示到 95%，剩餘部分留給模型初始化；初始化完成後進度區塊收起，狀態變為「已就緒」。
- 進度不會倒退：自動重試或 WebGPU 回落到 WASM 時，進度條沿用已顯示的數值。
- 關閉再重新開啟設定頁時，會恢復目前的載入進度。

## 4. 向量索引面板 {#local-embedding-section-8}

「向量索引」入口只在**書籍詳情頁**、且本地嵌入有效啟用時顯示；關閉本地嵌入或在實體行動裝置上時入口隱藏。入口位置隨版面變化：

- 桌面版面：右側工具列。
- 平板版面：右側側軌。
- 窄螢幕版面：頂部工具列。

入口依本地嵌入是否有效啟用顯示，不以版面斷點判斷，桌面瀏覽器縮窄視窗仍可使用。點選後，桌面和平板版面開啟右側抽屜，手機版面開啟與助手、翻譯進度一致的底部抽屜。已開啟的面板在版面切換時保留；切換到另一本書時自動關閉。

面板標題為「本機向量索引」，副標題「瀏覽器本機執行」，下方顯示目前書名和章節數。

### 狀態徽章與統計 {#local-embedding-section-9}

- **狀態徽章**：標題列右側顯示 就緒 / 模型載入中 / 載入失敗 / 未就緒 / 已停用。
- **「章節向量」**：顯示「已嵌入 X / Y」（X 為目前模型版本已嵌入的章節數）、進度條，以及「待處理：N」（嵌入佇列中等待處理的章節數；佇列為全域共用，可能包含其他書籍的任務）。
- **「記憶向量」**：同樣顯示「已嵌入 X / Y」、進度條和「待處理：N」。
- **底部狀態區**：顯示模型版本號、執行後端（WebGPU 或「WASM（慢）」）和目前狀態。

存在 stale 向量（版本不符）時，面板頂部顯示「Embedding 空間已升級」橫幅，列出舊版章節與記憶數量，並提供「立即重建」按鈕。stale 向量不計入「已嵌入」，因此升級後數字可能明顯回落。

> stale 項目**不會**在所有書籍中自動重算：只有在模型就緒時開啟某本書的詳情頁（或詳情頁開啟期間模型載入完成），才會自動把本書缺失和 stale 的章節 / 記憶加入佇列。其他書籍請開啟後自動觸發，或在面板中點選「立即重建」/「補齊缺失」。

### 操作 {#local-embedding-section-10}

- **章節**：「補齊缺失」把本書未嵌入或 stale 的章節加入佇列；「全部重算」把本書所有章節重新加入佇列計算。
- **記憶**：「補齊缺失」把本書未嵌入或 stale 的記憶加入佇列。
- **「立即重建」**：僅在 stale 橫幅中出現，一次把本書 stale 的章節和記憶加入佇列。
- 以上按鈕只在模型「就緒」且佇列閒置時可用，避免與進行中的重建衝突。
- **「測試向量查詢」**：開啟查詢對話框（見下文）。
- **「暫停」/「恢復」**：只在佇列執行中或已暫停時出現在底部狀態區，用於手動暫停或繼續佇列。

**測試向量查詢對話框**：頂部說明「以自然語言描述劇情、人物關係或關鍵詞，檢索本書章節與記憶。」輸入查詢語句後點選「查詢章節」或「查詢記憶」（Enter 預設執行章節查詢；記憶查詢僅比對目前模型版本的項目）。

- 尚未查詢時顯示「尋找書中的情節與記憶」提示。
- 查詢中顯示「正在檢索章節…」或「正在檢索記憶…」載入狀態。
- 結果依相關度排序，每條顯示排名序號和相關度分數（滑鼠懸停提示「相關度」）；點選章節結果跳至對應章節，點選記憶結果查看詳情。
- 便於調整參數或排查「為什麼這條記憶沒被注入」。

### 進度與目前任務 {#local-embedding-section-11}

佇列執行時，進度直接顯示在各分區內，面板頂部沒有單獨的橫幅：

- 「章節向量」與「記憶向量」各自顯示「待處理：N」，有待處理項目時同時顯示 ETA（依最近 5 個批次的平均耗時估算）。
- 目前任務卡片顯示佇列正在處理的內容：處理本書時顯示「本書 {類型} ×{數量}」；處理其他書籍時以醒目顏色顯示「其他書籍 · {類型} ×{數量}」並附上該書**書名**，即使你在另一本書的面板裡也能看到佇列在忙哪本書。

背景記憶與章節推理每組最多 4 條輸入，並依長度拆組，降低長短文字混合時的計算開銷；前台查詢與段落重排每組最多 8 條，優先於等待中的背景任務。背景批次之間會留出計算空檔，因此整書重算可能更慢，以減少 CPU / GPU 持續佔用。章節在批次之間回應暫停；未完成的章節保留在佇列，繼續後重新計算，完成整章後再統一儲存。面板關閉時暫停統計讀取，開啟後合併同批更新。

## 5. 模型版本與 stale 重算 {#local-embedding-section-12}

`MODEL_ID + 截取維度 + pooling 方案 + 輸入方案`一起構成「embedding 空間身份」。任意一項變化，舊向量與新向量就落在不同空間，餘弦相似度會退化成雜訊，必須重算。

應用程式透過 `MODEL_VERSION` 常數記錄目前空間身份，每條已嵌入的記憶 / chunk 都會同時儲存這個版本號。檢索與統計邏輯會呼叫統一的 `isMemoryEmbeddingStale` / `isChapterChunkStale` 判斷版本是否相符：

- 相符（current）：參與語意檢索 / 計入「已嵌入」。
- 不相符（stale）：跳過語意評分，並在補齊掃描時進入重算佇列。模型就緒時其他記憶仍按語意模式評分；stale 項目（以及尚未產生向量的新記憶）關鍵詞原始置信度 ≥ 0.8 時逐條改用關鍵詞 0.75 + 時間衰減 0.25，否則只剩語意模式下的小權重，達不到注入門檻。

**這表示升級模型不會遺失資料**：舊項目與記憶內容都會保留，重建完成前只有關鍵詞強命中的記憶能被檢索與注入；重建後回到完整能力。

啟用本地嵌入時，應用程式啟動會清理瀏覽器 Cache Storage 中的**歷史模型殘留**（如 `embeddinggemma`、`qwen3-embedding`），回收磁碟空間。舊 GTE 模型的快取（約 340–465 MB）目前**刻意保留**，暫不自動刪除；如需回收空間，可在瀏覽器中清除本網站資料（之後需要重新下載目前的模型）。

## 6. 同步期間的 sync gate {#local-embedding-section-13}

雲端同步與修訂還原期間，嵌入佇列會被一道**專用閘門**暫時掛起：

- `isSyncing` 或 `isRestoringSyncSnapshot` 任一為 true，閘門鎖住佇列。
- 閘門解鎖後**只**恢復「由閘門自身掛起」的任務 — 使用者在 UI 上主動點選的「暫停」狀態完整保留，不會被同步流程意外解除。
- 這避免了同步過程中嵌入寫入與 `overwriteFromSnapshot` 的覆蓋競態，也防止還原一半的資料上再疊上半新的向量。

UI 表現：面板沒有專門的同步提示；同步期間佇列處於暫停，底部狀態區顯示「恢復」按鈕，但按鈕無法使用，避免在同步過程中寫入向量。同步結束後佇列自動繼續，無需手動點選；如果在同步期間點選了「暫停」，同步結束後佇列保持暫停。

## 7. 疑難排解 {#local-embedding-section-14}

### 進度卡在 0% {#local-embedding-section-15}

- **檢查網路**：模型託管在 Hugging Face CDN，若網路無法連線會進入自動重試（遞增延遲 3s / 8s / 20s，最多 3 次）。可在瀏覽器開發者工具的 Network 面板查看具體請求。
- **代理 / 反向代理**：企業網路 / VPN 可能攔截 CDN，可在「代理設定」（僅 Web 端）嘗試切換，或在瀏覽器層面設定允許清單。
- **磁碟空間**：模型約 190 MiB，請為瀏覽器 Cache Storage 預留至少約 250 MB 可用空間（另有少量設定檔與向量資料），磁碟空間不足時下載會中途失敗。

### 狀態停在「載入失敗」 {#local-embedding-section-16}

- 查看瀏覽器主控台 `[EmbeddingService]` 前綴的錯誤紀錄，常見原因：
  - WebGPU 驅動程式不相容 → 應用程式會自動回落到 WASM；如果連 WASM 也失敗，多半是瀏覽器記憶體不足。
  - 首次載入時切走分頁太久導致逾時 → 重新開啟應用程式即可（模型快取命中後第二次啟動很快）。
- 在 **設定 → 本機嵌入** 中，失敗狀態下點選「重試」，就緒狀態下點選「重新載入」，都會釋放舊模型並重新檢查 WebGPU。向量索引面板中沒有重新載入按鈕。Worker 當機或請求逾時後，未完成任務保留在佇列；模型恢復後繼續，已儲存的章節快取不會被半成品覆蓋。

### 檢索結果品質不佳 {#local-embedding-section-17}

- 用「測試向量查詢」對話框直接輸入查詢語句，看回傳結果是否合理。
- 如果某條記憶/章節「明明應該被找到」卻沒出現，確認它是否為 stale（面板頂部有「Embedding 空間已升級」橫幅時）：先點選「立即重建」或「補齊缺失」，再測試。
- 中日英混合查詢：模型原生多語言，直接輸入純淨查詢即可（v0.14.3 起不再為 query 端加上任何前綴）。

### 已停用但提示「嵌入佇列還在跑」 {#local-embedding-section-18}

通常是關閉總開關時正在處理某批次。目前批次完成後佇列自然停止，強制中斷會丟棄這一批結果。關閉後「向量索引」入口立即隱藏；尚未處理的項目保留在佇列中，重新啟用後自動繼續。

---

## 8. 隱私與離線性 {#local-embedding-section-19}

- 嵌入模型推理在瀏覽器 Worker 內執行，不呼叫外部嵌入 API。
- 模型本身一次性下載到 Cache Storage，之後離線啟動也能使用。
- Gist 同步會上傳記憶內容，但**上傳前會剝離記憶向量與模型版本標記**（詳見 [設定說明 → 資料同步](/help/settings-guide#settings-guide-section-19)）。向量只儲存在本機 IndexedDB 中，每台啟用本地嵌入的裝置各自產生；**Tsukuyomi 不持有任何中轉伺服器**。
