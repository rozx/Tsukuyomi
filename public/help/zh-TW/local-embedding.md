# 🧬 本地嵌入（Local Embedding） {#local-embedding-section-1}

本地嵌入是 Tsukuyomi 的**離線語義檢索引擎**：完全在瀏覽器內運行嵌入模型，把記憶與章節內容映射成向量，讓 AI 能按語義而不是關鍵詞找到相關上下文。向量計算在本機完成，不消耗 AI API 額度。啟用 Gist 同步後，記憶及其向量會隨記憶條目上傳；實際發送給 AI 的上下文仍按模型請求發送，詳見本文隱私說明。

> 本指南面向想瞭解或排查本地嵌入功能的使用者。設定入口請見[設定說明](/help/settings-guide#settings-guide-section-30)，記憶相關用法見[記憶管理](/help/book-details-memory)。

---

## 1. 它能做什麼 {#local-embedding-section-2}

啟用本地嵌入後，系統會在背景為以下資料建立向量索引：

- **記憶庫**：每條記憶的"摘要 + 內容"按段落和句末標點切成 ≤1200 字的短段分別嵌入，再做多分段穩健聚合，避免長記憶被截斷後語義漂移。翻譯時三信號評分中的「語義相似度」分量（嵌入可用時權重 0.85）由此提供；AI 也能調用 `search_memories` 工具按自然語言搜索記憶。
- **章節內容**：每章按段落（目標 100 字/chunk）和「標題 + 首段」拆成多個 chunk 分別嵌入，AI 通過 `query_chapter` 工具按自然語言找到相關段落，無需依賴預先生成的章節摘要。

章節向量、標題片段和全文索引按目標語言及實際輸入簽名校驗，只包含原文與該目標的選用譯文。切換目標後，失效快取會在背景重建；舊目標的遲到計算不會覆蓋新快取，未完成時可能顯示重建狀態。術語、角色和別名檢索只擴展原名與本次目標譯名，缺譯名不借用其他語言。記憶內容與記憶向量跨目標共享，不因目標切換清空。

未啟用時：

- 三信號評分自動退化為關鍵詞 + 時間衰減（權重 0.75 / 0.25，仍然有效，但語義層面的"意義相近但措辭不同"會漏召）。
- AI 不再暴露 `query_chapter` 工具，翻譯提示詞也會移除對應引導。
- 批量嵌入面板會以"未啟用"狀態展示，所有寫入操作鎖定。

## 2. 模型與運行方式 {#local-embedding-section-3}

### 預設嵌入模型 {#local-embedding-section-4}

- **模型**：`onnx-community/gte-multilingual-base`（基於阿里達摩院 GTE-Multilingual-Base 的 ONNX 版本）。
- **架構**：305M 參數 BERT encoder，多語言原生支持（覆蓋中 / 日 / 英等 70+ 語言）。
- **維度**：使用完整的 **768 維**向量，並做 L2 歸一化。
- **Pooling**：CLS pooling — 取 encoder 末層首個 token（CLS）作為句向量，與官方示例一致。query 與 document 共用同一編碼路徑，不再使用非對稱前綴。
- **檢索方案**：對稱編碼 — query 與 document 都直接編碼原文，模型多語言能力在原始文本上即可發揮。本應用已在 service 層固定，使用者無需關心。
- **模型版本號**：`gte-multilingual-base@768@cls@raw`。**模型 ID + 維度 + pooling + 輸入方案任一變化都會 bump 這個版本號**，舊版本的 chunk / memory 會被自動判定為 stale 並重算（見下文）。

### 運行後端 {#local-embedding-section-5}

應用啟動時會按下列優先級選擇運行後端：

| 後端       | 量化                            | 體積   | 推理速度   | 適用場景                                           |
| :--------- | :------------------------------ | :----- | :--------- | :------------------------------------------------- |
| **WebGPU** | q4f16（4-bit 權重 + fp16 激活） | ~465MB | 快 5-10×   | Chrome / Edge 桌面端，啟用 GPU 的較新設備          |
| **WASM**   | int8（8-bit 量化）              | ~340MB | 兼容性最好 | 不支持 WebGPU 的瀏覽器，或 WebGPU 初始化失敗時回落 |

> WebGPU 初始化失敗一次後，本會話內永久回落到 WASM（避免每次重試都再觸發驅動不兼容的探測）。手動觸發「重新載入」按鈕會清空黑名單，可在升級了顯卡驅動 / 啟用了瀏覽器 flag 後重新嘗試 WebGPU。

### 移動端強制禁用 {#local-embedding-section-6}

Quasar 檢測到移動平台時會**鎖定**「啟用本地嵌入」開關為關閉，並在 UI 上灰顯。原因是瀏覽器 WASM 的記憶體上限（一般 ~2GB）在 300MB+ 模型 + 多 chunk 推理時極易觸發崩潰。移動端依然能正常使用關鍵詞匹配 + 時間衰減信號。

## 3. 啟用步驟 {#local-embedding-section-7}

1. 進入 **設定 → 本地嵌入**（移動端不可見）。
2. 打開「啟用本地嵌入」總開關。
3. 系統彈出模型下載提示，開始首次下載（**需要穩定網路，請保留視窗在前景**；下載體積取決於運行後端，見上表）。
4. 下載完成後模型會被瀏覽器 Cache Storage 持久化，**之後啟動會自動預熱，無需再次下載**。
5. 進度橫幅消失、狀態徽章變為 `ready` 後，便可進入下一步。
6. 打開任意書籍，點選右欄圖標軌道里的「批量嵌入」入口（v0.12.1 起從頂部工具欄遷移到此），按需觸發本書的章節 / 記憶向量化。

## 4. 批量嵌入面板 {#local-embedding-section-8}

進入書籍詳情頁後，右欄圖標軌道會出現「批量嵌入」入口（書籍詳情頁之外不顯示）。點選展開抽屜式面板，可在此查看與控制嵌入隊列。

### 狀態徽章與統計 {#local-embedding-section-9}

- **嵌入服務狀態**：`idle` / `loading` / `ready` / `failed`，並顯示當前運行後端（`webgpu` 或 `wasm`）。
- **本書章節**：已嵌入 / 總數 / stale（版本不匹配，待重算）。
- **本書記憶**：已嵌入 / 總數 / stale。

> "stale" 計數非零時通常意味著模型版本最近做了升級（例如從 EmbeddingGemma 切到 gte-multilingual-base），所有舊版本 chunk 都會被判定為 stale 自動進入重算隊列，期間統計可能短暫回落。

### 操作 {#local-embedding-section-10}

- **重新嵌入本書章節** / **重新嵌入本書記憶**：把所有未嵌入或 stale 的條目入隊。
- **批量重算**（設定對話框）：跨書籍觸發全部 stale 條目重算。
- **測試查詢**：直接輸入任意自然語言查詢，立刻看到相似度最高的 N 條章節 / 記憶，相似度分數實時顯示，便於調參或排查"為什麼這條記憶沒被注入"。
- **暫停 / 繼續**：暫停按鈕直接掛起隊列；同步進行中時面板會顯示「同步期間已暫停」提示，結束後自動恢復（詳見第 6 節 sync gate）。

### 進度橫幅 {#local-embedding-section-11}

隊列活躍時面板頂部顯示進度條，包含：

- 已完成 / 總數（按 `memory` 與 `chapter` 分別拆分）。
- ETA：基於最近 5 個批次的平均耗時估算。
- 當前批次正在處理的書籍 ID（即便你切換到另一本書的面板，也能看到隊列在哪兒忙）。

記憶按 `BATCH_SIZE = 8` 合批一次 `embedBatch`；章節按章為單位，每章內部多個 chunk 一次推理（章節通常較長，獨立成批避免記憶體峰值）。

## 5. 模型版本與 stale 重算 {#local-embedding-section-12}

`MODEL_ID + 截取維度 + pooling 方案 + 輸入方案`一起構成「embedding 空間身份」。任意一項變化，舊向量與新向量就落在不同空間，余弦相似度會退化成噪聲，必須重算。

應用通過 `MODEL_VERSION` 常量記錄當前空間身份，每條已嵌入的記憶 / chunk 都會同時存這個版本號。檢索與統計邏輯會調用統一的 `isMemoryEmbeddingStale` / `isChapterChunkStale` 判斷版本是否匹配：

- 匹配（current）：參與語義檢索 / 計入"已嵌入"。
- 不匹配（stale）：跳過語義評分（自動降級到關鍵詞 + 時間衰減），並被 backlog 掃描進入重算隊列。

**這意味著升級模型不會丟資料**：舊條目仍能被檢索，只是暫時降級使用，等隊列處理完會自動回到完整能力。

應用還會在啟動時清理瀏覽器 Cache Storage 中的**歷史模型殘留**（如 `embeddinggemma`、`qwen3-embedding`），回收磁盤空間。

## 6. 同步期間的 sync gate {#local-embedding-section-13}

雲同步與修訂恢復期間，嵌入隊列會被一道**專用閘門**臨時掛起：

- `isSyncing` 或 `isRestoringSyncSnapshot` 任一為 true，閘門鎖住隊列。
- 閘門解鎖後**只**恢復"由閘門自身掛起"的任務 — 使用者在 UI 上主動點選的「暫停」狀態完整保留，不會被同步流程意外解除。
- 這避免了同步過程中嵌入寫入與 `overwriteFromSnapshot` 的覆蓋競態，也防止恢復一半的資料上面再疊上半新的向量。

UI 表現：同步期間面板會顯示「同步進行中，嵌入已暫停」橫幅，`isSyncing` 結束後自動消失。

## 7. 故障排查 {#local-embedding-section-14}

### 進度卡在 0% {#local-embedding-section-15}

- **檢查網路**：模型托管在 Hugging Face CDN，若網路不可達會進入自動重試（遞增延遲 3s / 8s / 20s，最多 3 次）。可在瀏覽器開發者工具的 Network 面板看具體請求。
- **代理 / 反代**：企業網路 / VPN 可能攔截 CDN，可在「代理設定」（僅 Web 端）嘗試切換或在瀏覽器層面配置允許列表。
- **磁盤空間**：瀏覽器 Cache Storage 通常需要 500MB 以上空間，磁盤緊張時下載會中途失敗。

### 狀態停在 `failed` {#local-embedding-section-16}

- 查看瀏覽器控制台 `[EmbeddingService]` 前綴的錯誤紀錄，常見原因：
  - WebGPU 驅動不兼容 → 應用會自動回落到 WASM；如果連 WASM 也失敗，多半是瀏覽器記憶體不足。
  - 首次載入時切走標籤頁太久導致超時 → 重新打開應用即可（模型快取命中後第二次啟動很快）。
- 在批量嵌入面板點選「重新載入」按鈕會清空 WebGPU 黑名單並強制重新初始化。

### 檢索結果質量不佳 {#local-embedding-section-17}

- 用「測試查詢」對話框直接輸入查詢語句，看返回 Top-N 是否合理。
- 如果某條記憶/章節"明明應該被找到"卻沒出現，確認它的狀態是否為 stale：先重新嵌入再測試。
- 中日英混合查詢：模型原生多語言，直接輸入純淨查詢即可（v0.14.3 起不再為 query 端添加任何前綴）。

### 已禁用但提示"嵌入隊列還在跑" {#local-embedding-section-18}

通常是關閉總開關時正在處理某批次。隊列會在當前批次完成後自然停止，強制中斷會丟棄這一批結果。等待幾秒進度橫幅會自動消失。

---

## 8. 隱私與離線性 {#local-embedding-section-19}

- 嵌入模型推理在瀏覽器內執行，不調用外部嵌入 API。
- 模型本身一次性下載到 Cache Storage，之後離線啟動也能用。
- Gist 同步會把記憶向量作為記憶條目的一部分上傳到你的私有 Gist（詳見 [設定說明 → 資料同步](/help/settings-guide#settings-guide-section-19)），**Tsukuyomi 不持有任何中轉服務器**。
