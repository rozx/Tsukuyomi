# 🤖 AI 模型配置指南 {#ai-models-guide-section-1}

本文檔說明當前版本中 AI 模型頁面與模型對話框的真實功能。

---

## 📋 頁面能力 {#ai-models-guide-section-2}

### 桌面版 {#ai-models-guide-section-3}

**AI 模型工作臺** 由三部分組成：

- **頂部**：搜索框（名稱 / 提供商 / 模型 ID / 預設任務）與「新增 AI 模型」按鈕，下方是模型數量統計。
- **模型列表**：按提供商（OpenAI / Google Gemini）分組，組標題顯示模型數與已啟用數。每張模型卡片可 **複製**（副本預設禁用）、**編輯**、**刪除**（確認後執行，支持撤銷）。
- **任務路由**：為翻譯（初譯）、校對 / 潤色、術語翻譯、AI 助手分別選擇預設模型，設定會隨匯入匯出一起儲存。

### 手機版 {#ai-models-guide-section-4}

- 頂部為「AI 模型」標題與「添加」按鈕。
- 尚未配置模型時顯示引導卡片：「新增 AI 模型」按鈕和「兩步開始使用」說明（添加模型連線 → 選擇預設任務）。
- **我的模型**：按提供商分組，顯示模型數和已啟用數，點選模型即可編輯。
- **任務預設模型**：點選任務行，從底部彈出的列表中選擇模型，也可選擇「未設定」讓該任務不使用預設模型。
- 模型對話框在手機上以底部抽屜形式打開，字段與桌面版一致。

---

## 🏢 當前支持的提供商 {#ai-models-guide-section-5}

系統內置提供商僅有：

- `OpenAI`（OpenAI 兼容介面）
- `Gemini`（Google Gemini）

兩者都通過 Vercel AI SDK 接入：OpenAI 走 `@ai-sdk/openai-compatible`，Gemini 走 `@ai-sdk/google`。

> 說明：DeepSeek、Moonshot、OpenRouter、Ollama 等 OpenAI 兼容服務，請選擇 `OpenAI` 並填寫對應的 `baseUrl` 與模型 ID。基礎位址只寫到域名時會自動補上 `/v1`；如服務的路徑不同，請填寫完整路徑。

---

## ➕ 添加模型 {#ai-models-guide-section-6}

點選「新增 AI 模型」後，在對話框中填寫：

1. **啟用模型**（開關）
2. **使用 CORS 代理**（開關，僅瀏覽器模式顯示，見下文）
3. **模型名稱**（必填）
4. **溫度**（0~2）
5. **提供商**（OpenAI / Gemini）
6. **API Key**（必填）
7. **基礎位址**：
   - OpenAI：必填
   - Gemini：不顯示，使用 Google 官方地址
8. **模型標識**（必填，可從列表選，也可直接輸入）
9. **思考等級**（可選，見下文）
10. **模型資料**：上下文視窗與最大輸出 Token
11. **自定義請求頭**（可選）
12. **預設任務**

當 API Key（及 OpenAI 的 baseUrl）滿足條件後，會自動拉取可用模型列表，也可點選「重新整理列表」手動刷新。模型標識框支持直接輸入列表裡沒有的型號，包括用輸入法輸入。

關閉對話框時如有未儲存的修改，會提示「繼續編輯」或「捨棄變更並關閉」。

## ⚙️ 模型資料與可用性 {#ai-models-guide-section-7}

**取得模型資料** 只查詢隨應用打包的 [models.dev](https://models.dev) 目錄，離線也可使用，不發送模型生成請求，也不需要 API Key。未收錄的型號會提示手動填寫，已有數值保持不變。

- **上下文視窗**：模型可接受的輸入上限，0 表示未設定。
- **最大輸出 Token**：單次響應上限，0 表示未設定。
- 目錄值標記為 models.dev 來源；手動編輯後標記為手動，手動值優先用於運行時預算。
- 常見的思考等級後綴（例如 `gpt-6-sol(high)`）只在目錄匹配時忽略，實際請求仍保留原始模型標識。
- 舊版本通過「詢問模型自身」獲得的數值，如果目錄里有該型號，運行時會以目錄為準；想固定使用自己的數值，手動編輯一次即可。

上下文視窗決定 AI 助手與匯入助手何時壓縮對話：上下文接近視窗時自動壓縮較早的對話；未設定時不會主動壓縮，只在服務返回「上下文超限」後恢復一次。詳見 [AI 助手](./chat-assistant-guide.md)。

**測試可用性** 使用當前尚未儲存的地址、密鑰、請求頭、代理和思考等級發送一條簡短請求，顯示成功/失敗及耗時。需要先填寫模型標識、API Key（OpenAI 還需基礎位址）。測試最多等待 30 秒，會產生少量 API 用量，不修改模型資料或自動儲存配置。編輯表單或關閉對話框會取消測試，舊結果不會用於新的配置。

## 🧠 思考等級 {#ai-models-guide-section-8}

可選擇預設（跟隨模型）、關閉 / 最低、極低、低、中、高、極高。預設不覆蓋廠商設定；舊模型沒有此字段時沿用預設行為。更高等級通常增加回應時間與 Token 消耗，各型號支持的等級可能不同，可用「測試可用性」驗證當前組合。

設定會隨模型儲存、匯入匯出和同步，並用於助手、翻譯、潤色、校對、術語及上下文摘要。OpenAI 兼容介面使用 reasoning effort，Gemini 由 SDK 按型號轉換成思考等級或預算。

## 🌐 網路與代理設定 {#ai-models-guide-section-9}

以下設定對 OpenAI 與 Gemini 都生效，包括模型列表、生成請求和可用性測試。

### CORS 代理開關 {#ai-models-guide-section-10}

每個模型可獨立控制是否使用 CORS 代理：

- **使用 CORS 代理**（預設開啟）：API 請求通過 CORS 代理服務器轉發。
- 關閉後請求將直連模型服務，適用於：
  - 本地部署的 AI 服務（如 Ollama）
  - 已配置好跨域策略的自建服務
  - 不需要代理的 API 端點
- 此開關僅在瀏覽器模式下生效，Electron 桌面版始終直連。

### 自定義 HTTP 請求頭 {#ai-models-guide-section-11}

每個模型可配置自定義 HTTP 請求頭（Header），用於：

- 額外的身份認證（如 Bearer Token、自定義認證頭）
- API 網關路由標記
- 特殊服務配置參數

操作方式：

- 點選「新增 Header」按鈕新增一組鍵值對
- 每組包含 **Header 名稱** 和 **Header 值**
- 可添加多組自定義請求頭，名稱為空的行不會儲存
- 點選刪除按鈕移除不需要的請求頭

## 🎯 預設任務設定 {#ai-models-guide-section-12}

每個模型可獨立勾選是否用於以下任務，並可為每項單獨設定溫度：

- 翻譯
- 校對/潤飾（同一任務項）
- 術語翻譯
- 助手

> 這些「可用於任務」的開關會影響該模型是否出現在對應任務的預設模型選擇中。實際使用哪個模型，由頁面上的 **任務路由**（手機版為「任務預設模型」）決定。

---

## 📚 書籍級模型覆蓋 {#ai-models-guide-section-13}

AI 模型頁配置的是全域預設模型。對於需要不同文風、能力或成本策略的單本書，可在 **書籍詳情頁 → SETTINGS → 翻譯設定** 中分別覆蓋：

- 翻譯模型
- 校對 / 潤飾模型

模型解析優先級為：**有效且已啟用的本書覆蓋 → 對應任務的全域預設模型**。如果覆蓋模型被禁用或刪除，任務會靜默回退全域預設，不會中斷；書籍設定頁仍會顯示失效佔位，方便重新選擇。

本書覆蓋不作用於術語翻譯、聊天助手和解釋任務。完整操作說明見 [AI 翻譯功能](/help/book-details-translation#book-details-translation-section-18)。

## 🔍 搜索與展示細節 {#ai-models-guide-section-14}

搜索框會實時過濾以下內容：

- 模型名稱
- 提供商（OpenAI / Gemini）
- 模型 ID
- 預設任務文案

桌面版模型卡片會顯示：

- 提供商與模型 ID
- 啟用狀態（已啟用/已禁用）
- 溫度、上下文視窗、最大輸出
- 脫敏 API Key（僅顯示前綴）
- 基礎位址
- 預設任務匯總

API Key 以明文儲存在本設備（IndexedDB）。需要注意：

- 開啟 CORS 代理時，請求（含 API Key）會經代理服務器轉發給模型服務。
- 開啟 GitHub Gist 同步後，API Key 會隨 AI 模型配置一起上傳到你的 Gist。詳見 [設定說明](./settings-guide.md) 的同步部分。

## 💡 使用建議（基於當前實現） {#ai-models-guide-section-15}

1. 至少配置一個「助手」預設模型，否則右側聊天助手無法發送訊息。
2. 新增模型後先點「取得模型資料」補齊上下文視窗，再點「測試可用性」確認連線，然後儲存。
3. 為「翻譯」和「校對/潤飾」分別配置不同溫度，便於穩定性與表達效果平衡。
4. 複製模型後先在副本上調參測試（例如換一個思考等級），確認效果後再啟用。
5. 定期清理不再使用的模型，避免任務模型選擇列表過長。

## ❓ 常見問題 {#ai-models-guide-section-16}

**Q: 為什麼 Gemini 不需要基礎位址？**

A: Gemini 預設使用 Google 官方地址，對話框中會隱藏 baseUrl 輸入。自定義請求頭和 CORS 代理開關對 Gemini 同樣生效。

**Q: 點「取得模型資料」提示目錄暫無記錄？**

A: 該型號不在內置的 models.dev 目錄中（常見於自建服務或新發佈的型號）。請參照服務商文檔手動填寫上下文視窗與最大輸出 Token；已有數值不會被清空。

**Q: 「測試可用性」失敗了怎麼辦？**

A: 先核對基礎位址、API Key 和模型標識；瀏覽器模式下可嘗試切換 CORS 代理開關；如果報錯與思考參數有關，把思考等級改回「預設」再測試。

**Q: 複製的模型為什麼不能直接用？**

A: 複製模型預設是「已停用」，需要進入編輯後啟用。

**Q: 助手發送按鈕是灰色的？**

A: 通常是未配置「助手預設模型」或當前無可用助手模型。

**Q: 刪除後能恢復嗎？**

A: 可以，在成功通知出現期間點選「復原」可恢復。
