# 记忆管理

记忆管理功能帮助您记录书籍的关键信息、剧情要点和重要设定，为 AI 翻译提供更丰富的上下文，确保翻译的连贯性和准确性。

## 🧠 什么是记忆

记忆是关于书籍的重要信息片段，用于存储 AI 记忆的大块内容，如背景设定、章节摘要等。

**记忆的用途**：

- 🌍 记录世界观设定和规则
- 📖 保存重要的剧情发展
- 💡 存储关键的背景信息
- ⚠️ 记录翻译时需要注意的事项

## 📋 记忆的结构

每条记忆包含以下信息：

**核心内容**：

- 📝 **内容**: 记忆的详细内容（必填）
- 🤖 **摘要**: AI 自动生成的内容摘要

**元数据**：

- 📅 **创建时间**: 记忆创建的时间
- 🕘 **最后访问时间**: 用于时间衰减评分
- 🧬 **语义向量**: 本地嵌入模型生成的多维向量（用于语义检索）

## 🚪 访问记忆管理面板

**操作步骤**：

1. 📑 在书籍详情页的左侧边栏
2. ⚙️ 找到"设置菜单"区域
3. 🖱️ 点击"记忆管理"按钮
4. 📋 右侧会显示记忆管理面板

**面板布局**：

- 🛠️ **顶部工具栏**: 添加记忆、搜索、筛选（仅未向量化）、重新向量化、导入/导出
- 📊 **进度横幅**: 嵌入队列活跃时显示向量化进度和暂停/继续按钮
- 📇 **记忆列表**: 显示所有记忆的卡片（每张卡片右上角有向量状态徽章）
- 📄 **记忆详情**: 点击记忆查看和编辑详细内容

## 添加记忆

### 手动添加

**操作步骤**：

1. 在记忆管理面板
2. 点击"添加记忆"按钮
3. 在弹出的对话框中填写：
   - **摘要**: 记忆的简短描述（必填，用于 AI 检索）
   - **内容**: 记忆的详细内容（必填）
4. 点击"保存"按钮

**填写建议**：

- **内容详细**: 提供足够的细节帮助 AI 理解
- **一个概念一条记忆**: 每条记忆应该是一个完整的概念
- **长度适中**: 建议控制在 200-500 字

### 记忆内容示例

**世界观设定**：

```
本世界的魔法分为五大元素：火、水、风、土、雷。
每个魔法师只能掌握其中一种元素。
魔法的强度与魔法师的精神力成正比。
```

**剧情要点**：

```
主角在第15章发现自己是失踪多年的王子。
这个秘密只有老管家知道，他一直在暗中保护主角。
```

**翻译注意事项**：

```
本作中"夜明け"不翻译为"黎明"，而应翻译为"曙光"，
因为作者在后记中解释这个词有特殊的象征意义。
```

## 编辑记忆

### 修改记忆内容

**操作步骤**：

1. 在记忆列表中找到要编辑的记忆
2. 点击记忆卡片
3. 在弹出的对话框中修改信息
4. 点击"保存"按钮

**可修改内容**：

- 记忆的内容
- 随时补充和完善记忆

### 更新记忆

**随剧情更新**：

- 新信息揭露时更新内容
- 伏笔实现后添加注释
- 设定扩展时补充细节

## 导入与导出

### 导出记忆

- 点击工具栏的"导出"按钮
- 将当前记忆库导出为 JSON 文件

### 导入记忆

- 点击工具栏的"导入"按钮
- 选择 JSON 格式的记忆文件
- 系统会自动合并新旧记忆

## 删除记忆

**操作步骤**：

1. 在记忆列表中找到要删除的记忆
2. 点击记忆卡片旁的"删除"按钮
3. 在确认对话框中确认删除

**删除影响**：

- 删除后不可恢复
- AI 翻译时不再参考该记忆
- 建议删除前确认不再需要

## 三信号智能检索

翻译时系统自动从记忆库中选择最相关的记忆注入 AI 上下文，无需手动关联。

### 评分公式

每条记忆的相关度得分（0 ~ 1.0）由三个信号加权计算：

| 信号 | 权重 | 说明 |
|:-----|:-----|:-----|
| **语义相似度** | 0.6 | 记忆向量与当前翻译内容的余弦相似度（需启用语义检索） |
| **关键词匹配** | 0.3 | 当前章节中出现的术语/角色名在记忆文本中的命中比例 |
| **时间衰减** | 0.1 | 最近访问的记忆得分更高（30 天半衰期指数衰减） |

### 字符预算

系统按得分从高到低贪心填充，直到达到字符预算上限（默认 2000 字符）。低于最低相关度阈值（默认 0.38）的记忆不会被选中。

### 语义检索

在**设置 → 本地嵌入**中开启"启用本地嵌入"后，系统会使用本地嵌入模型（默认 `gte-multilingual-base`，约 300MB+，多语种支持）为每条记忆生成语义向量。这使得 AI 能够理解记忆的语义含义，而不仅仅是关键词匹配。

- **首次启用需下载模型**，之后浏览器缓存自动复用；仅在曾缓存时才会自动预热。
- **完全本地运行**，不消耗 API 额度；优先使用 WebGPU，回退到 WASM。
- **移动端强制禁用**本地嵌入（浏览器 WASM 内存限制），但关键词匹配和时间衰减信号仍然生效。
- 即使不启用本地嵌入，关键词匹配和时间衰减信号仍会工作，系统会自动使用**退化评分权重**保证记忆依然有参考价值。

## 记忆搜索与筛选

### 混合搜索

在记忆面板顶部的搜索框中输入查询文本，系统会同时使用关键词匹配和语义相似度（启用语义检索时）对记忆进行排序，返回最相关的结果。

**搜索范围**: 记忆内容 + 摘要

### 筛选功能

- **仅显示未向量化**: 筛选出尚未生成语义向量的记忆，便于检查向量化覆盖情况
- **清除筛选**: 一键清除搜索词和筛选条件

## 记忆在翻译中的应用

### 自动注入

翻译时，系统自动完成以下流程：

1. **提取实体**: 扫描当前翻译文本中出现的术语和角色名
2. **三信号打分**: 对所有记忆计算语义相似度 + 关键词命中率 + 时间衰减
3. **字符预算填充**: 按得分从高到低选择记忆，直到达到字符预算上限
4. **注入上下文**: 将选中的记忆作为 `【相关记忆】` 注入 AI 翻译提示词

### 预览参考记忆

在书籍详情页的工具栏中，点击"参考记忆"按钮可以预览当前章节会使用哪些记忆，以及每条记忆的三信号得分。预览结果会在切换章节时自动更新。

### AI 工具搜索

AI 在翻译过程中也可以主动调用 `search_memories` 工具，用自然语言查询搜索记忆库。搜索同样使用关键词 + 语义混合检索。

## 最佳实践

### 建立记忆库的时机

**推荐流程**：

1. **阅读第一章后**: 记录基本世界观设定
2. **每完成一卷**: 总结重要剧情和设定
3. **翻译前**: 完善关键记忆
4. **翻译中**: 遇到重要信息及时记录

### 记忆的粒度

**避免过细**：

- 不要记录每个细节
- 专注于真正重要的信息
- 一条记忆应该是一个完整的概念

**避免过粗**：

- 不要把太多信息塞在一条记忆中
- 不同主题应该分开记录
- 便于后续查找和使用

**推荐粒度**：

- 一条记忆 = 一个设定/事件/概念
- 长度控制在 200-500 字
- 包含必要的细节，去除无关信息

### 记忆的更新

**定期审核**：

- 每完成一卷审核一次
- 删除过时或无用的记忆
- 补充新的重要信息
- 合并重复的记忆

**保持准确**：

- 及时更新过期信息
- 修正错误的理解
- 补充遗漏的细节

### 记忆与其他功能的配合

**与术语库配合**：

- 术语库记录名词的翻译 → 翻译时自动作为关键词匹配信号
- 记忆库解释名词的含义和背景 → 当术语名出现在记忆摘要/内容中时自动关联

**与角色设定配合**：

- 角色设定记录人物的基本信息 → 角色名和别名自动作为关键词匹配信号
- 记忆库记录角色的关键经历和发展

**分工建议**：

- 基本信息 → 术语库、角色设定
- 背景故事、剧情要点 → 记忆库
- 翻译规范、注意事项 → 术语库、记忆库

## 常见问题

### 记忆太多会影响性能吗？

- 系统通过字符预算和相关度阈值控制每次注入的记忆数量
- 单本书最多 500 条记忆
- 全量记忆有 60 秒缓存，不会频繁读取数据库
- 语义向量化在后台异步执行，不阻塞翻译

### 如何组织大量记忆？

1. 保持每条记忆的独立性（一个概念一条记忆）
2. 使用混合搜索快速查找
3. 定期整理和归档
4. 利用"仅显示未向量化"筛选检查覆盖情况

### 记忆和章节向量索引有什么区别？

- **章节向量索引**（自动）：启用本地嵌入后，系统会为每个章节的段落以及"章节标题 + 首段"建立多向量索引，AI 可通过 `query_chapter` 工具按自然语言搜索章节内容，用作即时上下文。
- **记忆库**（手动）：您手动录入的跨章节重要信息（世界观、伏笔、翻译注意事项等），由 AI 通过 `search_memories` 工具检索或通过三信号评分自动注入翻译。

建议：

- 章节向量索引用于获取"书内其他章节中的相关段落"。
- 记忆库用于记录长期、概括性、跨章节的信息，它们不适合通过检索原文获得。

### 如何决定什么信息值得记录？

询问自己以下问题：

1. 这个信息在后续章节会被引用吗？
2. 理解这个信息对翻译有帮助吗？
3. 这是一个容易忘记但重要的细节吗？
4. AI 可能会误解或翻译错误吗？

如果任何一个问题的答案是"是"，就值得记录。
