# ⚙️ 设置使用指南 {#settings-guide-section-1}

本文档仅说明当前版本已实现的设置能力，按设置页的选项卡组织。

> 自 v0.10.1 起，设置从弹窗改为独立路由页 `/settings`。在桌面/平板端会显示返回按钮，在移动端则整合进底部 Tab 栏。

---

## 📌 打开与关闭 {#settings-guide-section-2}

- 入口：左侧导航栏 **设置** 或直接访问 `/settings`。
- 关闭/返回：点击页面左上角的返回按钮返回上一页。
- 设置页会记住你上次打开的选项卡。

## 🌐 通用设置 {#settings-guide-general}

**界面语言**可选择简体中文、繁體中文或 English。无已保存偏好时匹配系统首选语言：繁体脚本及台港澳用繁中，简体脚本、中国大陆和新加坡用简中，英语地区用英文，其他语言回退简中。

手动选择会保留到下次启动，并参与应用设置同步；收到同步偏好后界面即时更新。界面切换不会翻译历史消息、用户指令、角色描述、记忆或历史更新日志，也不会自动翻译小说。

新书在真正创建时以当时的界面语言初始化目标。已有书籍请在 **书籍详情 → 设置 → 翻译设置** 修改目标，界面切换不会改变它。正在运行的 AI 任务使用启动时的语言；新执行才采用新设置。

## 2) 🌐 代理设置（仅浏览器版） {#settings-guide-section-7}

用于配置浏览器版访问网页与 AI 服务时使用的 CORS 代理。

### 基础开关 {#settings-guide-section-8}

- **启用代理**：开启后，爬虫和网络工具会优先走代理。

> 旧版的「自动切换代理服务」已移除：请求失败时不再依次尝试列表中的其他代理，而是由 Firecrawl 回退兜底（见「API Keys」与「网站映射」）。

### 默认代理与代理 URL {#settings-guide-section-9}

- 可从“选择代理服务”下拉中选择（默认 CORS Tsukuyomi）。
- 代理 URL 支持模板：`...{url}`。
- 当选择了列表中的代理服务时，URL 输入框会被锁定为对应项。

### 代理列表管理 {#settings-guide-section-10}

- 添加代理（名称、URL、可选描述）
- 编辑代理
- 删除代理
- 测试代理（测试目标为 `https://www.duckduckgo.com`）
- 拖拽排序

列表中的其他代理只会在你把它设为默认代理，或写入某个网站的映射时使用。

### 重要说明 {#settings-guide-section-11}

- 该选项卡只在非 Electron 环境显示。
- 即使关闭代理，浏览器版对部分内置站点仍会走应用内 `/api/...` 路径。
- 浏览器版 AI 模型请求使用独立的默认 CORS 代理逻辑，不受此处“代理 URL”直接控制。

## 3) 🗺️ 网站映射 {#settings-guide-section-12}

为特定网站指定抓取方式，按顺序优先使用。浏览器版与桌面版都会显示。

### 抓取顺序 {#settings-guide-section-13}

1. 网站映射的第一项是 **Firecrawl**（且已启用 Firecrawl 回退）时，直接经 Firecrawl 抓取。
2. 否则先按映射中的 CORS 代理依次尝试（没有映射时使用默认代理）；关闭代理时走 `/api/...` 或直接访问；桌面版始终直接访问。网络错误、超时、429、5xx 会稍后重试一次。
3. 仍被拦截（403、429、5xx、网络错误，或返回了 Cloudflare 等反爬验证页）且已启用 Firecrawl 回退时，改由 Firecrawl 抓取。404 等“页面不存在”不会回退。

### 自动添加映射 {#settings-guide-section-14}

- **仅 Firecrawl 可用时自动添加映射**：网站只能经 Firecrawl 抓取成功时，自动把 Firecrawl 置顶写入该网站的映射，之后直接使用 Firecrawl，不再先尝试代理。
- 该开关依赖「API Keys」中的 Firecrawl 回退总开关。
- 自动写入不会弹出提示；如果网站恢复了代理访问，可在映射中移除 Firecrawl 或调整顺序。

### 映射管理 {#settings-guide-section-15}

- 输入网站域名或网址，选择 CORS 代理或 **Firecrawl** 后添加。
- 每个网站最多 **3** 项，可在编辑弹窗中调整顺序、启用/禁用。
- 桌面版直接访问网站，映射中的 CORS 代理条目显示为不生效，只有 Firecrawl 条目生效。

## 4) 🔑 API Keys {#settings-guide-section-16}

### Tavily 搜索 API Key {#settings-guide-section-17}

- 用于 AI 网络搜索与网页读取（助手聊天、导入元信息，以及翻译 / 润色 / 校对任务）。
- 点击“保存”后写入本地设置；清空后保存可移除该 Key。

### Firecrawl {#settings-guide-section-18}

- **启用 Firecrawl 回退**（默认开启）：网页抓取被拦截时改由 Firecrawl 抓取；同时在未配置 Tavily（或 Tavily 出错）时，为助手聊天与导入提供网络搜索 / 网页读取。开启后，被访问页面的网址与搜索内容会发送给 Firecrawl。
- **API Key（可选）**：未配置时使用 keyless 免费模式，按 IP 有每日请求数与额度上限（具体数值未公开）。
- 保存 Key 时会先查询额度验证，Key 无效时不会保存。
- **检查额度**：显示剩余额度 / 套餐额度与账期结束日（需要已保存 Key）。
- 额度用尽时，正在进行的批量导入 / 更新检查会停止，已获取的章节会保留；稍后或补充额度后可继续。

## 5) 🔄 同步设置（GitHub Gist） {#settings-guide-section-19}

用于配置并执行 Gist 同步。

### 基础配置 {#settings-guide-section-20}

- 启用 Gist 同步
- GitHub 用户名
- GitHub Personal Access Token
- Gist ID（可选，留空可在上传时创建）

> ⚠️ **同步内容包含 API Key**：AI 模型的 API Key、Tavily API Key 与 Firecrawl API Key 会以明文随配置上传到 Gist。应用创建的 Gist 为 secret（不公开列出），但任何拿到链接的人都能查看，请勿分享 Gist 链接。GitHub Token 本身不会上传。如不希望密钥离开本设备，请不要开启 Gist 同步。

### 操作按钮 {#settings-guide-section-21}

- **验证 Token**
- **上传到 Gist**
- **从 Gist 下载**（未填 Gist ID 时不可用）

### 自动同步 {#settings-guide-section-22}

- 可启用“自动同步”。
- 同步间隔范围：**1~1440 分钟**。
- 自动同步会先用条件请求检查远端是否有变化。远端无变化时不消耗 GitHub API 配额，可以放心设置较短的同步间隔。

### 增量同步与并发冲突处理 {#settings-guide-section-23}

从 v0.10.1 起，同步采用基于 **manifest（清单）** 的增量策略：

- **只上传变化的内容**：编辑一本书后触发同步，仅该书与清单文件会被上传；其他书籍、AI 模型、封面、记忆库都不会被重复推送。
- **选择性下载**：远端有更新时，只反序列化并合并发生变化的条目，未变更的数据不会被重新处理。
- **多设备并发保护**：上传前会再次检查远端是否被其他设备修改。如发现并发写入，自动重新拉取合并后重试（最多 3 次）。超过后会提示“其他设备正在频繁写入，请稍后再试”。
- **跨设备智能配对**：同一在线章节即使在不同设备生成了不同本地 ID，也会优先按来源 `webUrl` 配对；卷在 ID 不一致时会按原文标题回退匹配并保留已有译名，减少重复卷与重复章节。
- **同步快照边界**：同步以本地数据打包前的快照时刻为边界。上传期间继续产生的编辑会保留到下一轮同步，不会被误判为已经上传或被远端删除。
- **失败条目重试**：单条下载、解析或应用失败时，不会把该条目标记为已同步；下轮会重新拉取，避免陈旧本地副本覆盖远端新数据。
- **删除跨端传播**：manifest 中保留墓碑（tombstones）记录，在 A 设备上删除的条目不会被 B 设备重新推回。
- **头部待同步提示**：Header 会显示当前待同步变更的数量，点击同步按钮旁的小 Popover 可以查看每一项的具体修改。徽标覆盖书籍、AI 模型、封面、应用设置、**记忆库条目**以及跨端删除墓碑（自 v0.11.1 起补齐记忆变更）。

> 超过 300 个文件时，GitHub API 可能只返回部分文件列表。应用会读取同一修订版本的同步清单，补齐未列出的同步文件，并继续增量同步；清单或升级时保存的临时目录不可用时会安全中止。

### 章节原文与译文合并 {#settings-guide-section-24}

从 v0.16.0 起，每台设备会在成功同步后记录章节的段落结构基准，区分原文修改和新增译文：

- **只有一端改了结构**：已有同步基准时，采用该端的段落顺序与原文。另一端即使刚完成翻译，也不会因此把已删除的段落带回。
- **译文合并**：只有原文完全一致的段落才合并双方译文；段落 ID 相同但原文不同，不会把旧原文的译文套到新原文上。
- **语言隔离**：原文相同时，段落版本及各语言选用分别合并，标题与术语、角色、别名译名的语言槽也分别保存；清空一个语言槽不删除其他语言。旧数据没有语言标记时归为简中。
- **两端都改了结构**：以较新的章节为主，追加另一端独有的段落，并在同步结束后列出有冲突的书籍和章节，请检查合并结果。
- **尚无基准**：沿用原有规则，以较新章节为主并追加另一端独有的段落。升级后完成成功同步，才会逐步建立基准；基准只存在当前设备，不上传到 Gist。

### 🔐 同步凭据安全 {#settings-guide-section-25}

- GitHub Personal Access Token 只保留在当前设备。
- 首次上传、增量上传与强制推送都会从同步包中剥离 Token，不会把凭据写入 Gist。
- 即使首次上传在创建 Gist 后的验证阶段失败，应用也会保存已创建的 Gist ID，重试时不会继续创建孤儿 Gist。

### 🧹 强制推送模式（Force Push） {#settings-guide-section-26}

用于"远端数据损坏"或"设备迁移"场景，把远端清空后用本地数据**完全覆盖**：

- 位置：同步设置 → 强制推送开关（默认关闭）。
- 启用后下一次上传以本地可见内容为准整体重写 Gist；仍须读取并验证远端协议及实体删除元数据，读取失败或发现未来协议时不上传。
- 操作具有破坏性，请务必先在接收设备备份，并确保其他设备暂不触发自动同步。

> 💡 **多设备用户注意**：Manifest 架构涉及 Gist 文件结构调整。建议在所有已登录同一账户的设备上同步升级客户端后再触发同步。首次从旧布局同步时会自动执行一次性迁移（读取旧布局 → 合并本地数据 → 以新布局重写 Gist），迁移失败时本地数据保持不变，下次同步会自动重试。

### 多语言协议与实体删除 {#settings-guide-language-sync}

- 书籍目录与正文分开存储，正文按章节 ID 固定分为最多 16 个小组，空组不占文件。新增一章通常上传所在小组、目录和清单；仅修改正文时，未变化的目录也会跳过。小组过大时仍会分块，插入或重排章节不会让其他组重新分配。
- 首次升级到 v6 会完整迁移旧书籍，此次上传量仍可能较大。迁移中断后保留旧版正文，下一次同步可重试。历史恢复会重组全部正文组，任一所需组缺失或损坏都会中止恢复。
- 300 是 GitHub API 文件列表的返回上限，不是书库容量上限。超过该数量仍可同步；客户端下载同一修订的清单及对应文件，并保留哈希校验和失败中止。旧布局分批升级会先保存临时文件目录，中断后可继续读取原有书籍；正式清单发布后删除临时目录。清单和临时目录都不可用时会停止操作以保护数据。

- 新同步清单使用 **manifest v6**，书籍保存对应实体协议版本。先在所有参与设备导出备份，再升级所有客户端，最后逐台完成同步，避免旧设备同时写入。
- 旧协议 1–5 会在成功迁移时升级；遇到高于当前支持的协议会停止写入。旧客户端的普通同步无法处理 v6。已经发布的旧版强制推送无法被新客户端远程修补，请关闭其同步或先升级，勿对共享 Gist 强制推送。
- 记忆的访问时间仅用于本设备的排序、LRU 和检索，不参与上传；修改内容或摘要才产生同步变更。旧记忆首次升级时保留原时间作为内容修改时间。
- 下载、应用或本地数据读取失败时，不会把本轮标记为已同步。上传的每个批次前都会重新检查远端 ETag；Gist API 不提供原子条件写入，同时写入仍可能发生竞争。

- 术语、角色、别名使用稳定身份及字段逻辑版本；别名改名保留身份。各语言并发修改分别合并，同一字段按确定性逻辑版本裁决，不依赖设备墙上时钟。
- 删除整个实体优先于迟到的离线编辑。书内删除记录长期保留，即使离线超过 90 天，旧身份也不会复活；删除角色也阻止其旧别名回流。清空某语言译名只清空该槽，不删除实体。
- 删除段落的某个译文版本会留下删除记录，其他设备上的旧副本同步时不会把它带回；在原处修改译文也会推进版本，合并时保留较新的修改。译文版本的删除记录在该段落最后一次变动 90 天后清理，离线更久的设备仍可能带回旧版本。
- 明确撤销删除、备份/修订覆盖恢复和强制推送所需的恢复会生成新身份，保留已知删除记录，并重建范围内引用。用户看到的是恢复快照的内容，后续同步不会让已删除的旧身份覆盖恢复项。
- 完整备份保留书籍目标、所有语言成果与删除记录。设备自身的同步身份不会复制到另一设备；把备份迁入新设备不会让两台设备共享同一身份。

### 修订历史 {#settings-guide-section-27}

启用且有 Gist ID 时可查看修订历史：

- 刷新历史
- 展开单个修订查看文件变更
- 恢复到指定修订

> 自 v0.11.1 起，从修订历史恢复**完整支持** manifest 新布局：AI 模型、封面历史、记忆库都会随修订快照一并还原，不再只恢复书籍主体。若修订来自旧版本聚合布局，会自动回退到旧解析路径。

恢复前会创建包含章节正文与译文的本地备份。若修订快照的任一必要条目读取失败，恢复会整体中止并保留当前数据；若应用阶段失败，回滚也会还原独立存储的章节内容，而不只是书籍元数据。

### 删除 Gist {#settings-guide-section-28}

- 可执行“删除当前 Gist”（需确认）。

### 数据恢复与同步覆盖行为（当前实现） {#settings-guide-section-29}

- **版本修订级别恢复**：从单次网络修订版恢复时，会先清空本地书籍、AI 模型、封面历史，再全量应用远端备份的数据。
- **本地误删软恢复**：在开启同步功能且存在云端备份记录时，如果本地无意间删除了数据并在同步前找回，系统通常会弹出“已删除项同步处理”对话框供选择。
- **恢复项防止再次删除**：恢复成功的条目会刷新同步时间并清理对应墓碑，避免下一轮同步把刚恢复的数据再次删除。
- 此时恢复对话框提供了针对（书籍、模型配置、封面和记忆库 Memory）的高级恢复交互，不仅能恢复数据，还能覆盖当前的删除行为记录防止从云端错误清除。

## 6) 🧬 本地嵌入 {#settings-guide-section-30}

用于配置**本地向量检索**，为记忆库的语义检索和章节 `query_chapter` 工具提供支持。完整介绍、运行原理与故障排查见独立文档：[本地嵌入](/help/local-embedding)。

### 总开关 {#settings-guide-section-31}

- **启用本地嵌入**（默认关闭）：开启后会按需下载嵌入模型并在后台生成向量索引。
- 关闭时：嵌入队列自动停止、相关 UI 隐藏，AI 不再暴露 `query_chapter` 工具，翻译提示词也会移除对应引导。
- **移动端强制禁用**：Quasar 检测到移动平台时会锁定此开关为关闭，避免浏览器 WASM 内存限制导致崩溃。

### 嵌入模型与运行后端 {#settings-guide-section-32}

- 默认模型：`hotchpotch/bekko-embedding-v1-a25m`，约 123M 总参数 / 25M 活跃参数，使用 384 维向量、mean pooling 和 L2 归一化。模型文件约 190 MiB，词表 int8 压缩、Transformer 计算 fp32；首次下载后由浏览器 Cache Storage 持久化。
- 运行后端自动选择：
  - **WebGPU** — 能取得 GPU 适配器时优先使用。
  - **WASM** — 适配器不可用时直接使用；两个后端共用同一默认文件。
- 模型版本号：`bekko-embedding-v1-a25m@384@mean@raw`。模型 / 维度 / pooling / 输入方案变化时更新版本号，旧向量作为 stale 在后台重算。
- 仅在启用后且曾经缓存过模型时才会自动预热，首次开启需下载模型，请耐心等待。

### 记忆注入 {#settings-guide-section-33}

- 最低相关度阈值：低于此分数的记忆不会被注入翻译上下文（默认 0.30）。
- 字符预算：单次注入的最大字符数（默认 2000）。
- 可在对应面板查看分数分布和实时测试检索结果。

### 本地向量索引弹窗 {#settings-guide-section-34}

- 展示每本书的章节 / 记忆向量记录数（已嵌入 / 总数 / stale 三档）。
- 支持**批量重算**、单书重建、测试查询对话框（可直接输入文本查看相似度最高的章节）。
- 嵌入队列进行中时会显示进度横幅，可暂停或继续；同步进行中时由 sync gate 临时挂起，结束后自动恢复，不影响用户主动 pause 的状态。

## 8) 💾 导入/导出 {#settings-guide-section-36}

### 导出资料 {#settings-guide-section-37}

导出为本地 JSON 文件，文件名格式：

- `tsukuyomi-settings-YYYY-MM-DD.json`

导出数据包含（当前实现）：

- AI 模型
- 书籍（含章节内容）
- 封面历史
- Memory
- 同步配置
- 应用设置

### 导入资料 {#settings-guide-section-38}

- 支持文件类型：`.json`、`.txt`（内容需为可解析 JSON）。

导入行为（按当前实现）：

- AI 模型：有数据时先清空再导入。
- 书籍：有数据时先清空再导入。
- 封面历史：有数据时先清空再导入。
- Memory：按书籍逐条创建（不会先全量清空）。
- 应用设置：执行设置导入逻辑。
- 同步配置：有数据时覆盖当前同步配置。

> 导入不是“按字段精细选择”的流程；操作前建议先导出备份。

> 主要用于版本核对与对外引用——不包含可编辑的设置项。

### 桌面版自动更新（v0.16.1 起） {#settings-guide-section-40}

仅在正式桌面包中显示；Web 版与开发模式不显示或显示「自动更新不可用」。

- **自动检查**：启动 30 秒后检查一次，之后每六小时检查一次；发现新的正式版本会自动在后台下载，关于页显示目标版本与下载进度。
- **检查更新**：空闲时可手动检查（检查、下载或准备重启期间按钮不可用，下载完成后改为「重启并更新」）；检查失败会显示原因，可重试。
- **重启并更新**：下载完成后按钮变为「重启并更新」，确认后应用退出、安装新版本并重新启动。书库与设置沿用原数据位置。
- **查看发布版本**：跳转到 GitHub 发布页，可手动下载。
- 离开关于页再回来，会显示当前的检查 / 下载状态，不会重新开始。

安装只会由用户确认触发，普通关闭或下次启动不会自动安装。以下情况会拒绝重启并提示原因，更新包仍保留，稍后可重试：

- 正在翻译、导入、同步，或书籍正在执行操作；
- 仍有未完成的保存；
- 重启前的保存检查期间有新的工作开始（该工作会照常完成并保存，本次重启准备失败）。

> v0.16.0 及更早的桌面版没有更新模块，需要手动下载一次 v0.16.1。Windows 版改为便携 ZIP，请保留整个解压目录。macOS 版未经 Apple 公证，首次打开被拦截时可在「系统设置 → 隐私与安全」中选择「仍要打开」。

## ❓ 常见问题 {#settings-guide-section-41}

### Q1：为什么桌面版看不到“代理设置”？ {#settings-guide-section-42}

A：代理设置选项卡只在浏览器版显示。桌面版直接访问网站，被拦截时由 Firecrawl 回退兜底；网站映射在桌面版同样可用。

### Q1.1：某个网站总是导入失败（例如 403）怎么办？ {#settings-guide-section-43}

A：确认「API Keys」中已启用 Firecrawl 回退。keyless 模式有每日上限，大量导入时建议配置 Firecrawl API Key，并在「检查额度」中查看剩余额度。

### Q2：API Keys 里为什么没有 OpenAI / Gemini Key？ {#settings-guide-section-44}

A：模型 API Key 在“AI 列表”中的模型编辑弹窗内配置，不在这里。

### Q3：导入后数据不符合预期怎么办？ {#settings-guide-section-45}

A：先确认导入文件结构与内容；建议始终先导出一份当前本地备份，再执行导入。

### Q4：同步按钮可用但下载按钮灰色？ {#settings-guide-section-46}

A：通常是未填写 Gist ID，或当前处于同步中。
