# 🧬 本地嵌入（Local Embedding） {#local-embedding-section-1}

本地嵌入是 Tsukuyomi 的**离线语义检索引擎**：完全在浏览器内运行嵌入模型，把记忆与章节内容映射成向量，让 AI 能按语义而不是关键词找到相关上下文。向量计算在本机完成，不消耗 AI API 额度。启用 Gist 同步后，记忆及其向量会随记忆条目上传；实际发送给 AI 的上下文仍按模型请求发送，详见本文隐私说明。

> 本指南面向想了解或排查本地嵌入功能的用户。设置入口请见[设置说明](/help/settings-guide#settings-guide-section-30)，记忆相关用法见[记忆管理](/help/book-details-memory)。

---

## 1. 它能做什么 {#local-embedding-section-2}

启用本地嵌入后，系统会在后台为以下数据建立向量索引：

- **记忆库**：每条记忆的"摘要 + 内容"按段落和句末标点切成 ≤1200 字的短段分别嵌入，再做多分段稳健聚合，避免长记忆被截断后语义漂移。翻译时三信号评分中的「语义相似度」分量（嵌入可用时权重 0.85）由此提供；AI 也能调用 `search_memories` 工具按自然语言搜索记忆。
- **章节内容**：每章按段落（目标 100 字/chunk）和「标题 + 首段」拆成多个 chunk 分别嵌入，AI 通过 `query_chapter` 工具按自然语言找到相关段落，无需依赖预先生成的章节摘要。

章节语义向量统一编码原文，避免已译与未译章节的语言差异影响排名；原文缺失时使用目标译文。关键词、预览和全文索引保留原文与当前目标的选用译文。缓存按目标语言及实际输入签名校验，译文变化也会刷新关键词与预览。切换目标后，失效缓存会在后台重建；旧目标的迟到计算不会覆盖新缓存，未完成时可能显示重建状态。术语、角色和别名检索只扩展原名与本次目标译名，缺译名不借用其他语言。记忆内容与记忆向量跨目标共享，不因目标切换清空。

模糊情节查询会对少量候选的原文段落进行本地重排，避免关键情节被前后文稀释。已有明确匹配的查询保留整块上下文，重复查询复用向量缓存；重排计算失败时保留原排名。整个过程在浏览器内完成，不增加 AI API 请求。

未启用时：

- 三信号评分自动退化为关键词 + 时间衰减（权重 0.75 / 0.25，仍然有效，但语义层面的"意义相近但措辞不同"会漏召）。
- AI 不再暴露 `query_chapter` 工具，翻译提示词也会移除对应引导。
- 批量嵌入面板会以"未启用"状态展示，所有写入操作锁定。

## 2. 模型与运行方式 {#local-embedding-section-3}

### 默认嵌入模型 {#local-embedding-section-4}

- **模型**：`hotchpotch/bekko-embedding-v1-a25m`（Bekko a25m 多语言编码器）。
- **架构**：约 123M 总参数、25M 活跃参数，支持中 / 日 / 英等 100+ 语言。
- **维度**：使用完整的 **384 维**向量，并做 L2 归一化。
- **Pooling**：mean pooling — 对有效 token 的表征求平均。query 与 document 共用同一编码路径，不添加任务前缀。
- **默认文件**：官方 `onnx/model.onnx`，约 **190 MiB**；静态词表已做 int8 压缩，Transformer 计算保持 fp32。`dtype: fp32` 选择这个已压缩文件，不表示下载完整 fp32 词表。
- **模型版本号**：`bekko-embedding-v1-a25m@384@mean@raw`。模型 ID、维度、pooling 或输入方案变化都会更新版本号，旧记忆与章节向量会被判定为 stale，后台重新计算。

### 运行后端 {#local-embedding-section-5}

应用启动时优先检查是否能取得 WebGPU 适配器并创建设备；不可用时直接使用 WASM。两个后端共用同一份默认模型文件。

| 后端       | 文件与计算                              | 大小     | 适用场景                          |
| :--------- | :-------------------------------------- | :------- | :-------------------------------- |
| **WebGPU** | 默认 ONNX，词表 int8 / Transformer fp32 | ~190 MiB | 支持 WebGPU 的桌面浏览器          |
| **WASM**   | 同一默认 ONNX 文件                      | ~190 MiB | WebGPU 适配器或设备不可用的浏览器 |

> 适配器不可用时，本会话使用 WASM；手动「重新加载」会重新检查 WebGPU。实际推理速度取决于设备、输入长度和运行后端。

### 移动端强制禁用 {#local-embedding-section-6}

Quasar 检测到移动平台时会**锁定**「启用本地嵌入」开关为关闭，并在 UI 上灰显。原因是浏览器 WASM 的内存上限（一般 ~2GB）在模型加载与多 chunk 推理时极易触发崩溃。移动端依然能正常使用关键词匹配 + 时间衰减信号。

## 3. 启用步骤 {#local-embedding-section-7}

1. 进入 **设置 → 本地嵌入**（移动端不可见）。
2. 打开「启用本地嵌入」总开关。
3. 系统弹出模型下载提示，开始首次下载（**需要稳定网络，请保留窗口在前台**；下载体积取决于运行后端，见上表）。
4. 下载完成后模型会被浏览器 Cache Storage 持久化，**之后启动会自动预热，无需再次下载**。
5. 进度横幅消失、状态徽章变为 `ready` 后，便可进入下一步。
6. 打开任意书籍，点击右栏图标轨道里的「批量嵌入」入口（v0.12.1 起从顶部工具栏迁移到此），按需触发本书的章节 / 记忆向量化。

## 4. 批量嵌入面板 {#local-embedding-section-8}

进入书籍详情页后，右栏图标轨道会出现「批量嵌入」入口（书籍详情页之外不显示）。点击展开抽屉式面板，可在此查看与控制嵌入队列。

### 状态徽章与统计 {#local-embedding-section-9}

- **嵌入服务状态**：`idle` / `loading` / `ready` / `failed`，并显示当前运行后端（`webgpu` 或 `wasm`）。
- **本书章节**：已嵌入 / 总数 / stale（版本不匹配，待重算）。
- **本书记忆**：已嵌入 / 总数 / stale。

> "stale" 计数非零时通常意味着模型版本最近做了升级（例如从 GTE 切到 Bekko），所有旧版本 chunk 都会被判定为 stale 自动进入重算队列，期间统计可能短暂回落。

### 操作 {#local-embedding-section-10}

- **重新嵌入本书章节** / **重新嵌入本书记忆**：把所有未嵌入或 stale 的条目入队。
- **批量重算**（设置弹窗）：跨书籍触发全部 stale 条目重算。
- **测试查询**：直接输入任意自然语言查询，立刻看到相似度最高的 N 条章节 / 记忆，相似度分数实时显示，便于调参或排查"为什么这条记忆没被注入"。
- **暂停 / 继续**：暂停按钮直接挂起队列；同步进行中时面板会显示「同步期间已暂停」提示，结束后自动恢复（详见第 6 节 sync gate）。

### 进度横幅 {#local-embedding-section-11}

队列活跃时面板顶部显示进度条，包含：

- 已完成 / 总数（按 `memory` 与 `chapter` 分别拆分）。
- ETA：基于最近 5 个批次的平均耗时估算。
- 当前批次正在处理的书籍 ID（即便你切换到另一本书的面板，也能看到队列在哪儿忙）。

记忆和章节都按每批最多 8 条输入计算向量，前台查询优先于等待中的后台批次。章节在批次之间响应暂停；未完成的章节保留在队列，继续后重新计算，完成整章后再统一保存。面板关闭时暂停统计读取，打开后合并同批刷新。

## 5. 模型版本与 stale 重算 {#local-embedding-section-12}

`MODEL_ID + 截取维度 + pooling 方案 + 输入方案`一起构成「embedding 空间身份」。任意一项变化，旧向量与新向量就落在不同空间，余弦相似度会退化成噪声，必须重算。

应用通过 `MODEL_VERSION` 常量记录当前空间身份，每条已嵌入的记忆 / chunk 都会同时存这个版本号。检索与统计逻辑会调用统一的 `isMemoryEmbeddingStale` / `isChapterChunkStale` 判断版本是否匹配：

- 匹配（current）：参与语义检索 / 计入"已嵌入"。
- 不匹配（stale）：跳过语义评分（自动降级到关键词 + 时间衰减），并被 backlog 扫描进入重算队列。

**这意味着升级模型不会丢数据**：旧条目仍能被检索，只是暂时降级使用，等队列处理完会自动回到完整能力。

应用还会在启动时清理浏览器 Cache Storage 中的**历史模型残留**（如 `embeddinggemma`、`qwen3-embedding`），回收磁盘空间。

## 6. 同步期间的 sync gate {#local-embedding-section-13}

云同步与修订恢复期间，嵌入队列会被一道**专用闸门**临时挂起：

- `isSyncing` 或 `isRestoringSyncSnapshot` 任一为 true，闸门锁住队列。
- 闸门解锁后**只**恢复"由闸门自身挂起"的任务 — 用户在 UI 上主动点击的「暂停」状态完整保留，不会被同步流程意外解除。
- 这避免了同步过程中嵌入写入与 `overwriteFromSnapshot` 的覆盖竞态，也防止恢复一半的数据上面再叠上半新的向量。

UI 表现：同步期间面板会显示「同步进行中，嵌入已暂停」横幅，`isSyncing` 结束后自动消失。

## 7. 故障排查 {#local-embedding-section-14}

### 进度卡在 0% {#local-embedding-section-15}

- **检查网络**：模型托管在 Hugging Face CDN，若网络不可达会进入自动重试（递增延迟 3s / 8s / 20s，最多 3 次）。可在浏览器开发者工具的 Network 面板看具体请求。
- **代理 / 反代**：企业网络 / VPN 可能拦截 CDN，可在「代理设置」（仅 Web 端）尝试切换或在浏览器层面配置允许列表。
- **磁盘空间**：浏览器 Cache Storage 通常需要 500MB 以上空间，磁盘紧张时下载会中途失败。

### 状态停在 `failed` {#local-embedding-section-16}

- 查看浏览器控制台 `[EmbeddingService]` 前缀的错误日志，常见原因：
  - WebGPU 驱动不兼容 → 应用会自动回落到 WASM；如果连 WASM 也失败，多半是浏览器内存不足。
  - 首次加载时切走标签页太久导致超时 → 重新打开应用即可（模型缓存命中后第二次启动很快）。
- 在批量嵌入面板点击「重新加载」按钮会清空 WebGPU 黑名单并强制重新初始化。

### 检索结果质量不佳 {#local-embedding-section-17}

- 用「测试查询」对话框直接输入查询语句，看返回 Top-N 是否合理。
- 如果某条记忆/章节"明明应该被找到"却没出现，确认它的状态是否为 stale：先重新嵌入再测试。
- 中日英混合查询：模型原生多语言，直接输入纯净查询即可（v0.14.3 起不再为 query 端添加任何前缀）。

### 已禁用但提示"嵌入队列还在跑" {#local-embedding-section-18}

通常是关闭总开关时正在处理某批次。队列会在当前批次完成后自然停止，强制中断会丢弃这一批结果。等待几秒进度横幅会自动消失。

## 8. 隐私与离线性 {#local-embedding-section-19}

- 嵌入模型推理在浏览器内执行，不调用外部嵌入 API。
- 模型本身一次性下载到 Cache Storage，之后离线启动也能用。
- Gist 同步会把记忆向量作为记忆条目的一部分上传到你的私有 Gist（详见 [设置说明 → 数据同步](/help/settings-guide#settings-guide-section-19)），**Tsukuyomi 不持有任何中转服务器**。
