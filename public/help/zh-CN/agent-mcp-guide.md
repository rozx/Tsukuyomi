# 外部 Agent 与 MCP 接入指南 {#agent-mcp-guide-section-1}

通过 **外部 Agent 工作台**（`/mcp`），你可以让 Claude Code、Pi、Antigravity 等本地 Agent 直接操控 Tsukuyomi，使用已有 Agent 订阅额度完成建书、加章、维护设定与分块翻译。

## 运行模式 {#agent-mcp-guide-section-2}

### 桌面版：本地 Streamable HTTP MCP 服务端 {#agent-mcp-guide-section-3}

- 仅绑定本机回环地址 `127.0.0.1`（默认端口 `48321`），默认关闭，需要在 `/mcp` 页面手动开启。
- 强制校验 `Authorization: Bearer <token>`、`Host` 与 `Origin`，防止跨站网页误访问。
- 同一 `POST /mcp` 端点同时兼容 `2026-07-28` 无状态协议（`server/discover`）与 `2025-03-26` 握手协议（`initialize`）。
- 本机端口、Bearer Token、服务开关与权限模式仅保存于当前设备，不会同步到 GitHub Gist，也不会包含在导出备份文件中。

### 浏览器版：WebMCP 本地中继 {#agent-mcp-guide-section-4}

- 浏览器版通过 **WebMCP 本地中继**（`@mcp-b/webmcp-local-relay`）让 Claude Code、Cursor 等本地 Agent 使用本页的工具，不需要打开浏览器的实验开关。
- 在页面第一步开启 WebMCP 后，应用会在本页注册当前权限允许的工具（含只读的工作流指南 `get_workflow_guide`），并连接你电脑上运行的中继。
- 在 Agent 客户端里添加中继：Claude Code 运行 `claude mcp add webmcp-local-relay -- npx -y @mcp-b/webmcp-local-relay@latest --widget-origin <本页地址>`，其他客户端把页面给出的 JSON 合并到 MCP 配置里。需要 Node.js 22 或更高版本。页面给出的配置已经填好本页地址，中继只接受来自它的连接。
- 开启后，页面第一步会显示是否真的接上了本机中继：已接上、本机有中继但本页没有接上（多半是中继的 `--widget-origin` 与本页地址不一致），或还没有找到中继（Agent 客户端还没有启动它）。
- 让 Agent 调用 `webmcp_list_sources`，能看到本页就说明已连接。工具列表里看不到本页工具时，可用 `webmcp_list_tools` 列出、`webmcp_call_tool` 按名称调用。
- 使用期间请保持 Tsukuyomi 的标签页打开（不必停留在「外部 Agent」页面，在书籍、设置等任何页面都一样）：工具来自这个标签页，关闭或刷新后 Agent 会暂时看不到它们。
- 中继比页面晚启动，或者 Agent 客户端重启过时，页面会在二十秒左右自动重新接上，不需要切回标签页或刷新。有些客户端不直接列出 MCP 工具，而是按需加载：Agent 说看不到工具时，先让它按客户端的方式查找，再判断是不是没连上。
- 只开一个 Tsukuyomi 标签页：同时开着多个时，Agent 看到的工具名会带上标签页后缀。
- 页面给出的配置里的地址取自你打开页面时的地址；换一个地址访问（例如 `localhost` 换成 `127.0.0.1`，或换了域名）后需要重新复制配置。
- 浏览器开着旧版的 WebMCP 实验开关时，应用会在本页自动改用内置实现；个别情况下无法替换，页面会提示去 `chrome://flags/#enable-webmcp-testing` 关闭该开关。
- 本页必须通过 HTTPS 或 localhost 打开，否则无法开启。
- 浏览器环境因跨域限制无法抓取部分站点时，可让 Agent 自行获取正文后调用 `create_book` 与 `add_chapters` 直接导入。

## 权限分级与多版本写回 {#agent-mcp-guide-section-5}

- **仅只读（`read_only`）**：仅开放书库、章节、术语、角色、记忆查询，全书搜索与词频统计，分块上下文拉取，以及读取你当前的页面位置和内置使用文档。
- **翻译与编辑（`translate_and_edit`，默认）**：允许建书、修改书籍信息、导入、批量加章、检查并导入书籍更新、提交与批量替换译文，新增、修改和删除术语/角色/记忆，但禁止删除书籍。
- **完全控制（`full`）**：额外开放 `delete_book`；切换到该模式时页面会要求再确认一次。
- **译文版本策略**：默认以 `append` 追加新译文版本并设为选中；每种语言每段最多保留 5 个历史版本，超过上限时会逐出最早版本，因此请避免对同一段落反复提交不同译文。Agent 翻译一章时复核并修正自己刚提交的译文属于例外：指南让它用 `overwrite` 就地改写那份草稿，不多占一个版本；润色、校对已有译文仍按默认方式追加新版本。

## 推荐翻译工作流 {#agent-mcp-guide-section-6}

1. 在 `/mcp` 页面只需要两步：开启服务，然后复制「快速上手指南」并粘贴给 Agent。
2. 指南开头的「首次设置」会让 Agent 替你完成准备：询问并建立项目文件夹、在其中配置好这个 MCP、把指南的其余部分保存为该文件夹里的 AGENTS.md（Claude Code 另建一个引用它的 CLAUDE.md）。之后在这个文件夹里启动 Agent 就能直接工作，不用再粘贴。指南后面是数据模型、全部工具、分步工作流、规则与出错处理；保存下来的部分控制在 23.5 KB 以内，不会被对规则文件有大小上限的客户端（如 Antigravity 的 24,000 字节）截断。桌面版的 MCP 配置里包含访问令牌，不要把这个文件夹提交到公开仓库。想自己在客户端里添加 MCP 时，展开页面上的「手动添加 MCP」。
3. 大部头网页小说通过 `import_book_from_url` 默认按批抓取最多 20 章，可按返回的 `pending_chapter_count` 重复调用续传，并通过 `max_chapters` 调节单批章数。
4. 连载中的书籍可用 `check_book_updates` 检查来源站点的新章节，再用 `apply_book_updates` 导入。默认只导入新章节；应用已导入章节的正文改动（`include_updated`）会清除被改段落的译文。检查结果同时附带本地的翻译进度（`local_progress`：各状态的章节数、第一个没译完的章节、最新两章各译了多少段），你刚手动导入过新章节时，站点上没有新章节，Agent 也不会误报「没有可译的章节」。
5. 翻译落盘后会立即刷新书库与阅读页面，页面上的「调用活动」会实时显示每次工具调用的参数与返回结果摘要（刷新页面后仍保留，关闭标签页后清空），译文历史中会展示对应的外部来源标签（如 `MCP · claude-opus-4`）。
6. Agent 能知道你正在看什么：`get_app_context` 会返回你所在的页面、打开的书和章节、选中的段落及其原文与译文，以及你在页面上划选的文字。所以可以直接说「润色我选中的这一段」。
7. 统一修改译名时，Agent 会先用 `count_occurrences` 统计旧译名的出现次数，再用 `replace_in_translations` 预览并批量替换。按默认的写回方式，每个改动的段落会追加一个新版本，旧版本仍然保留。全书范围的查找用 `search_paragraphs`（支持正则），翻译时查前文的译法可以限定只搜当前章之前的章节、只看已有译文的段落，不会被后面还没翻译的章节占满结果；开启了本地嵌入时还可以用 `search_chapters` 按内容描述找章节。
8. 可以直接问 Agent「Tsukuyomi 怎么导入小说」这类使用问题：它会用 `search_help_docs` 和 `get_help_doc` 查阅本帮助文档后回答。
9. `delete_terms`、`delete_characters`、`delete_memories` 用于清理过时或重复的条目。指南要求 Agent 在删除前先征得你的同意。
10. 翻译新章节的第一块时，Agent 会同时拿到上一章末尾的原文与译文，以及最近几章的标题译名，用来延续语气、标点习惯和标题格式。
11. 原文把术语或角色名写错字（例如同音字）时，这些条目会作为「可能相关」单独列出并标明原文里的写法，由 Agent 确认后使用。站内的翻译、润色、校对也有同样的提示。
12. Agent 遵守的翻译规则（标点与引号、保持格式、日语敬语、术语与角色怎么建、记忆该记什么）与内置翻译是同一份，写在快速上手指南和工作流模板里。记忆只用来存可复用的翻译决定（称呼、术语译法、文风），取翻译块时按相关度自动带出，不用来记剧情；你希望每次都带上的长期要求请写进书籍或章节的特殊指令。每章都要遵守的全书规范（标题格式、标点约定、叙事文风）也应写进书籍级特殊指令：记忆按与正文的相关度带出，与剧情无关的格式规则常常取不到，而特殊指令每次取翻译块都会带上。指南会让 Agent 发现这类规范时用 `update_special_instructions` 的 `mode: "append"` 追加，不覆盖已有的指令（不传 `mode` 时整体替换）。有多种常见译法、需要全书统一的词（职业、魔物类别、设定高频词）则建成术语，按块带出，不往特殊指令里堆词表；无歧义的日常词不建术语。
13. 长篇书籍不需要读整本目录：`get_book` 只要卷的概览时也会给出每卷已译完、译了一部分、还没开始的章节数和第一个没译完的章节，也可以只取最近几章或某一卷；要接着翻译时可以用 `from_first_untranslated` 配合 `limit`，只取从第一个没译完的章节起的几章（例如「翻译第 28～33 话」时不必拉整卷）。`list_terms` / `list_characters` 支持分页和精简输出。
14. 搜索类工具（全书搜索、词频统计、章节段落、术语与角色列表、使用文档）默认精确匹配，另有可选的模糊匹配：Agent 记不清确切写法或原文有错字时可以开启。批量替换译文不支持模糊匹配，避免改到不该改的文字。
15. 本地的 txt 等文本也可以让 Agent 导入：它自己读取文件，用 `create_book` 建书，再用 `add_chapters` 逐章写入。分段规则与内置导入一致——每一行是一个段落，空行和行首缩进原样保留。
16. `move_chapters` 可以调整章节在卷内的顺序，或把章节移到另一卷（也可以新建一卷）；内置的聊天助手也有同名工具。它只改变位置，不改动正文与译文。
17. `get_translation_chunk` 的一块有三道上限，谁先到就在哪里收口：最多 60 段（不计标点不超过 8 个字的短行、纯符号行算半段，弹幕式的短行一块能放下一百多行；Agent 可用 `max_paragraphs` 调整，上限 200）；字符预算默认取书籍的分块大小，但最多 4000 字原文（`chunk_size` 可另行指定）；整个响应的 JSON 不超过约 9000 字节（UTF-8，中日文每字 3 字节；`max_response_bytes` 可调整）。最后这道上限针对 Antigravity 这类把超过 10 KiB 的工具结果存成文件、要多一轮读取的客户端：先放角色、术语、记忆、上一章末尾等上下文，剩下的空间再装段落，所以命中角色多的第一块会少几段，`compact` 的续块能多装。取一块正好对应一次提交和一次复核。一块之后只剩很少几段（按配额折算不超过段数上限的四分之一，并入后字数不超过字符预算的 1.25 倍、响应不超过字节预算 5%）时并入这一块，章末不会多出一个只有十来段的小尾块。
18. 回忆、首尾呼应、前后篇里原样重复的句子：取翻译块时，如果某段原文与本章前文或之前 30 章里已经译过的段落完全相同（忽略空白，不计标点至少 10 个字），会把当时的译法一并带出，Agent 可以直接沿用。「ええ、もちろんですわ」这类客套话、短应答译法随语境变化：不计标点不到 24 个字的短句，前文最近两处的译法不同时不会带出。更早的章节或只是相近的句子需要 Agent 自己用 `search_paragraphs` 查。
19. Agent 的翻译步骤与内置翻译相同：先准备（确认术语、角色、记忆与翻译策略，新术语和新角色这时就建好），再翻译并提交，最后复核；润色与校对没有复核。快速上手指南和工作流模板里的步骤是同一份，Agent 不需要两边各读一遍。
20. 快速上手指南开头写着对应的应用版本。应用更新后，Agent 会发现自己保存的指南版本不一致，并用 `get_quick_start_guide` 取得当前版本、替换保存的副本，不需要你重新复制。
21. 翻译块里术语与角色的说明合计约 600 字：命中的条目不多时每条最多带 150 字，条目多时（如群像场面）按条目数收紧，每条至少 40 字；被截短的标明 `description_truncated`，全文可用 `list_terms` / `list_characters` 读取。译名、性别、说话风格与别名不截短。不需要说明时可以传 `include_descriptions: false`。续取后续块用的 `compact` 省略说明、最近章节标题和第一块已给过的章节标题、目标语言等信息，为空的列表（如没有命中的记忆、近似命中）也不再列出；角色的性别与说话风格仍然带上，后面才出场的角色也有口吻可依。上一章末尾与最近章节标题只用来对齐语气和格式，不带段落和章节的 ID。
22. 「可能相关」的术语与角色（原文写法略有出入的近似命中）不会从一个更长的片假名词中间切出一段来比对，名称的前半后面接着助词的也不算；不超过 4 个字的纯片假名名称，首字不同时视为另一个词。
23. 新章节的第一块带有 `style_hints`：统计本章与之前 5 章已有译文（最多 200 段）里引号（「」 或 “”）、破折号、省略号、对白句末是否带句号、数字全半角、空格的写法。书籍没写标点约定时，Agent 照多数的写法翻译，不必先逐个搜索前文确认；特殊指令里写明的规范优先。已有译文不到 10 段时不给出。
24. `upsert_terms` / `upsert_characters` 按补丁更新：只传 ID（或原名）和要改的字段，没传的字段保留原值，例如只补说话风格不会抹掉说明；空字符串表示清空说明或说话风格。新建条目时原名和译名都要给。`aliases` 整体替换别名列表；只想补一个别名时用 `append_aliases`，同名的别名改写译名，其余别名保留。
