# 🤖 AI 模型配置指南

本文档说明当前版本中 AI 模型页面与模型对话框的真实功能。

---

## 📋 页面能力

### 桌面版

**AI 模型工作台** 由三部分组成：

- **顶部**：搜索框（名称 / 提供商 / 模型 ID / 默认任务）与「添加 AI 模型」按钮，下方是模型数量统计。
- **模型列表**：按提供商（OpenAI / Google Gemini）分组，组标题显示模型数与已启用数。每张模型卡片可 **复制**（副本默认禁用）、**编辑**、**删除**（确认后执行，支持撤销）。
- **任务路由**：为翻译（初译）、校对 / 润色、术语翻译、AI 助手分别选择默认模型，设置会随导入导出一起保存。

### 手机版

- 顶部为「AI 模型」标题与「添加」按钮。
- 尚未配置模型时显示引导卡片：「添加 AI 模型」按钮和「两步开始使用」说明（添加模型连接 → 选择默认任务）。
- **我的模型**：按提供商分组，显示模型数和已启用数，点击模型即可编辑。
- **任务默认模型**：点击任务行，从底部弹出的列表中选择模型，也可选择「未设置」让该任务不使用默认模型。
- 模型对话框在手机上以底部抽屉形式打开，字段与桌面版一致。

## 🏢 当前支持的提供商

系统内置提供商仅有：

- `OpenAI`（OpenAI 兼容接口）
- `Gemini`（Google Gemini）

两者都通过 Vercel AI SDK 接入：OpenAI 走 `@ai-sdk/openai-compatible`，Gemini 走 `@ai-sdk/google`。

> 说明：DeepSeek、Moonshot、OpenRouter、Ollama 等 OpenAI 兼容服务，请选择 `OpenAI` 并填写对应的 `baseUrl` 与模型 ID。基础地址只写到域名时会自动补上 `/v1`；如服务的路径不同，请填写完整路径。

## ➕ 添加模型

点击「添加 AI 模型」后，在弹窗中填写：

1. **启用模型**（开关）
2. **使用 CORS 代理**（开关，仅浏览器模式显示，见下文）
3. **模型名称**（必填）
4. **温度**（0~2）
5. **提供商**（OpenAI / Gemini）
6. **API Key**（必填）
7. **基础地址**：
   - OpenAI：必填
   - Gemini：不显示，使用 Google 官方地址
8. **模型标识**（必填，可从列表选，也可直接输入）
9. **思考等级**（可选，见下文）
10. **模型资料**：上下文窗口与最大输出 Token
11. **自定义请求头**（可选）
12. **默认任务**

当 API Key（及 OpenAI 的 baseUrl）满足条件后，会自动拉取可用模型列表，也可点击「刷新列表」手动刷新。模型标识框支持直接输入列表里没有的型号，包括用输入法输入。

关闭弹窗时如有未保存的修改，会提示「继续编辑」或「放弃修改并关闭」。

## ⚙️ 模型资料与可用性

**获取模型资料** 只查询随应用打包的 [models.dev](https://models.dev) 目录，离线也可使用，不发送模型生成请求，也不需要 API Key。未收录的型号会提示手动填写，已有数值保持不变。

- **上下文窗口**：模型可接受的输入上限，0 表示未设置。
- **最大输出 Token**：单次响应上限，0 表示未设置。
- 目录值标记为 models.dev 来源；手动编辑后标记为手动，手动值优先用于运行时预算。
- 常见的思考等级后缀（例如 `gpt-6-sol(high)`）只在目录匹配时忽略，实际请求仍保留原始模型标识。
- 旧版本通过「询问模型自身」获得的数值，如果目录里有该型号，运行时会以目录为准；想固定使用自己的数值，手动编辑一次即可。

上下文窗口决定 AI 助手与导入助手何时压缩对话：上下文接近窗口时自动压缩较早的对话；未设置时不会主动压缩，只在服务返回「上下文超限」后恢复一次。详见 [AI 助手](/help/chat-assistant-guide)。

**测试可用性** 使用当前尚未保存的地址、密钥、请求头、代理和思考等级发送一条简短请求，显示成功/失败及耗时。需要先填写模型标识、API Key（OpenAI 还需基础地址）。测试最多等待 30 秒，会产生少量 API 用量，不修改模型资料或自动保存配置。编辑表单或关闭弹窗会取消测试，旧结果不会用于新的配置。

## 🧠 思考等级

可选择默认（跟随模型）、关闭 / 最低、极低、低、中、高、极高。默认不覆盖厂商设置；旧模型没有此字段时沿用默认行为。更高等级通常增加响应时间与 Token 消耗，各型号支持的等级可能不同，可用「测试可用性」验证当前组合。

设置会随模型保存、导入导出和同步，并用于助手、翻译、润色、校对、术语及上下文摘要。OpenAI 兼容接口使用 reasoning effort，Gemini 由 SDK 按型号转换成思考等级或预算。

## 🌐 网络与代理设置

以下设置对 OpenAI 与 Gemini 都生效，包括模型列表、生成请求和可用性测试。

### CORS 代理开关

每个模型可独立控制是否使用 CORS 代理：

- **使用 CORS 代理**（默认开启）：API 请求通过 CORS 代理服务器转发。
- 关闭后请求将直连模型服务，适用于：
  - 本地部署的 AI 服务（如 Ollama）
  - 已配置好跨域策略的自建服务
  - 不需要代理的 API 端点
- 此开关仅在浏览器模式下生效，Electron 桌面版始终直连。

### 自定义 HTTP 请求头

每个模型可配置自定义 HTTP 请求头（Header），用于：

- 额外的身份认证（如 Bearer Token、自定义认证头）
- API 网关路由标记
- 特殊服务配置参数

操作方式：

- 点击「添加 Header」按钮新增一组键值对
- 每组包含 **Header 名称** 和 **Header 值**
- 可添加多组自定义请求头，名称为空的行不会保存
- 点击删除按钮移除不需要的请求头

## 🎯 默认任务设置

每个模型可独立勾选是否用于以下任务，并可为每项单独设置温度：

- 翻译
- 校对/润色（同一任务项）
- 术语翻译
- 助手

> 这些「可用于任务」的开关会影响该模型是否出现在对应任务的默认模型选择中。实际使用哪个模型，由页面上的 **任务路由**（手机版为「任务默认模型」）决定。

## 📚 书籍级模型覆盖

AI 模型页配置的是全局默认模型。对于需要不同文风、能力或成本策略的单本书，可在 **书籍详情页 → SETTINGS → 翻译设置** 中分别覆盖：

- 翻译模型
- 校对 / 润色模型

模型解析优先级为：**有效且已启用的本书覆盖 → 对应任务的全局默认模型**。如果覆盖模型被禁用或删除，任务会静默回退全局默认，不会中断；书籍设置页仍会显示失效占位，方便重新选择。

本书覆盖不作用于术语翻译、聊天助手和解释任务。完整操作说明见 [AI 翻译功能](/help/book-details-translation#本书模型覆盖)。

## 🔍 搜索与展示细节

搜索框会实时过滤以下内容：

- 模型名称
- 提供商（OpenAI / Gemini）
- 模型 ID
- 默认任务文案

桌面版模型卡片会显示：

- 提供商与模型 ID
- 启用状态（已启用/已禁用）
- 温度、上下文窗口、最大输出
- 脱敏 API Key（仅显示前缀）
- 基础地址
- 默认任务汇总

API Key 只保存在本设备（IndexedDB），不会上传到应用服务器。

## 💡 使用建议（基于当前实现）

1. 至少配置一个「助手」默认模型，否则右侧聊天助手无法发送消息。
2. 新增模型后先点「获取模型资料」补齐上下文窗口，再点「测试可用性」确认连接，然后保存。
3. 为「翻译」和「校对/润色」分别配置不同温度，便于稳定性与表达效果平衡。
4. 复制模型后先在副本上调参测试（例如换一个思考等级），确认效果后再启用。
5. 定期清理不再使用的模型，避免任务模型选择列表过长。

## ❓ 常见问题

**Q: 为什么 Gemini 不需要基础地址？**

A: Gemini 默认使用 Google 官方地址，弹窗中会隐藏 baseUrl 输入。自定义请求头和 CORS 代理开关对 Gemini 同样生效。

**Q: 点「获取模型资料」提示目录暂无记录？**

A: 该型号不在内置的 models.dev 目录中（常见于自建服务或新发布的型号）。请参照服务商文档手动填写上下文窗口与最大输出 Token；已有数值不会被清空。

**Q: 「测试可用性」失败了怎么办？**

A: 先核对基础地址、API Key 和模型标识；浏览器模式下可尝试切换 CORS 代理开关；如果报错与思考参数有关，把思考等级改回「默认」再测试。

**Q: 复制的模型为什么不能直接用？**

A: 复制模型默认是「已禁用」，需要进入编辑后启用。

**Q: 助手发送按钮是灰色的？**

A: 通常是未配置「助手默认模型」或当前无可用助手模型。

**Q: 删除后能恢复吗？**

A: 可以，在成功通知出现期间点击「撤销」可恢复。
