# 发布说明 - v0.18.0

## 版本信息

- **版本号**: 0.18.0
- **发布日期**: 2026 年 10 月 9 日
- **基于版本**: v0.17.0

本版本主要改进同步和本地嵌入。同步协议升级到 v6，书籍目录和章节正文分开存放，正文按章节固定分成 16 个小组；新增或修改一章通常只需上传一个小组、目录和清单，不再重传整本书。超过 300 个文件的大书库可以正常同步，没有变化的书库会跳过全库扫描。另外新增远端遗留文件清理，修订历史改为按书籍归组。本地嵌入换用更小的 Bekko 模型（约 190 MiB），推理移到独立 Worker 中运行，并重做了「向量索引」面板。**多设备同步用户以及开启了本地嵌入的用户，请先阅读文末的升级说明。**

---

## ☁️ 同步协议 v6 (Chapter-level Incremental Sync)

- **按章节小组增量同步**：书籍资料和目录单独保存，不含正文；章节正文按章节 ID 固定分到 16 个小组，插入或重排章节不会让其他章节换组。新增或修改一章时，通常只上传所在小组、目录（有变化时才传）和清单；只改正文时目录也会跳过。下载时同样只拉取有变化的小组。
- **大书库不再受 300 个文件限制**：GitHub 返回的文件列表最多只有 300 个文件。以前列表被截断就会停止同步，现在会按当前修订读取完整的同步清单，补齐没有列出的文件，并继续校验哈希。只有既被截断、又读不到完整清单时才会停止。
- **书库没有变化时同步更快**：本机记录一个只存在本地的同步检查点。书库、设置和删除记录都没有变化时，不再读取全部章节正文和记忆来重算清单；远端的变化仍会照常检查。冷启动时章节正文改为批量读取，远端文件最多 4 个并发下载。
- **记忆访问时间只在本地**：记忆新增内容修改时间。「最后访问时间」只在本机用于排序和时间衰减，不再上传。因此打开或被 AI 读取的记忆不会再触发同步，也不会覆盖其他设备上较新的修改，或让已删除的记忆恢复。
- **出错时整体停止**：任意条目下载、校验、应用失败，或本地读取某本书的记忆失败时，整轮同步都会中止，不上传、不更新同步状态，下次同步会重新拉取，避免上传不完整的数据。分批上传期间如果检测到其他设备写入，会停止上传，并提示「远程数据在上传期间发生变化，已停止上传，请重新同步」。
- **同步进度**：同步面板改为显示「整体进度」百分比，进度不会回退；当前阶段（「准备本地数据」「下载中」「应用中」「上传中」「保存同步状态」等）显示在进度条下方。

## 🧹 遗留文件清理与修订历史 (Gist Cleanup & Revision History)

- **清理远端遗留文件**：**设置 → 同步设置** 中，「修订历史」上方新增「清理远端遗留文件」。点「扫描遗留文件」后，以最新的远端清单为准，列出不再被引用的旧格式文件、孤立文件和多余分片，并显示「可清理 {count} 个文件 · {size}」。扫描只读取数据，不做修改。确认「清理这 {count} 个文件」后，会重新扫描、核对远端版本，再一次性删除。清理只影响最新版本，历史修订中的文件仍然保留；不属于月詠的文件不会被删除。远端清单损坏、格式升级没有完成或远端版本已变化时，会停止清理。
- **修订历史按书籍归组**：展开某个修订后，「修订内容」按书籍汇总「书籍资料」「章节数据」「记忆」和「分块索引」，并显示文件数和大小变化，标记「新增」和「已移除」；点开条目可以看到原始文件。不属于该修订书库的文件会单独归入「历史遗留文件」。

## 🔑 设置同步更可靠 (Settings Sync)

- **API Key 独立同步**：Tavily 和 Firecrawl 的 API Key 分别记录修改时间。以前本机修改过其他设置（甚至只是切换过标签页）后，会拒收远端较新的 Key；现在不会了。清空 Key 也会同步到其他设备。「API Keys」页的输入框会自动显示同步来的新值，但不会覆盖你正在编辑、还没保存的内容。
- **任务默认模型不再被清空**：「任务默认模型」中每个任务的选择分别记录修改时间并同步合并。同步过程中，设置有时会比 AI 模型先到达本机，以前这时选择会被当作无效而清空；现在会保留，等模型同步到本机后自动恢复显示。只有模型确实已被禁用、或不再支持该任务时，选择才会被清空。

---

## 🧠 本地嵌入换用 Bekko 模型 (Bekko Embeddings)

- **更小的模型**：默认嵌入模型从 `onnx-community/gte-multilingual-base`（768 维）换成 `hotchpotch/bekko-embedding-v1-a25m`（384 维）。WebGPU 和 WASM 共用同一个约 190 MiB 的 ONNX 文件（以前约 340–465 MB），向量占用的空间减半。
- **章节检索更稳定**：章节向量只使用原文计算，已翻译和未翻译的章节可以公平比较。描述比较模糊时，会用候选章节的原文段落重新排序结果；排序期间书籍如果发生变化，会提示稍后重试，而不是返回过期结果。
- **WebGPU 更稳定**：选择 WebGPU 之前会先检测设备是否可用，不可用时直接改用 WASM。WebGPU 失败一次后，回退到 WASM 也能正常恢复，不会持续报同一个错误。

---

## ⚡ 嵌入推理移到 Worker (Embedding Worker)

- **界面不再卡顿**：模型加载、分词和推理改在独立的 Web Worker 中运行，下载模型或批量生成向量时，页面仍可正常操作。
- **后台任务限速**：后台批次更小，每批之间有休息时间；你发起的查询会插队优先执行。全书重建可能会比以前慢一些，但 CPU / GPU 占用更平稳。
- **崩溃与超时处理**：Worker 崩溃或长时间无响应时会被终止，状态显示为「加载失败」，不会卡住页面。正在处理的批次会放回队列，在 **设置 → 本地嵌入** 点「重试」或有新的嵌入任务触发重新加载后继续；章节只在全部向量生成后才写入，不会留下不完整的数据。
- **下载进度更准确**：**设置 → 本地嵌入** 显示「模型加载进度」，以及「正在准备模型文件…」「正在下载模型文件…」「正在初始化模型…」等阶段。进度只按模型权重文件计算，不再在下载小配置文件时闪到 100%，也不会回退；自动重试或从 WebGPU 回退到 WASM 时进度会保留。重新打开设置页时，会恢复当前进度。

---

## 🔍 「向量索引」面板重做 (Vector Index Panel)

- **入口**：「向量索引」只在书籍详情页、且启用了本地嵌入时显示。桌面端在右侧图标栏，平板端在侧边栏（新增），窄屏布局在顶部工具栏（新增）。面板在桌面和平板上从右侧滑出，在手机布局中以底部抽屉打开；切换布局时保持打开状态，切换书籍时自动关闭。
- **新的面板样式**：标题旁显示状态标签（就绪 / 模型加载中 / 加载失败 / 未就绪 / 已禁用），并改名为「章节向量」「记忆向量」，副标题改为「浏览器本地运行」。
- **测试查询对话框**：新增说明文字「用自然语言描述剧情、人物关系或关键词，检索本书章节与记忆。」、空状态和加载状态；结果显示排名和「相关度」标签。

---

## 🧩 记忆注入与检索 (Memory Injection & RAG)

- **字符预算严格执行**：记忆注入的字符预算包含标题、ID 和换行，第一条记忆也不会再超出预算。放不下的长记忆会被跳过，后面较短的记忆仍可注入；出错时的兜底注入也遵守预算。
- **关闭本地嵌入后立即降级**：关闭「启用本地嵌入」后，即使模型仍在内存中，自动注入和 `search_memories` 也会只使用关键词检索。
- **检索更快**：查询向量缓存由自动注入、AI 工具和预览共用；`query_chapter` 会缓存当前书籍的向量快照，并并行读取章节正文。章节向量按小批次生成，暂停或关闭后能及时停止。

## 📝 问题修复

- 修复：网页版的封面图片改为直接从原网站加载，不再经过 CORS 代理，不受代理故障或限流影响。
- 修复：网页版访问本机或局域网地址（例如 Ollama 等本地模型服务）时自动直连，即使开启了「使用 CORS 代理」也一样；上传封面也不再经过代理。
- 修复：从修订历史或备份恢复大书库时，内存占用明显降低。
- 修复：同步时偶尔把自己上一批上传误判为「其他设备写入」，并且错误提示显示成翻译 key 的问题。

## 📌 升级说明 (Upgrade Notes)

- **多设备同步请按顺序升级**：本版本把同步协议从 v4 升级到 v6（中间的 v5 没有正式发布）。新版本可以读取旧协议 1–5，第一次同步时会把整个 Gist 迁移到 v6 的新文件布局，上传量可能比较大；数据太多时会分批上传，中断后再次同步会继续完成。v0.17.0 及更早的客户端遇到 v6 数据时会停止同步，并提示升级。请先在每台设备上导出备份，再把所有设备升级到 v0.18.0，最后逐台完成同步。**旧版本的强制推送仍会覆盖共享 Gist**，升级之前请先关闭旧设备的同步，不要用旧版强制推送。
- **迁移后可清理旧文件**：迁移完成后，可以在「清理远端遗留文件」中扫描、清理不再使用的旧格式文件。历史修订仍可恢复。
- **需要重新下载嵌入模型（约 190 MiB）**：启动时不会自动下载新模型。请在 **设置 → 本地嵌入** 点「下载模型」，或者等嵌入任务（例如保存记忆）自动触发下载。旧 GTE 模型的文件（约 340–465 MB）会暂时保留在浏览器缓存中，如需释放空间，可以清除本站点的数据。
- **已有向量需要重建**：旧的 768 维向量和章节向量都会失效，但不会丢失数据。重建之前，记忆检索只使用关键词和时间衰减，章节搜索暂时不可用。模型就绪后打开书籍详情页，会自动重建这本书的向量；也可以在「向量索引」面板中点「立即重建」、「回填缺失」或「全部重算」。没有打开过的书不会自动重建。
- **「向量索引」按钮**：没有启用本地嵌入时，「向量索引」按钮会隐藏（以前会显示一个禁用提示）。
- 新增 `@noble/hashes` 依赖（用于恢复签名），并为 `@huggingface/transformers` 4.3.0 打了补丁（`patches/`）。开发者需要重新运行 `bun install`。
